Self-check: the Part 3 Review

Q1
The logbook's pieces tally counted up to 42 with withSpring, sampled every few milliseconds. Why is that a problem, and what does the lesson use instead?
0 3 8 12 19 27 30 37 42 44 47 48 49 48 47 46 45 44 43 42 41 42
A) Nothing is wrong: springs feel alive
B) The phone is too slow for 60 frames
C) A spring overshoots its target: the tally showed totals that were never true (49, then 41). Numbers and progress get withTiming
D) Use setInterval for numbers
Why: Springs are for things that move like objects; anything that must not pass its target is a timing (Lesson 7.1, Common Mistakes).
A is wrong: Alive is fine for a card, not for a count people read.
B is wrong: The samples show the spring's own curve, not dropped frames.
D is wrong: A timer on the JavaScript thread is the old, janky way.
Q2
A tutorial's Gesture.Pan().onEnd(…) was copied into the course's Gesture Handler 3 hook config. What is the fix?
src/components/SwipeToRemove.tsx:42:5 - error TS2353: Object literal may only specify known properties, and 'onEnd' does not exist in type 'PanGestureConfig'.
A) The callbacks are properties of one config object with Gesture Handler 3's names: onActivate and onDeactivate; fix the first error and the second goes
B) Downgrade Gesture Handler
C) Add // @ts-ignore
D) Wrap the component in a Pressable
Why: The second error (an implicit any) follows from the first: for a property TypeScript does not know, it cannot type the event (Lesson 7.2).
B is wrong: The SDK pins Gesture Handler 3; the old API is the tutorial's.
C is wrong: Silencing it leaves a callback that never runs.
D is wrong: A Pressable is the button behind the gesture, not a fix for its config.
Q3
With only lottie-react-native installed, the phone is happy and tsc and lint are silent, but npx expo export --platform web stops with this. What is missing?
Error: Unable to resolve module @lottiefiles/dotlottie-react from ~/shoreline/shoreline-crew/node_modules/lottie-react-native/lib/module/LottieView/index.web.js: @lottiefiles/dotlottie-react could not be found within the project or in these directories:
A) A development build
B) The web player: install @lottiefiles/dotlottie-react with npx expo install
C) A Metro config change
D) Nothing: Lottie does not work on the web
Why: lottie-react-native's web version imports the dotlottie web player; on the web it must be installed too (Lesson 7.3).
A is wrong: This is the web bundle, not a native module.
C is wrong: Metro is resolving correctly: the package is not there.
D is wrong: It works once the web player is installed.
Q4
A decorative icon is hidden from screen readers with aria-hidden="true". What does the type checker want?
src/components/Icon.tsx:35:6 - error TS2322: Type '{ name: { ios: "calendar"; android: "calendar_today"; web: "calendar_today"; } | { ios: "mappin.and.ellipse"; android: "location_on"; web: "location_on"; } | { ios: "person.2"; android: "group"; web: "group"; } | ... 7 more ... | { ...; }; size: number; tintColor: string | ... 1 more ... | NativeColorValue; "aria-hi...' is not assignable to type 'ViewProps'.
  Types of property '"aria-hidden"' are incompatible.
    Type 'string' is not assignable to type 'boolean | undefined'.
A) accessible="false"
B) A label instead
C) importantForAccessibility on iOS
D) A boolean: aria-hidden on its own (it means true) or aria-hidden={false}
Why: React Native's ARIA props are typed values, not HTML attribute strings (Lesson 8.1).
A is wrong: Also a string where a boolean belongs.
B is wrong: A decorative icon should be skipped, not named.
C is wrong: That is an Android prop, and the type error is about the value's type.
Q5
Why does the course's Jest setup put Node's own fetch back before the tests run?
A) Node's fetch is faster
B) Jest has no fetch at all
C) Expo SDK 58 replaces fetch with a phone-only one, and MSW can only answer Node's
D) To reach the real shoreline-api
Why: The custom Jest environment restores Node's fetch so MSW 3 can answer every request; an unhandled one fails the test, so no test depends on a server (Lesson 8.2).
A is wrong: Speed is not the reason.
B is wrong: There is one: Expo's, for phones.
D is wrong: The point is never to reach a server.
Q6
npx expo export --platform android in Lesson 8.4. What is this number for?
Android Bundled 19343ms node_modules/expo-router/entry.js (2084 modules)
...
› android bundles (1):
_expo/static/js/android/entry-a0fc6b8a5faced8847b7291067d2d3bd.hbc (5.5MB)
A) A measurement: write it down, change one thing (removing packages the app never uses), export again and compare
B) The store's size limit
C) How much memory the app uses
D) Nothing: bundle sizes do not matter on phones
Why: Measure before you optimize, and after: the rubric's row 8 asks for one measurement written down, and "strong" for one that led to a change.
B is wrong: It is the JavaScript bundle, not the store package.
C is wrong: Memory is measured on a device, not by the export.
D is wrong: A bigger bundle takes longer to load and parse on every start.
Q7
npx expo-doctor before a build. What does it want, and why?
19/20 checks passed. 1 checks failed. Possible issues detected:
✖ Check that no duplicate dependencies are installed
Found duplicates for expo-server:
  ├─ expo-server@58.1.0 (at: node_modules/expo-server)
  └─ expo-server@57.0.3 (at: node_modules/expo-atlas/node_modules/expo-server)
A) Delete node_modules and reinstall
B) Ignore it: only one check failed
C) Pin expo-atlas to the newest version
D) One copy of each native module: an overrides entry in package.json tells npm which expo-server the other package gets
Why: Native builds contain one version of each native module; two copies can lead to unexpected build errors. The older copy came with a development tool (Lesson 9.1).
A is wrong: npm would install the same two copies again.
B is wrong: It is the check that protects the build.
C is wrong: Its newest version may still ask for the previous SDK's expo-server.
Q8
When does a project need a development build instead of Expo Go?
A) As soon as it has more than five screens
B) When it needs a native package Expo Go does not contain, its own name, icon and ids on the phone, or a config plugin's settings
C) Only for the App Store
D) Never: Expo Go runs everything
Why: Expo Go carries only the SDK's modules and Expo's identity; a development build is the app's own, with Metro and Fast Refresh as before (Lesson 9.2).
A is wrong: Screens are JavaScript: Expo Go runs any number.
C is wrong: Builds are about native code, not stores.
D is wrong: Only the modules inside Expo Go.
Q9
The update settings inside a build. What does file:fingerprint mean for an update after a native change?
EXUpdatesRuntimeVersion: 'file:fingerprint'
A) Updates ignore runtime versions
B) The fingerprint is a password for updates
C) The runtime version is a fingerprint of the native side: a native change gives a new runtime version, so it needs a new build; updates reach only builds with the same fingerprint
D) Every update makes a new fingerprint
Why: That is what keeps an update from loading JavaScript on a build whose native code does not match it (Lesson 9.3).
A is wrong: They match on it exactly.
B is wrong: It is a hash of the native project, not a secret.
D is wrong: JavaScript-only updates keep the fingerprint.
Q10
The ids were changed to the client's own domain (org.marisolcrew) and the app config test fails. What is the test protecting, and what do you do?
 FAIL  ./app.config.test.ts
  ✕ builds Shoreline Dev from the development profile (186 ms)
  ✕ builds Shoreline Preview from the preview profile, with an API address (1 ms)
  ✕ refuses the production profile until it has an https API address (2 ms)
The app ids (permanent once a store has seen them): the test makes an id change a deliberate decision. Change the expected names and ids in app.config.test.ts in the same commit, once, before the first store build.
Why: Lesson 9.4: the ids belong to a domain the client controls; the test fails on purpose until the change is written down twice.
Q11
The evidence check on a final project ends like this. What does it mean?
4 passed, 9 to fix, 3 to check
NOT READY: fix the FIX lines above, then run this check again
A) The project failed the course
B) Evidence the rubric asks for is missing: fix every FIX line and run the check again; it lists evidence, it never scores
C) The tests failed
D) The project cannot be shown in the showcase
Why: The check reads files only (names, ids, the worksheet, the example Item, the tests, the README, the review). The rubric scores, with a person; a CHECK line is something to look at, a FIX line evidence to add.
A is wrong: It is not a score, and "not yet" rows are a to-do list.
C is wrong: It never runs the tests: CI does.
D is wrong: Every learner shows their project; missing evidence is fixed by the evidence date.
Q12
Your peer reviewer writes: "At the largest text size the late list cuts off the kayak names." How do you answer the point?
With a fix and its commit (the row wraps; a screen test at the largest font scale), or with a sentence on why you are leaving it. Every point of the review gets an answer (rubric row 10).
Why: peer-review.md ends with exactly that rule for the author; a review answered point by point is evidence for rows 7 and 10.

Course Retrospective: What to Listen For

  • R1 and R2: a change from a wish ("I want to make apps") to a claim with evidence ("I built and shipped a phone app for a client, with tests and a privacy inventory"). Ask for the evidence behind each word.
  • R3: the hardest lessons are usually 5.5 (offline) and 8.3 (screen tests); what made them click is usually a red screen read from the top, or a test that failed for a real bug.
  • R4: one direction, not five; a first project that fits a month.
