Development Builds and EAS Build

By the end you can
  • Say when Expo Go is no longer enough, and which parts of Shoreline Crew need a build of their own
  • Explain what a development build is, add expo-dev-client, and say which changes need a new build and which only need Metro
  • Write eas.json with development, preview and production profiles that set APP_VARIANT and the API address, and test them on your computer
  • Link the project to an Expo account by hand when the config is app.config.ts, and keep keys in EAS environment variables
  • Start a cloud build, read its queue and limits honestly, install the result on an Android phone or emulator, and name what an iPhone build costs
  • Choose between a cloud build and a local build, and say what each needs on your computer
Key ideas
  • Expo Go is a borrowed app with a fixed native kit, one SDK, its own name and id. A development build is your own debug app with Expo's developer tools (expo-dev-client): your native code, your label, still loading JavaScript from Metro with Fast Refresh. A release build (preview, production) has the JavaScript inside.
  • JavaScript = Metro, native = a new build. Screens, hooks, styles, tests and EXPO_PUBLIC_ values for Metro need no build; a package with native code, a config plugin option, the name, ids, icons and permission sentences do.
  • eas.json is the packing list: one build profile per kind of build (--profile); developmentClient, distribution: "internal" (an APK from a link on Android), env (this profile's variables), environment (which set of EAS environment variables), autoIncrement with appVersionSource: "remote".
  • A cloud build never sees .env.local: EAS CLI evaluates app.config.ts with the profile's env and EXPO_NO_DOTENV=1, and .gitignore keeps the file out of the upload. Addresses go in the profile; keys go in EAS environment variables (sensitive).
  • With app.config.ts, EAS cannot write the project id: paste owner and extra.eas.projectId into easProject yourself.
  • Costs, honestly: a free account and the free plan build Android and iOS within a monthly limit, in a low-priority queue (check Expo's pricing page); a real iPhone needs the paid Apple Developer Program; Android builds install free. Local builds (npx expo run:android) trade setup for queue time.
Worked example: a profile tested before a build

The lesson's profile test reads each profile's env and runs app.config.ts with it, the way EAS CLI does (no .env.local). All three pass on the finished code:

npm test -- --watchAll=false app.config
 PASS  ./app.config.test.ts
  ✓ builds Shoreline Dev from the development profile
  ✓ builds Shoreline Preview from the preview profile, with an API address
  ✓ refuses the production profile until it has an https API address
Tests:       3 passed, 3 total

One misspelled word in eas.json, "APP_VARIANT": "prevue", passes EAS's own eas.json check (it cannot know your variants) and fails the test with Lesson 9.1's message:

● builds Shoreline Preview from the preview profile, with an API address
  APP_VARIANT must be development, preview or production, not "prevue".

Read it from the top: which test (the preview profile), the message (the guard you wrote), then the code frame (line 21 of app.config.ts). Caught in a fraction of a second on your computer instead of minutes into a cloud build that counts against your month.

Glossary

TermMeaning
development buildA debug build of your own app with Expo's developer tools; loads JavaScript from Metro
expo-dev-clientThe package that turns a debug build into a development build (launcher, developer menu)
release buildA build with the JavaScript inside (preview, production): no Metro, no developer menu
EAS BuildExpo's cloud build service (Expo Application Services); driven by npx eas-cli@latest
build profileOne entry in eas.json's build section, picked with --profile
internal distributionInstalled directly from a link, not from a store (an APK on Android; ad hoc on iPhones)
APK / AABThe Android file a phone installs from a link / the App Bundle Google Play wants
EAS environment variablesValues stored on expo.dev per environment (plain text, sensitive, secret)
keystoreThe key that signs an Android app; EAS can create and keep it
ad hoc provisioningApple's way to install a build on registered iPhones (paid membership)
build queueThe line a cloud build waits in for a free server (low priority on the free plan)
local buildnpx expo run:android / run:ios / eas build --local: built on your own computer
