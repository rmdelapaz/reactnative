Lessons

4.1

File-Based Routing

By the end you can
  • Explain how Expo Router turns the files in src/app into screens and addresses, including layouts, index, dynamic [id] segments and +not-found
  • Configure a stack and its header bar in three places: for every screen, for one route in the layout, and from inside a screen once its data has loaded
  • Move between screens with Link (including asChild on your own button) and with the imperative router, and choose push or replace
  • Read a route's params with useLocalSearchParams, typed from the route, and explain why they are always strings
  • Use typed routes to catch broken links with tsc, and know when Metro must run to refresh them
Key ideas
  • Files are screens: src/app/index.tsx is /, cleanups/[id].tsx is /cleanups/<any id>, _layout.tsx wraps the screens of its folder (no address), +not-found.tsx catches everything else. Only route files belong in src/app.
  • The stack: push puts a screen on top, back pops it, and the screen underneath keeps its state. On phones it is a native stack: each platform draws its own header and back button (iPhone: chevron with words, swipe from the edge; Android: arrow, system back).
  • Screen options at three levels: <Stack screenOptions> for every screen, <Stack.Screen name="…"> in the layout for one route, <Stack.Screen options={{ title }} /> inside a screen for loaded data.
  • Link and the router: a Link (with asChild on your own Button) for "go there"; router.push, replace, back and canGoBack() when code decides. Opened from its address, a screen has nothing underneath.
  • Params are strings from the address: name the route, useLocalSearchParams<'/cleanups/[id]'>(), and handle an id that names nothing (the API's 404).
  • Typed routes: Metro writes .expo/types/router.d.ts; a misspelled link is a tsc error. A route added while Metro was stopped gives stale types: start Metro first.

shoreline-crew/src/app/cleanups/[id].tsx
  // Back where the volunteer came from; opened from a link, there may be nothing to go back to
  function leave() {
    if (router.canGoBack()) {
      router.back();
    } else {
      router.replace('/');
    }
  }

4.2

Tabs, Nesting and Modals

By the end you can
  • Build a tab bar with Expo Router's JavaScript Tabs, with an icon, a title and themed colors for each tab, and explain how it differs from the template's NativeTabs
  • Use a group folder, (tabs), to nest the tab navigator inside the root stack without changing any address
  • Decide where a screen belongs: on top of the tabs (no tab bar), inside a tab (tab bar stays), or as a modal, and say which edges of the phone each one touches
  • Present a screen as a modal, close it with a button that works however it was opened, and describe how iPhones, Android phones and the web preview show it
  • Read the warnings and odd headers that a mismatch between a layout and its files produces, and fix them
Key ideas
  • Tabs switch, stacks push: a visited tab stays mounted with its state; a tab never opened is not drawn; back goes to the first tab. Import Tabs from expo-router/js-tabs (the same bar everywhere); NativeTabs is the system's own bar.
  • A group folder (tabs) shares a layout and adds nothing to the address: (tabs)/profile.tsx is /profile.
  • Navigators nest: the root Stack holds (tabs) as one screen (hide its header), next to the cleanup screen, the modal and not-found. headerBackTitle: 'Back', or a back button says "(tabs)".
  • Where a screen goes: in the root stack it covers the tabs (one address, reachable from anywhere); in a stack inside one tab the bar stays; as a modal it slides up over everything.
  • Edges: leave out every edge a bar covers: Cleanups ['top', 'left', 'right'], tab screens with a header ['left', 'right'], stack screens and modals ['bottom', 'left', 'right'].
  • A modal is a stack route with presentation: 'modal' and an address; it needs a visible Done that goes back, or replaces with / when nothing is underneath. The web preview shows it as an ordinary screen.
Worked example: the root stack and a tab that vanishes

The tab layout names one file per tab, and the root stack holds the whole group as ONE screen, its header hidden, next to the cleanup screen and the modal (the course's code after Lesson 4.2):

shoreline-crew/src/app/_layout.tsx
      <Stack
        screenOptions={{
          headerTitleStyle: { fontFamily: fonts.heading },
          // The back button's words. Left alone, it shows the previous screen's title, and under
          // the tabs that is the folder's name, "(tabs)"
          headerBackTitle: 'Back',
        }}
      >
        {/* ...and these to one. The tabs are ONE screen of this stack, with their own headers */}
        <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
        {/* Until the cleanup has loaded and its screen sets its own title */}
        <Stack.Screen name="cleanups/[id]" options={{ title: 'Cleanup' }} />
        <Stack.Screen name="+not-found" options={{ title: 'Not found' }} />
        {/* A modal: it slides up over the tabs or a cleanup, instead of being pushed from the side */}
        <Stack.Screen
          name="before-you-go"
          options={{ presentation: 'modal', title: 'Before you go' }}
        />
      </Stack>

Now the tab name="my-cleanup", one letter short. npx tsc --noEmit prints nothing (screen names are plain strings). Metro, rendering the app, prints:

λ  WARN  [Layout children]: No route named "my-cleanup" exists in nested children: [ 'index', 'logbook', 'my-cleanups', 'profile' ]

and the tab bar has three tabs: My cleanups is gone. The warning lists the names that exist; fix the layout's name.

Glossary

TermMeaning
routeA screen with an address; in Expo Router, a file in src/app
layout (_layout.tsx)Wraps the screens of its folder and holds their navigator; not a screen
stackA navigator that pushes screens on top and pops them on back
dynamic route ([id])A file whose bracketed segment matches any one part of the address
paramsValues from the address, always strings: useLocalSearchParams
typed routesTypes for every address, written by Metro in .expo/types/router.d.ts
not-found route (+not-found.tsx)The screen for an address no other file matches
replaceShow a screen in place of the current one: back does not return to it
tab navigatorA bar of buttons that switches between screens that stay mounted
group ((tabs))A folder in parentheses: shares a layout, adds nothing to the address
nested navigatorsA navigator inside a screen of another (the tabs inside the root stack)
modalA stack route with presentation: 'modal': a short detour over everything
headerBackTitleThe words on a stack's back buttons
NativeTabsExpo Router's tab bar drawn by the phone itself (expo-router/native-tabs)
sitemap (/_sitemap)Expo Router's developer list of every route
