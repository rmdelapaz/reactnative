1.3

From the HQ to the Phone

By the end you can
  • Decide which code from a React web app carries over to React Native unchanged, which must be rewritten, and explain why
  • Spot browser-only code (the DOM, sessionStorage, window.location, import.meta.env) that the type checker may not catch
  • Read Expo's TypeScript settings and explain how they and TypeScript 6.0 differ from the web project's
  • Give the app its API address with an EXPO_PUBLIC_ environment variable, and explain when the value is read
  • Set up the shared-code folders and make a typed, checked request whose result appears on the screen
Key ideas
  • The rule: code that only works with data copies over; code that touches the browser gets rewritten. Copied: types.ts (byte for byte), the type guards, ApiError, describeError, formatDate, getAvailability. Rewritten: the API address, the session (4.3), components and CSS (Module 2 on).
  • tsc does not know you are on a phone: Expo's tsconfig loads "lib": ["DOM", "ESNext"] for the web preview, so window, document and sessionStorage type-check and fail on a phone. tsc DOES catch import.meta.env (TS2339) and missing files (TS2307). Search copied code yourself.
  • Same fetch, different failures: on phones Expo replaces fetch (expo/fetch); with no answer it throws a FetchError ("fetch failed: …"), not the browser's TypeError. The phone's request() wraps any failed fetch in a NetworkError, and describeError checks for that.
  • Expo's TypeScript settings: one short tsconfig.json extending expo/tsconfig.base, strict, @/* → ./src/* (imports without .ts). SDK 58 pins TypeScript 6.0: same checks as 7.0, and the one npx expo lint's TypeScript tools support.
  • EXPO_PUBLIC_ variables: .env.example (in Git) documents, .env.local (not in Git) holds your value; read as process.env.EXPO_PUBLIC_API_URL, copied into the bundle when Metro builds it: restart with --clear after a change, write the full name with a dot (destructuring is a lint error and leaves the address out), never secrets.
  • The address today: http://localhost:4000 in the web preview. On a phone localhost is the phone, so Expo Go shows "Could not reach the server" until Lesson 5.1.

Glossary

TermMeaning
shared codeCode about the data (types, checks, dates) that works the same on the web and on a phone
src/api/types.tsThe API's contract: a byte-for-byte copy of shoreline-api/core/types.ts, never edited, ignored by ESLint
type guardA function (value: unknown): value is T that checks data from the network before anyone uses it
lib (tsconfig)Which built-in type libraries TypeScript loads; Expo's include DOM, for the web preview
expo/fetch, FetchErrorExpo's own fetch on phones; with no answer it throws a FetchError ("fetch failed: …")
NetworkErrorThe app's own error for "no answer at all", thrown by request()
EXPO_PUBLIC_ variableA value from .env.local, read as process.env.EXPO_PUBLIC_…, copied into the bundle
.env.example / .env.localDocuments the variables (in Git) / holds your machine's values (not in Git)
@/ path alias@/api/client = src/api/client, from any folder (tsconfig paths)
npx tsc --showConfigPrints the settings TypeScript really uses, merged from expo/tsconfig.base
