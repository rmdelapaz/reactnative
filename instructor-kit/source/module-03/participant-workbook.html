2.1

View, Text and StyleSheet

By the end you can
  • Build screens from View and Text, and say which HTML habits they replace
  • Write styles with StyleSheet.create: camelCase names, numbers instead of px, no shorthands, and know which mistakes the type checker catches
  • Explain why styles do not cascade in React Native, and use the one place they do: a Text inside a Text
  • Combine styles with style arrays, where later entries win and false entries are skipped
  • Describe how fonts, font weights, line heights and the person's text size differ between Android, iOS and the web preview
  • Keep the app's colors and spacing in a theme file and build reusable, typed AppText and EventCard components
Key ideas
  • Two building blocks: View is a box (size, background, border, padding, layout; no text); Text shows text, and only Text can. Headings are Text with accessibilityRole="header". A string straight in a View is the red screen on a phone; the web preview forgives it.
  • Styles are objects: camelCase, plain numbers of density-independent pixels (dp / points; 16 is about the same size on every phone), percentages as strings, no shorthands (borderWidth + borderColor, paddingVertical / paddingHorizontal), lineHeight is a size, no className, selectors or CSS variables. Colors are the same strings.
  • StyleSheet.create names your styles, keeps them in one place and type-checks each one. Loud: fontSize: '16px' (TS2322), border (TS2345), a misspelled property or style name. Silent: padding: '16px', text styles on a View, lineHeight: 1.5, and className in a project with Expo's generated types.
  • No cascade: a style stays on its component. The one exception: a Text inside a Text inherits the outer Text's text styles and changes only what it sets (the bold spots number). Hence a shared text component, AppText.
  • Style arrays: style={[a, b && c, props.style]} merges left to right, later entries win, false / null / undefined are skipped. AppText: base, then variant, then the screen's style.
  • Text per platform: system fonts (San Francisco, Roboto; the browser's in the web preview), fontWeight falls back to the closest weight, line height about 1.5 × the size, and text grows with the person's settings (allowFontScaling true): never a fixed height on text. Theme: brand colors and roles named by their job in src/theme/, ready for dark mode (Lesson 2.5).

Glossary

TermMeaning
ViewThe box: size, background, border, padding, layout of its children; no text (android.view.View / UIView)
TextThe only component that shows text; a Text inside a Text is inline and inherits
density-independent pixelReact Native's unit (Android dp, iOS points): about the same physical size on every screen
StyleSheet.createNamed style objects in one place, each type-checked against what a View, Text or Image accepts
style array[a, b, c]: merged left to right, later entries win, false/null/undefined skipped
no cascadeA style belongs to one component; nothing flows down from a View
text inheritanceA nested Text gets the text styles of the Text around it
StyleSheet.flattenMerges a style array into one plain object (to look at what a component really gets)
theme tokens / color rolesColors named by their job (page, heading, error), not their look; one file to change
contentContainerStyleA ScrollView's style for the content that scrolls (padding, gap), next to style for the window
allowFontScalingOn by default: Text follows the person's text size setting
expo-env.d.tsWritten by the first npx expo start: loads Expo's types (they add className for the web preview)
