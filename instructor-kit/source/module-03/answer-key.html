2.1 · View, Text and StyleSheet: self-check

Q1
Shoreline Crew HQ wrote <p>5 of 12 spots left, <strong>5</strong> …</p>. What is the phone's version of the <strong> inside the <p>?
A) A Text inside a Text, with only fontWeight in its style
B) A View with fontWeight: 'bold' around the number
C) A <b> element: React Native keeps the HTML inline tags
D) A second Text beside the first in a row View
Why: A nested Text is React Native's inline text: it inherits the color, size and line height of the Text around it and changes only what it sets (EventCard's spots number). Lab 2.1 Task 3 builds exactly this.
B is wrong: A View draws no text and passes no text styles on.
C is wrong: There are no HTML elements on a phone.
D is wrong: Two separate Texts lose the shared style, and no single Text holds the sentence (Lab 2.1 Task 3's starter).
Q2
npx tsc --noEmit in shoreline-crew prints this (cut to its first line and the code frame). Which change fixes it?
src/components/AppText.tsx:20:5 - error TS2322: Type 'string' is not assignable to type 'number'.
20     fontSize: '16px',
       ~~~~~~~~
Found 1 error in src/components/AppText.tsx:20
A) Write fontSize: '16' without the px
B) Set "strict": false in tsconfig.json
C) Write fontSize: 16
D) Move the style into an inline style={{ ... }}
Why: React Native's sizes are plain numbers of density-independent pixels: fontSize is typed number. Read the error from the top: file and line, the type expected (number), the tildes under the property.
A is wrong: Still a string: the same TS2322.
B is wrong: Hiding the check does not make '16px' a size a phone understands.
D is wrong: Inline styles are checked against the same types.
Q3
Predict: the card's style says padding: '16px'. What does npx tsc --noEmit print, what does the web preview show, and what should a phone do?
card: {
  padding: '16px',
  borderRadius: radius.card,
},
tsc prints nothing; the web preview shows 16 pixels of padding; a phone should ignore it (no padding)
Why: React Native 0.88's types allow any string for sizes, so it type-checks; the browser understands px, React Native's native layout code (read for this version) only numbers, 'auto' and percentages. The kit ran tsc: silence. Sizes are numbers, percentages are strings (the lesson's version note).
Q4
<Text style={[styles.line, full && styles.full]}> renders with full set to false. What happens?
A) An error: false is not a style
B) Both styles apply; full wins where they overlap
C) Only styles.full applies
D) Only styles.line applies: React Native skips the false entry
Why: A style array merges left to right, later entries win, and false, null and undefined are skipped. The kit's Jest run of the lesson's Spots printed {"fontSize":16,"color":"#1f2a37"} for an open cleanup.
A is wrong: Skipping falsy entries is what makes conditions this easy.
B is wrong: With full false there is no second style.
C is wrong: The base comes first and always applies.
Q5
AppText draws the banner's title. Which merged style does StyleSheet.flatten([styles.base, styles[variant], style]) give it?
<AppText variant="title" accessibilityRole="header" style={{ color: colors.onBanner }}>
  Shoreline Crew
</AppText>
A) {"color":"#1f2a37","fontSize":32,"lineHeight":40,"fontWeight":"bold"}
B) {"color":"#ffffff","fontSize":32,"lineHeight":40,"fontWeight":"bold"}
C) {"color":"#ffffff"}
D) {"color":"#1f2a37","fontSize":16,"lineHeight":24}
Why: Base (Ink, 16/24), then the title variant (32/40 bold replaces the size and line height), then the screen's style (white replaces Ink). The kit printed this line from Jest with React Native's renderer.
A is wrong: That would be the base's Ink winning: the screen's style comes LAST and wins.
C is wrong: Every layer only says what it changes; the rest comes from the earlier layers.
D is wrong: The title variant replaces the base's size and line height.
Q6
The lesson's Heading sets color: '#0b3954' and fontSize: 20 on the View around <Text>Upcoming cleanups</Text>. What style does the Text itself get?
<View style={styles.box}>
  <Text>Upcoming cleanups</Text>
</View>
A) {}: nothing at all; it shows the default size 14 in the default color
B) Deep Tide at 20, inherited from the View
C) Size 20 only: colors are not inherited
D) A red error screen: color is not allowed on a View
Why: No cascade: a style stays on the component you put it on. The kit's Jest run printed the View's merged style with the color and size, and {} for the Text inside it.
B is wrong: That is the web's cascade; React Native has none (only a Text inside a Text inherits).
C is wrong: Nothing passes from a View to a Text, size included.
D is wrong: It type-checks and runs; it just does nothing.
Q7
AppText's heading variant has fontSize: 20. Which lineHeight matches the lesson's rule?
A) 1.5
B) 20
C) '150%'
D) 28
Why: lineHeight is a size in the same units, about one and a half times the font size: AppText's heading is 20/28, the body 16/24.
A is wrong: 1.5 units: the line squeezes into a sliver (no type error).
B is wrong: Lines touch: no room between them.
C is wrong: A percentage string is not how React Native sizes a line height.

Q9
In your shoreline-crew project (after your first npx expo start), you type <View className="card">. What does npx tsc --noEmit print?
A) TS2322: Property 'className' does not exist
B) Nothing: Expo's generated types add className for the web preview, and a phone ignores it
C) TS2551 with Did you mean 'style'?
D) A red error screen, before anything runs
Why: The kit ran it: nothing. expo-env.d.ts (written by the first npx expo start, Lesson 1.2) loads expo/types, which adds className to ViewProps and TextProps for react-native-web. So className is one of the SILENT habits; use style={styles.card}. (Only a project that was never started, without the generated file, prints TS2322.)
A is wrong: Only without expo-env.d.ts, which every learner's project has after Lesson 1.2.
C is wrong: TS2551 is for a misspelled property that exists under a similar name.
D is wrong: tsc checks; it never draws a screen.
Q10
Why can a theme typo such as colors.pgae not slip through the way var(--pgae) did in CSS?
A) The theme is TypeScript code: a property that does not exist is a type error
B) React Native refuses to start with an unknown color
C) StyleSheet.create checks the hex codes
D) Metro replaces unknown colors with black
Why: colors is an as const object exported from src/theme/colors.ts, so tsc knows every key. A misspelled CSS variable just silently fell back.
B is wrong: Nothing at run time checks it: tsc does.
C is wrong: It checks style properties, not your theme's keys.
D is wrong: Metro does not type-check or replace anything.
Q11
The Cleanups screen's ScrollView takes two style props. Which one gets the Sand background, which one the padding and gap, and why?
<ScrollView style={styles.screen} contentContainerStyle={styles.content}>
style = the scrolling window (Sand fills the screen); contentContainerStyle = the content that scrolls (padding and gap travel with the cards)
Why: Padding on the window would stay put while the cards slide under it; on the content strip it scrolls with them (Lesson 2.1, Step 4).
Q12
A volunteer has made all text larger in the phone's settings. Which habit breaks the Cleanups screen for them?
A) Leaving allowFontScaling at its default, true
B) Giving every AppText variant a lineHeight
C) A fixed height on a box that holds text
D) Using the system font
Why: React Native follows the person's text size by default, so a 16 can become 20 or much more; a fixed height clips the text. Let text grow and wrap (Lesson 8.1 tests the extremes).
A is wrong: That is what you want: never turn it off.
B is wrong: A line height in proportion grows with the text.
D is wrong: System fonts follow the setting best of all.

The Lesson Page's Own Quick Quiz

Lesson 2.1 · View, Text and StyleSheet
  1. B The text in the default color, because a View passes no styles on: Styles stay on the component you put them on, and a View has no text to color. The Text uses the default style. Put the color on the Text, or use AppText with the heading variant.
  2. D White: A style array is merged from left to right and later entries win, so the screen's own style, which comes last, sets the color. That is why AppText puts the style prop at the end.
  3. A Every line is squeezed into a sliver 1.5 units tall: lineHeight is a size in the same units as fontSize, not a multiplier. 1.5 units is far less than one line of 16-unit text, so the lines collapse. tsc cannot know you meant a multiplier. Use 24 for 16-unit text.
  4. C From a Text to a Text nested inside it: A nested Text inherits the text styles of the Text around it and changes only what it sets, which is how EventCard makes just the spots number bold. Everywhere else there is no inheritance, which is why the app has AppText.
  5. B So one file can change what each job looks like, for example a dark palette in Lesson 2.5: A role says what a color is for, so Lesson 2.5 can give each role a dark-mode value in one file and every screen follows. It also keeps the app to one set of colors.

Exit Ticket

  1. Loud and silent: loud: fontSize: '16px' (TS2322), border: '1px solid …' (TS2345); silent: padding: '16px', a color or font size on a View, lineHeight: 1.5, className in a started project. Any two of each.
  2. Inheritance: only from a Text to a Text nested inside it; a View passes nothing on.
  3. AppText's order: later entries in a style array win, so the screen's style, last, can change anything the base or the variant set (the banner's white title over the base's Ink).

Common Wrong Answers and What They Reveal

  • Q1 B or D. Still thinks in HTML layout: show Lab 2.1 Task 3's starter, where the row of pieces loses the line's style.
  • Q3 "tsc catches it". Expects the types to know what a phone accepts: the lesson's version note, then the demo's silence.
  • Q5 A. Reads the array right to left. Point at AppText's comment: the screen's style comes last and wins.
  • Q6 B. The web's cascade: run the demo's Jest file and read the {}.
  • Q9 A. Habit from older React Native. Run the className step in a started project: nothing; only a project without expo-env.d.ts prints TS2322.
  • Q12 A. Turning font scaling off to protect a layout: the fix is a layout that grows (Lesson 8.1).
