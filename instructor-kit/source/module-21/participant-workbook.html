Key ideas
  • RNTL 14 is the web's Testing Library for native views: await render(...) (render, rerender, renderHook, fireEvent and act are async), userEvent from RNTL (press, type, clear, longPress, scrollTo), built-in matchers (toBeOnTheScreen, toBeChecked, toHaveTextContent, toHaveDisplayValue, toBeDisabled), no DOM: the tree is View, Text, TextInput, RCTSwitch.
  • Queries see what a screen reader sees: role from accessibilityRole or role, name from accessibilityLabel, aria-label or the text inside. Hidden elements (aria-hidden, screens behind a modal) are skipped unless you pass { includeHiddenElements: true }.
  • Presses follow the touch system: user.press() plays press in, press out, press, and respects pointerEvents; fireEvent(el, 'valueChange', true) sends one event by name (a screen reader flipping a native switch).
  • The pretend phone: React Native's preset window is 750 x 1334 with fontScale 2 until the setup sets a phone; Platform.OS is 'ios' (jest.replaceProperty for Android); AccessibilityInfo is a recording stand-in; Dimensions.set() inside act() plays a text-size change.
  • Screens under Expo Router: renderRouter(routes, { initialUrl }) with routes written like file names, testRouter, toHavePathname. It switches on fake timers: keep nextTick and queueMicrotask real (fakeTimers.doNotFake), and remember findBy counts fake time. Tests live in src/test/screens/, never src/app/.
  • What is worth a test: decisions a person depends on (loading, errors, guests, presses, names). Not styles, whole-tree snapshots, libraries or internals. Coverage per file is a map of what never ran, not a goal. End-to-end flows (Maestro, YAML, a device and a build) for the few paths that must work every release.
Worked example: reading the printed tree

The lesson's second Common Mistake, made for real in a copy of the finished project: a plain getByText('Group by date') to press a switch row's words. Jest prints the message, then the screen's tree (the test's eyes), then where:

● flips exactly once for a tap on the switch or on the words

  Unable to find an element with text: Group by date

  <View
    accessible={false}
  >
    <Text
      aria-hidden={true}
    >
      Group by date
    </Text>
    <RCTSwitch
      accessibilityLabel="Group by date"
      accessibilityRole="switch"
      value={true}
    />
  </View>

    37 |   expect(toggle).toBeChecked();
    38 |
  > 39 |   await user.press(screen.getByText('Group by date'));
       |                           ^

Read it in three moves. The message: no element with that text, as far as the queries can see. The tree: the words ARE there, on a Text with aria-hidden={true}, and the switch carries them as its accessibilityLabel. The cause: RNTL skips what a screen reader skips. Find the control by role and name (getByRole('switch', { name: 'Group by date' })); to press the words, as a finger can, say so: { includeHiddenElements: true }.
