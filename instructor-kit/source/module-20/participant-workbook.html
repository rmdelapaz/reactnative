Lesson

8.2

Testing the App's Logic

By the end you can
  • Set up Jest with jest-expo in an Expo SDK 58 project and explain what changes from the web course's Vitest
  • Make the HQ's MSW handlers answer a phone app's requests in Node, and explain the two things that stand in the way (Expo's own fetch, and MSW 3 being an ES module)
  • Replace native modules in tests in three ways: jest-expo's automatic stand-ins, a library's own Jest mock, and your own jest.mock()
  • Test Shoreline Crew's logic where it matters most: rules (address checks, schemas), files (the CSV export), the offline queue, the log sender's five outcomes and the reminders
  • Read a failing Jest run in the terminal and tell a broken test setup from a broken app
Key ideas
  • A dry run on the dock: jest-expo makes Node look like an iPhone (Babel with Expo's preset, React Native's Jest setup, a stand-in for every Expo native module, Platform.OS 'ios'). The app's decisions are real; the world around them is pretend.
  • From Vitest: globals instead of imports, jest.fn() / jest.mock() / jest.mocked(), settings in package.json, npm test watches (npm test -- --watchAll=false runs once), never a test inside src/app/.
  • Requests: SDK 58's global fetch is Expo's; jest.environment.js keeps Node's and jest.setup.ts puts it back (twice). MSW 3 is ES modules only: the test script starts Node with --experimental-vm-modules.
  • Three stand-ins: automatic (jest-expo), the library's own mock (AsyncStorage), your own jest.mock(). An empty jest.fn() answers undefined.
  • What to test: what is invisible and costly (the queue, the sender's five outcomes, the reminders, the CSV file). Reset module state in beforeEach. Assert on ids, titles and messages, not dates.

Self-check
Q1
The HQ's test files began with import { describe, it, expect, vi } from 'vitest'. What does a Shoreline Crew test file import instead?
A) import { describe, it, expect, jest } from 'jest-expo'
B) Nothing: describe, it, expect and jest are globals, typed by @types/jest through "types": ["jest"]
C) import { describe, it, expect } from '@testing-library/react-native'
D) import * as vi from 'jest', so the HQ's vi.fn() keeps working
Q2
A learner types npx jest src/state/sendLogs.test.ts and gets this. What do you tell them?
 FAIL  src/state/sendLogs.test.ts
  ● Test suite failed to run

    Must use import to load ES Module: ~/shoreline/shoreline-crew/node_modules/msw/lib/core/index.js
A) Add msw to transformIgnorePatterns, as the message suggests
B) Upgrade Node to the newest version
C) Run npm test -- --watchAll=false src/state/sendLogs.test.ts: the script starts Node with --experimental-vm-modules
D) Reinstall MSW with npm install msw@2
