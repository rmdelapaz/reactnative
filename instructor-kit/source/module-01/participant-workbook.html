Lessons

1.1

How React Native Works

By the end you can
  • Explain how React Native turns your components into native views, and why there is no DOM on a phone
  • Describe the New Architecture in plain words: Hermes, JSI, the Fabric renderer and native modules
  • Sort what carries over from React on the web and what changes on a phone
  • Say what Expo adds (the CLI, the SDK, Expo Router, Expo Go, development builds, EAS) and when each one is used
  • Describe the Shoreline Crew phone app and how it shares an API and types with Shoreline Crew HQ
Key ideas
  • No DOM on a phone: React Native's components stand for the phone's own native views. <View> is the box (div), <Text> holds all text (no loose text), <Pressable> with onPress makes something tappable, StyleSheet.create replaces CSS (camelCase, numbers without units, no selectors or cascade).
  • The web preview is a translation: react-native-web turns the same components into HTML (a View becomes a <div>). Use it for layout and data; confirm native behavior on a phone.
  • The New Architecture: Hermes runs your JavaScript inside the app; JSI lets it call native code directly; Fabric renders native views; native modules (TurboModules) give it the camera, location, secure storage. "The bridge" is the old design.
  • What carries over: components, props, state and every hook, TypeScript, TanStack Query, Zustand, React Hook Form with Zod, the API and its JSON. What changes: HTML and CSS, long lists, URLs and navigation, localhost and the network, storage, permissions, the stores.
  • Expo is the framework around React Native: the CLI (npx expo …), the SDK (numbered: SDK 58), Expo Router, Expo Go (runs your project while you develop), development builds (your own Expo Go with your native modules), EAS (cloud builds, updates, submissions; a free plan).
  • Shoreline Crew is the volunteers' phone app (cleanups, details, my cleanups, check in, logbook, profile) on the same shoreline-api and types as the HQ web app.

Now the classic web habit: {title} straight inside the View, without a <Text>. npx tsc --noEmit prints nothing; running it gives the words a phone shows on its red error screen:

● the cleanup cards, as React Native draws them
  Invariant Violation: Text strings must be rendered within a <Text> component. Detected attempt to render "Weekend Cove Cleanup" string within a <View> component.
● pressing Sign up changes the button, exactly as on the web

Read it from the top, the way you read a TypeScript error: what (an Invariant Violation), the rule (text only inside Text), the evidence (which string, inside which component). The type checker allows any child in a View; only running the code shows this.

1.2

Your Toolchain

By the end you can
  • Set up Node.js, VS Code with Expo Tools and the shoreline-api for mobile development
  • Create an Expo SDK 58 project with create-expo-app and explain what each of its files is for
  • Run the app on a phone with Expo Go or in the web preview, and choose between Expo Go, an emulator and the web preview
  • Use the development loop: Metro, Fast Refresh, reload, the developer menu and the error screens
  • Check the project with npx expo lint and npx tsc --noEmit, and fix the first-run surprises both tools have
Key ideas
  • The toolchain: Node.js LTS (24 or newer, with npm and npx), VS Code with Expo Tools, Git, the Expo CLI through npx (nothing global), Metro, Expo Go on your phone, the shoreline-api. Android Studio and Xcode are optional.
  • Three ways to run: Expo Go on a phone (the real thing; the course default), an emulator or simulator (optional; the iOS Simulator needs a Mac), the web preview (layout, text, data; not native look, permissions or the camera).
  • Metro transforms (types removed, not checked), bundles per platform, serves on 8081, watches and caches (--clear). The QR code carries exp:// and your computer's network address; the web preview is http://localhost:8081 on this computer only. Fast Refresh keeps state; r reloads; m opens the developer menu.
  • The phone must reach your computer: the same Wi-Fi, one that allows device-to-device traffic, the firewall allowing Node, iPhone Local Network on; WSL needs PowerShell or mirrored networking; otherwise the web preview.
  • A new project: npx create-expo-app@latest shoreline-crew, then npm run reset-project (answer n). "main": "expo-router/entry"; app.json is the app's identity; src/app/ holds routes only; install Expo packages with npx expo install.
  • Two checks before any task is done: npx expo lint (the first run sets up ESLint, then a CommandError: run it again) and npx tsc --noEmit (needs one npx expo start on a fresh template). Both print nothing when the project is clean.
Worked example: a typo the phone ignores

One typo in src/app/index.tsx, styles.tagLine instead of styles.tagline. Metro bundles it, Fast Refresh shows it, and the tagline silently loses its size and color: no error on the phone or in the web preview. The type checker names it before anything runs:

npx tsc --noEmit
src/app/index.tsx:9:27 - error TS2551: Property 'tagLine' does not exist on type 'Readonly<{ container: { flex: number; alignItems: "center"; justifyContent: "center"; gap: number; padding: number; }; title: { fontSize: number; fontWeight: "bold"; color: string; }; tagline: { fontSize: number; color: string; }; }>'. Did you mean 'tagline'?

9       <Text style={styles.tagLine}>Many hands, cleaner sands.</Text>
                            ~~~~~~~


Found 1 error in src/app/index.tsx:9

Read it in four moves. Where: src/app/index.tsx:9:27 = file, line 9, column 27. What: the code TS2551 and the message, with a suggestion (Did you mean 'tagline'?). Why it knows: StyleSheet.create is fully typed, so the type lists every style you defined. The line: printed with ~~~~~~~ under the problem. Fixed, npx tsc --noEmit and npx expo lint both print nothing at all: no news is good news.

Glossary

TermMeaning
React NativeReact for iPhone and Android apps: components become the platform's own native views
native viewA building block of the phone's own interface (Android views, iOS UIView); there is no DOM
core componentsView, Text, Image, Pressable, TextInput, ... (instead of HTML elements)
StyleSheet.createTyped style objects instead of CSS: camelCase names, numbers without units, no cascade
HermesThe JavaScript engine inside the app
JSI, Fabric, native modulesJavaScript calling native code directly / the renderer that makes native views / the phone's features for JavaScript
New ArchitectureReact Native's current (and only) architecture; "the bridge" was the old one
ExpoThe framework around React Native: CLI, SDK, Expo Router, Expo Go, development builds, EAS
Expo SDKA numbered set of native modules released together (the course uses SDK 58)
Expo GoA free phone app that runs your project while you develop it
development buildYour own Expo Go-style app with exactly your project's native code (Lesson 9.2)
EASExpo Application Services: cloud builds, updates and store submissions
MetroExpo's bundler and development server (:8081): transform, bundle, serve, watch, cache
Fast RefreshSaved changes appear on every connected device in a second or two, state kept
web previewThe app in a browser, rendered as HTML by react-native-web (press w)
Expo SnackAn online editor that runs React Native in a browser (Lesson 1.1)
shoreline-apiThe course's mock back end with sample data, at http://localhost:4000/api
AGENTS.mdThe template's notes for AI coding assistants: npx expo install, lint and typecheck before done
