Lessons

4.3

Sign-In Flows and Protected Routes

By the end you can
  • Store a session token in the phone's secure storage with expo-secure-store, explain why it is async, and say what the web preview does instead
  • Restore a saved session at startup while the splash screen stays up, so the first screen already knows who is signed in
  • Guard routes with Expo Router's Stack.Protected, and predict where the app goes when a guard changes or someone opens a guarded address
  • Build a sign-in modal that shows the API's own error messages, never keeps a failed password, and closes back to the screen that opened it
  • Sign out, and handle a 401 from the API by forgetting the session and asking the volunteer to sign in again
Key ideas
  • A token, not a password: the app sends the password once, gets a token and the user back, and keeps only those. Every later request carries Authorization: Bearer <token>.
  • Where it lives: expo-secure-store (iOS Keychain; Keystore-encrypted values on Android): async, strings only (JSON), survives restarts (so Sign out deletes it). Not AsyncStorage, never an EXPO_PUBLIC_ variable. The web preview has none: isAvailableAsync() is false, the session lives in memory only.
  • One store, one listener: the client keeps the session in memory with listeners (copied from the HQ); session.ts restores the saved copy once at startup (the splash screen waits) and saves every change. Imports point one way, or Metro warns about a require cycle.
  • useSession() = useSyncExternalStore(onSessionChange, readSession, () => null): the third function is for the web preview's server.
  • Stack.Protected guard={…} decides which screens exist. A guarded address, or a guard that turns false while its screen is open, redirects to the anchor (or redirectTo). So the sign-in modal closes first, then sets the session. A guard hides screens; the API protects data.
  • When the API forgets you: a 401 to a request that carried a token forgets the session everywhere; Profile asks GET /api/auth/me each time it comes into view (useFocusEffect) and says "Your sign-in has ended. Sign in again."
Worked example: the API's side of a sign-in

The API's side of the sign-in modal, for Theo (theo.nakamura@example.com, shoreline-demo). A wrong password and an empty form get the API's own words, which the screen shows:

HTTP/1.1 401 Unauthorized
cache-control: no-store
content-type: application/json; charset=utf-8
vary: Origin

{
  "error": "unauthorized",
  "message": "Email or password is incorrect."
}

A token the API has forgotten (after a restart) gets a 401 even from the public list of cleanups, because the request claimed to be someone:

HTTP/1.1 401 Unauthorized
cache-control: no-store
content-type: application/json; charset=utf-8
vary: Origin

{
  "error": "unauthorized",
  "message": "Your session has ended. Sign in again."
}

So the client's rule: a 401 to a request that carried a token forgets the session everywhere (setSession(null)), and session.ts's listener deletes the saved copy. A wrong password is also a 401, but from a request without a token: nothing to forget.

shoreline-crew/src/api/client.ts
    if (response.status === 401 && session !== null) {
      // The API no longer knows this sign-in (it restarted, or the session ended): forget it here too
      setSession(null);

4.4

Deep Links

By the end you can
  • Read a deep link such as shorelinecrew://cleanups/e08: its scheme, its path, and the file in src/app that answers it
  • Say which form of a link opens the app in a build, in Expo Go and in the web preview, and let Linking.createURL make the right one
  • Put the tabs underneath a screen opened by a link with unstable_settings.anchor, and predict where a link to a guarded screen goes
  • Share a link to a cleanup through the phone's share sheet with React Native's Share, with a fallback where there is none
  • Open links on an Android emulator, an iOS Simulator or a phone, and treat every incoming link as input from outside
Key ideas
  • A deep link = a scheme (which app: shorelinecrew, in app.json since Lesson 1.2, written into the native projects at build time) + a path (which screen: Expo Router reads it like a web address) + optional search params.
  • Three forms of one link: a build shorelinecrew://cleanups/e08; Expo Go exp://192.168.1.42:8081/--/cleanups/e08 (Expo Go owns exp; only for testing); the web preview http://localhost:8081/cleanups/e08. Linking.createURL makes the right one.
  • unstable_settings = { anchor: '(tabs)' } keeps the tabs underneath any screen a link opens, so back leads somewhere. The anchor names a screen of THAT layout; the tabs underneath load their data too. With an anchor, send people home with dismissTo, not replace.
  • Links to guarded screens follow the guard (redirect to the anchor). Every link is input from outside: ids go through encodeURIComponent, unknown ids and paths have screens, and a link only ever opens a screen.
  • Share.share() opens the share sheet: Android passes only title and message (the link goes inside the message), iOS message and url; the web preview rejects without a share sheet, so show the link in a selectable Text.
  • On a device: npx uri-scheme open "…" --android|--ios, adb shell am start …, xcrun simctl openurl booted … (quote the URL), or send yourself the link. npx uri-scheme list finds nothing until a build.
Worked example: the scheme and the anchor

The scheme in app.json (grep -n '"scheme"' app.json in shoreline-crew):

8:    "scheme": "shorelinecrew",

With it, shorelinecrew://cleanups/e08 opens src/app/cleanups/[id].tsx with id e08, in a build of the app. Expo Go answers exp://192.168.1.42:8081/--/cleanups/e08 (your address differs) and the web preview http://localhost:8081/cleanups/e08; Linking.createURL picks. The anchor puts the tabs underneath whatever a link opens:

shoreline-crew/src/app/_layout.tsx
export const unstable_settings = {
  anchor: '(tabs)',
};

Glossary

TermMeaning
tokenThe API's proof of a sign-in, sent as Authorization: Bearer <token> with every request
sessionThe token and the user it belongs to (SignInResponse), kept in memory by the client
secure storageexpo-secure-store: the iOS Keychain, or Keystore-encrypted values on Android; async, strings only
useSyncExternalStoreReact's hook for a store outside React; the third function answers for the web preview's server
Stack.ProtectedA group of screens that exist only while its guard is true
anchorThe screen always at the bottom of a layout's stack (unstable_settings.anchor); also where a guard redirects
401 UnauthorizedThe API does not know who you are: a wrong password, no token, or a token it forgot
config pluginA setting in app.json that changes the native projects when the app is built
require cycleTwo files that import each other; Metro warns, and a value can be undefined
deep linkA link that opens one screen inside an app: scheme + path
schemeThe app's part of a link (shorelinecrew), registered with the phone when a build is installed
exp://…/--/…Expo Go's form of a link to your project during development
dismissToClose screens back to an address already underneath (replace only when there is nothing)
share sheetThe phone's panel for sending something to another app; React Native's Share.share()
universal links / App Linkshttps links that open the app when installed and a web page otherwise (after Module 9)
