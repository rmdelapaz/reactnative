2.2 · Flexbox the Native Way: self-check

Q1
A new View holds a badge (a View with one Text) and nothing else is styled. The badge has a background color. How does it look on the phone?
A) A bar of color as wide as its parent
B) A pill just wider than its word
C) A square as tall as it is wide
D) Nothing at all: a View without a size is not drawn
Why: Every View is a flex column with alignItems: 'stretch', so a child fills the column's width: Lesson 2.2 measured the Scheduled badge at 340 instead of 93 in the web preview. In a row, or with alignSelf: 'flex-start', it keeps the width of its word.
B is wrong: That is the badge inside a row, or with alignSelf: 'flex-start'.
C is wrong: Nothing makes it square: its height still comes from its content.
D is wrong: A View is as tall as its content and, in a column, as wide as its parent.
Q2
You write the CSS shorthand in Screen's style. What does npx tsc --noEmit say, and what do you write instead?
screen: {
  flex: '1 1 0%',
  backgroundColor: colors.page,
},
error TS2322: Type 'string' is not assignable to type 'number'. Write flex: 1 (or flexGrow, flexShrink and flexBasis as three properties)
Why: In React Native flex is ONE number: a share of the free space (Yoga turns a positive flex into flexGrow with a basis of 0). The kit ran it on the stage app: the lesson's card, line for line.
Q3
In the Cleanups screen's header row someone writes alignItems: 'space-between'. Which change fixes what npx tsc --noEmit reports?
src/app/index.tsx:81:5 - error TS2322: Type '"space-between"' is not assignable to type '"center" | "flex-start" | "flex-end" | "stretch" | "baseline" | undefined'.
Found 1 error in src/app/index.tsx:81
A) Change 'space-between' to "space-between"
B) Add display: 'flex' to the row
C) Move space-between to justifyContent and keep alignItems: 'center'
D) Change flexDirection to 'column'
Why: space-between distributes children along the main axis: that is justifyContent's job. alignItems works across it and accepts only flex-start, flex-end, center, stretch and baseline (the type the message lists). The lesson's quiz Q5 is the same row.
A is wrong: The quotes do not matter: the value is not allowed in alignItems.
B is wrong: Every View is already a flex container; display: 'flex' changes nothing.
D is wrong: A column swaps the axes but alignItems still cannot take space-between.
Q4
EventCard's Detail row: the label has width: 72. Why does the value have flex: 1?
A) To make the value line up with the card's title
B) So it takes the space the label leaves and wraps inside it, instead of running past the card on a phone
C) Because a Text in a row is invisible without a flex value
D) To make the value as tall as the label
Why: Nothing shrinks by default (flexShrink: 0), so a long Text in a row keeps its natural width. flex: 1 gives it exactly the rest of the row and lets it wrap there (the lesson's quiz Q2).
A is wrong: The fixed label width lines the values up, not the value's flex.
C is wrong: The Text is visible either way; the question is where it ends.
D is wrong: In a row, both stretch to the row's height anyway (alignItems: 'stretch').
Q5
Lesson 2.2, Step 5: you delete flex: 1 from detailValue and the web preview barely changes. What should you conclude?
A) flex: 1 was never needed: delete it for good
B) Metro's cache is stale: restart with --clear
C) The value's text is short enough on every phone
D) Nothing yet: the web preview lets a Text shrink like CSS, while a phone's Yoga does not
Why: react-native-web gives Views React Native's defaults but renders a Text as an element that keeps the browser's flex-shrink: 1, so the preview can hide a row that would run off a phone's screen. The lesson measured the preview and hedges the phone ("should run past the card's edge"): give text in a row flex: 1 or flexShrink: 1 anyway, and look at rows on a phone.
A is wrong: It is exactly the bug the preview hides.
B is wrong: Nothing is cached: the preview is just more forgiving.
C is wrong: Meeting points are long, phones are narrow, and people turn up their text size.
Q6
In the header row, "Upcoming cleanups" gets flexShrink: 1, not flex: 1. Why?
A) flexShrink is the only flex property a Text accepts
B) With flex: 1 the heading would take all the free space, leaving space-between nothing to push the count with
C) flex: 1 would make the heading bold
D) flexShrink: 1 centers the heading vertically
Why: flexShrink: 1 keeps the heading's natural width (so space-between has free space to distribute) and lets it shrink and wrap only when both no longer fit, as with a very large text size. flex: 1 means "take the rest".
A is wrong: A Text accepts flex, flexGrow, flexShrink and flexBasis like a View.
C is wrong: flex has nothing to do with the font.
D is wrong: alignItems: 'center' on the row does that.

// Plain TypeScript: the same function would work in a web app
export function siteTags(site: Site): string[] {

  if (site.accessible) tags.push('Step-free access');

labs/module-04/checkpoint-1/solution/src/site.ts
import type { Site } from './types';

const terrains: readonly string[] = ['sand', 'rocky', 'mixed', 'marsh'];

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}

// A type guard: after `if (isSite(json))`, TypeScript treats the value as a Site
export function isSite(value: unknown): value is Site {
  return (
    isRecord(value) &&
    typeof value.id === 'string' &&
    typeof value.name === 'string' &&
    typeof value.town === 'string' &&
    typeof value.terrain === 'string' &&
    terrains.includes(value.terrain) &&
    typeof value.accessible === 'boolean' &&
    typeof value.parking === 'string'
  );
}

The Lesson Page's Own Quick Quiz

Lesson 2.2 · Flexbox the Native Way
  1. A Stacked from top to bottom, each as wide as the View: Every View is a flex container whose default flexDirection is column, and the default alignItems is stretch, so the three stack from top to bottom across the full width.
  2. D So it takes the space the label leaves and wraps inside it instead of running past the card: Nothing shrinks by default on a phone (flexShrink is 0), so a long Text in a row could run past the card. flex: 1 makes the value take exactly the space the 72-wide label leaves, and wrap inside it.
  3. B The card is a column and its children stretch across it by default: The card is a column with the default alignItems: stretch, so every child fills its width. In a row, or with alignSelf: flex-start, the badge keeps the width of its word.
  4. C The ScrollView grows to the height of all its rows, so it cannot scroll and the last rows are out of reach: A View without flex: 1 is as tall as its content, so the ScrollView grows to the height of all sixty rows and has nothing to scroll; the last rows stay below the screen. The course measured exactly this in the web preview.
  5. A justifyContent: 'space-between' and alignItems: 'center': In a row the main axis runs across, so justifyContent: space-between pushes the two to opposite ends, and alignItems: center centers them across the row, which is now up and down.

Exit Ticket

  1. Defaults: column (children stack top to bottom), flexShrink 0 (nothing shrinks: long text can run off), alignContent flex-start (wrapped lines stay at the start), flex is one number (a share of the free space; strings are a type error). Any two.
  2. The preview: react-native-web renders a Text that keeps CSS's flex-shrink 1, so it wraps there; on a phone Yoga's flexShrink 0 should keep its width and push it past the card (the lesson's hedge). flex: 1 makes both agree.
  3. Header row: justifyContent: 'space-between' and alignItems: 'center' on a row (the heading flexShrink: 1).

Common Wrong Answers and What They Reveal

  • Q1 B. Thinks of a badge as inline: the column's stretch is not yet a reflex. Show the badge-bar demo again.
  • Q3 A or D. Treats the type error as syntax, or the axes as fixed. Draw the two arrows.
  • Q5 A. Trusts the web preview as a phone: the habit the lesson's table builds.
  • Q8 or Q9 "tsc". Expects the type checker to know React Native's rules (Session 1's lesson): run the checkpoint starter's three commands side by side.
  • Q12 A. The web's cascade: Lesson 2.1's tide pools.
