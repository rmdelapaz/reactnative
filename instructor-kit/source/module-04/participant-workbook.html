2.2

Flexbox the Native Way

By the end you can
  • Explain how React Native's flexbox differs from CSS: every View is a flex column, flex is a single number, nothing shrinks by default, and there is no grid
  • Line things up along the main and cross axes with flexDirection, justifyContent, alignItems, alignSelf, flexWrap and gap
  • Size boxes with flex, fixed widths and percentages, and keep text inside a row from running off the screen
  • Build the common phone layouts: a header row, label and value side by side, a wrapping row of badges, a centered message, a bar pinned to the bottom
  • Make a screen fill the phone with flex: 1, and say where the web preview's layout can differ from a phone's
Key ideas
  • Every View is a flex container, laid out by Yoga on Android and iOS; the web preview uses the browser's flexbox through react-native-web. No block, inline or grid.
  • Four defaults differ from CSS: flexDirection: 'column', flexShrink: 0 (nothing shrinks), alignContent: 'flex-start', and flex is one number (strings are a type error).
  • Axes: justifyContent along the main axis, alignItems across it; switching to a row swaps what they do on the screen. Children stretch across by default: a badge in a column becomes a bar (alignSelf: 'flex-start' or a row fixes it).
  • Sizes: a number (exact), a percentage string (a share of the parent), flex: 1 (the rest), nothing (the content). Text in a row gets flex: 1 (fill the rest) or flexShrink: 1 (natural width, may shrink).
  • Filling the screen: the outermost View gets flex: 1, or the background stops and a ScrollView inside cannot scroll; Shoreline Crew's Screen component does it once.
  • Patterns: header row, label and value, wrapping chips, centered message, bottom bar, equal columns, corner overlay (position: 'absolute' only for overlays).
Worked example: flex is a number, and what tsc cannot see

A teammate writes the web's shorthand in Screen's style. Metro would bundle it; the type checker refuses it before anything runs:

npx tsc --noEmit
src/components/Screen.tsx:28:5 - error TS2322: Type 'string' is not assignable to type 'number'.

28     flex: '1 1 0%', // fill the space the navigator gives the screen, not just the content's height
       ~~~~

  node_modules/react-native/types_generated/Libraries/StyleSheet/StyleSheetTypes.d.ts:514:3
    514   flex?: number | undefined;
          ~~~~

Found 1 error in src/components/Screen.tsx:28

Read it the Lesson 2.1 way: where (Screen.tsx:28:5), what (TS2322: a string where a number belongs), the line with ~~~~ under flex, and the type it comes from (flex?: number). Skip the long The expected type comes from … dump. In React Native flex is ONE number, a share of the free space: flex: 1.

The mistakes the type checker cannot see are the dangerous ones. A badge straight in a card becomes a bar (the column stretches its children); a long value in a row without flex: 1 can run off a phone's screen, while the web preview lets the Text shrink like CSS and looks fine. Only your eyes (and a phone) catch those: that is why every Text that shares a row gets flex: 1 or flexShrink: 1.

Glossary

TermMeaning
YogaReact Native's flexbox engine on Android and iOS (the same on both)
main axis / cross axisThe direction children are placed in (down for a column, across for a row) / the other one
flex (React Native)One number: a share of the free space; flex: 1 = the rest
flexShrink: 0React Native's default: nothing gets smaller to fit
stretchalignItems' default: children fill the cross axis (a badge in a column becomes a bar)
alignSelfalignItems for one child, e.g. 'flex-start' to stop it stretching
flexWrap: 'wrap'Children that do not fit continue on the next line
ScreenShoreline Crew's wrapper: page color, padding, gaps and flex: 1 (+ scroll)
type guardisX(value: unknown): value is X: checks at run time and narrows the type (Lesson 1.3)
