Lesson

2.4

Touch and Input

By the end you can
  • Make anything tappable with Pressable, explain its press lifecycle (press in, press out, press, long press), and show press feedback with a style function
  • Give every control a finger-sized touch target with minHeight and hitSlop, and a role, a label and a state for screen readers
  • Build a controlled TextInput with onChangeText, and choose the keyboard and its behavior with inputMode, enterKeyHint, autoCapitalize and autoCorrect
  • Put the keyboard away at the right moments, and keep taps working while it is open
  • Use Switch for an on/off choice and know which other controls React Native has built in
Key ideas
  • Pressable reports the whole touch: onPressIn, onPressOut, onPress (a complete tap), onLongPress (500 ms; a handled long press is not also a tap). Sliding off cancels. Feedback with a style function ({ pressed }) => [...], at the touch. onClick type-checks and never runs.
  • Targets: 48 for fingers (Apple 44 pt, Android 48 dp): minHeight, never height; hitSlop enlarges the touch area (the web preview ignores it).
  • Screen readers: accessibilityRole, accessibilityLabel (an icon-only button needs one), and state with aria-* names (aria-expanded, disabled).
  • TextInput: controlled with value + onChangeText (a string); no <label>: accessibilityLabel; a placeholder is not a label. inputMode, enterKeyHint, autoCapitalize, autoCorrect, autoComplete, secureTextEntry, onSubmitEditing. Numbers are still strings.
  • The keyboard: the return key ends a one-line field; keyboardDismissMode="on-drag"; Keyboard.dismiss(); keyboardShouldPersistTaps="handled" so the first tap reaches a button. Only a phone shows it.
  • Switch: value + onValueChange (onChange gets an event); colors are props. Other controls: ActivityIndicator and RefreshControl (3.1), Alert, modal routes (4.2); no built-in slider or date picker. Derived state: the filtered list is computed on every render.

Glossary

TermMeaning
PressableReact Native's one component for "this can be tapped"
onPressIn / onPressOut / onPress / onLongPressFinger down / up or slid off / a complete tap / held 500 ms
press feedbackA visible change at the touch: a style function ({ pressed }) => ...
touch targetThe area a finger can hit: 48 in Shoreline Crew
hitSlopExtra touch area around a control, outside what is drawn
accessibilityRole / accessibilityLabelWhat kind of control it is / what a screen reader calls it
aria-expandedOpen or closed, for screen readers (state, with the web's name)
onChangeTextTextInput's callback with the new text as a string
inputMode / enterKeyHintWhich keyboard / what the return key says
keyboardShouldPersistTapsWhether a tap while the keyboard is open reaches a button ('handled')
SwitchThe native on/off toggle: value + onValueChange
derived stateValues computed from state on every render instead of stored
