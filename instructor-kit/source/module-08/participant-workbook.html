3.1

FlatList and SectionList

By the end you can
  • Explain why a FlatList beats a ScrollView with map for lists, and what "drawing only what is near the screen" means
  • Build a typed FlatList: data, renderItem, a stable keyExtractor, a header, and columns with numColumns
  • Show the right thing when a list has no items: loading, a failed load with a retry button, or "nothing matches"
  • Add pull to refresh with refreshing and onRefresh, and know what each platform (and the web preview) does with it
  • Group items under headings with SectionList and sticky section headers
Key ideas
  • Virtualization: a ScrollView draws every child; a FlatList draws the rows near the screen (windowSize 21: about ten screens each way) and more as you scroll. A row thrown away is drawn again from its data.
  • FlatList's three must-haves: data, renderItem ({ item, index }, typed ListRenderItemInfo<Card>), keyExtractor (a STRING from the data's id; without it React Native quietly uses the index).
  • The list is the screen's scroll view: {...screen} from useScreenScroll(); never a list inside a vertical ScrollView. The header is an ELEMENT, not an inline component.
  • Columns: numColumns with key={columns} (a list cannot change its columns), columnWrapperStyle only with more than one column, cells as a share of the row.
  • Empty is several states: ListEmptyComponent shows loading, failed (Try again) or nothing matches; the header shows in every state. Pull to refresh = refreshing + onRefresh, false again on success and failure; the web preview has no gesture.
  • SectionList: sections of { title, data }, renderSectionHeader, stickySectionHeadersEnabled set explicitly (iOS-only by default) and a heading with a background; no columns.

3.2

Big Lists, Fast

By the end you can
  • Explain how FlashList's recycling differs from FlatList's virtualization, and measure both in the web preview
  • Move a FlatList to FlashList 2 and adapt what is different: spacing inside the cells, no padding on the list's own style, item types and column spans
  • Keep each item's state with the right item when its cell is recycled, with useRecyclingState
  • Load a list page by page from the API's X-Total-Pages with onEndReached, with loading, failed and end-of-list footers that never ask twice or loop
  • Show items under headings in one FlashList by flattening sections into rows with sticky header indices
Key ideas
  • Recycling: FlatList unmounts rows that leave its window and creates new ones; FlashList keeps them in pools by item type and draws them again with new data. JavaScript only in version 2 (Expo Go runs it); no estimatedItemSize any more.
  • Measure, don't guess: rows created, rows in the page and JS frames per second (FlashList's useBenchmark / useFlatListBenchmark), Chrome's CPU throttling for a cheaper phone; the web preview says nothing reliable about a phone's native side: real phones and release builds have the final word.
  • Moving to FlashList: spacing inside the cells (no content gap, no columnWrapperStyle), no padding on the list's own style (a View around it), no key={columns} needed.
  • Row state travels with a recycled row: useRecyclingState(initial, [id]), or keep it in the screen; never a key on the row inside renderItem.
  • Infinite scroll: page 1, then the next page from onEndReached only when idle; the API's X-Total-Pages to know when to stop; drop known ids; footers for loading more, failed (Try again) and the end.
  • Headings in one FlashList: flatten sections into heading and item rows, getItemType, stickyHeaderIndices, overrideItemLayout spans so headings cross columns.

And the three rules that make it shippable, in the finished screen's code:

shoreline-crew/src/app/index.tsx
  // The list is near its end. Only ask when nothing is on its way and the last page did not fail:
  // after a failure, the Try again button asks (or the list would ask again and again)
  function onEndReached() {
    if (more.status === 'idle') {
      loadNextPage();
    }
  }

Glossary

TermMeaning
FlatListReact Native's list: draws the rows near the screen (virtualization)
virtualizationDrawing only what is near the screen, more as you scroll, throwing away rows far behind
keyExtractorItem → key, a string from the data's identity (an id)
ListHeaderComponent / ListEmptyComponent / ListFooterComponentWhat scrolls above the items / shows when there are none / below them (an element or a component; undefined, not null)
numColumnsItems side by side in rows; FlatList needs key={columns} when it changes
pull to refreshrefreshing + onRefresh (RefreshControl behind them); no gesture in the web preview
SectionListItems under headings from sections; stickySectionHeadersEnabled
FlashListShopify's list (@shopify/flash-list 2.3.2): recycles rows instead of throwing them away
recyclingA row that leaves the screen is reused for a row coming in, with new data
getItemTypeSeparate pools of spare rows per kind (heading, card)
useRecyclingStateuseState that resets when its dependencies change (a recycled row's new item)
infinite scrollThe next page loads when the list nears its end (onEndReached)
X-Total-PagesThe API's header: how many pages there are
stickyHeaderIndicesThe positions of the headings FlashList pins at the top
