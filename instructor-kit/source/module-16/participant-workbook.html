6.4

Notifications

By the end you can
  • Tell local notifications from push notifications and choose between them: what each needs, what each can do, and why Shoreline Crew's reminders are local
  • Put notifications through Lesson 6.1's permission step with a Hook made by createPermissionHook, including Android's channels and the iPhone's question
  • Schedule, replace and cancel reminders with expo-notifications, and keep them in step with the server's sign-ups in one function that is safe to run at any time
  • Open the right screen from a tap on a notification, whether the app was running or not, and treat the notification's data as outside input
  • Say what server push would need (a development build, an EAS project, credentials, push tokens and a server), and what Expo Go and the web preview can and cannot show
Key ideas
  • Local or push: a local notification is scheduled by the app and shown by the phone's own scheduler, with no server and no signal; a push is sent by a server through Apple's or Google's push service. Known in advance (a reminder): local. Known only to a server, when it happens (a cancellation): push.
  • Asking: iPhone once; Android 13 and later asks (once more after a first no), and only once the app has a channel; the web preview uses the browser's question. createPermissionHook makes the missing Hook; Lesson 6.1's gate does the rest. The moment is the switch, never the launch.
  • A reminder: content (title, body, data), a trigger with a type (DATE, TIME_INTERVAL, DAILY, WEEKLY), an identifier. The same identifier again replaces the reminder.
  • Reminders that stay true: one function, updateReminders, reads the truth (session, switch, permission, confirmed sign-ups) and makes the phone match: cancel its own unwanted, schedule the wanted. Safe to run any time, so the app runs it often.
  • A tap: a listener while the app runs; getLastNotificationResponse() once when the tap started it. The data is outside input: a type guard, and only ever open a screen.
  • Push would need a development build, an EAS project, FCM and APNs credentials (APNs is paid), a push token per device, a server that stores tokens, and a sender that reads receipts. The course describes it and does not ship it.

6.5

Haptics, Sharing and Files

By the end you can
  • Choose the right haptic for a moment with expo-haptics (or none at all), and say why a buzz is never the only feedback
  • Respect the people holding the phone: an in-app switch for vibration, and the phone's own settings, on iPhone and Android
  • Write a file with expo-file-system's File and Directory, in the right folder, without breaking the web preview
  • Turn app data into a CSV file a spreadsheet opens correctly, with quoting, a byte order mark and a guard against formulas
  • Hand a file to the share sheet with expo-sharing, and explain how that differs from Lesson 4.4's text sharing on each platform
Key ideas
  • Three kinds of haptic: notificationAsync (the result of something: Success, Warning, Error), impactAsync (something touched something), selectionAsync (a value changed under a finger); on Android, performAndroidHapticsAsync plays the system's own effects (Confirm, Reject).
  • Five rules: outcomes, not presses; the same meaning every time; never the only feedback (words on screen, read by screen readers); less is more (two moments in the whole app); optional (a switch).
  • Two layers of off: the app's switch (yours, on every platform) and the phone's settings (iPhone System Haptics; Android vibration and haptics), which have the last word.
  • Writing a file: new File(...) is only an address; create(), write(), text(). Files made to be shared go in the cache. On the web there are no files: create File, Directory and Paths inside functions, never at the top of a module, and check the platform first.
  • A CSV a spreadsheet trusts: text quoted, inner quotes doubled, numbers bare, a byte order mark first, \r\n, and a ' before text that starts like a formula.
  • The share sheet: React Native's Share for words and links (Lesson 4.4); expo-sharing's shareAsync for ONE local file, with a mimeType (Android) and a UTI (iPhone). It resolves when the sheet closes, never says whether anything was shared.

Glossary

TermMeaning
local notificationScheduled by the app on the phone; the phone's scheduler shows it, with no server and no signal
push notificationSent by a server through Apple's (APNs) or Google's (FCM) push service, to a token per device
notification channelAndroid's category for notifications ("Cleanup reminders"), which the person can tune in Settings
triggerWhen a scheduled notification fires: { type: DATE, date }, TIME_INTERVAL, DAILY, WEEKLY
notification handlersetNotificationHandler: how a notification that arrives while the app is open is shown
notification responseA notification plus what the person did with it (a tap); its content.data rides along
entitlement (aps-environment)An iPhone app's declared capability to receive pushes; enableRemoteNotifications: false leaves it out
idempotent syncOne function that makes the phone match the truth; running it again changes nothing
hapticsShort, precise taps from the phone's motor; expo-haptics plays them
share sheetThe phone's panel of apps and actions a file or text can be handed to
MIME type / UTIA file's type for Android (text/csv) and for an iPhone (public.comma-separated-values-text)
CSVComma-separated values: plain text that every spreadsheet opens
byte order mark (BOM)The invisible character U+FEFF at the start of a file that tells spreadsheets the text is UTF-8
CSV injectionA cell that starts with = + - or @ run as a formula; guarded with a leading '
cache directoryThe app's folder for files the phone may throw away (Paths.cache)
