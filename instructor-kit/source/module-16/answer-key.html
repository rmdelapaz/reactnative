6.4 · Notifications: self-check

Q1
At 7 am on a Saturday, an organizer cancels Weekend Cove Cleanup because of a storm warning. Can a local reminder tell the volunteers?
A) Yes: updateReminders cancels the reminder and the phone shows a cancellation
B) No: only the server knows, and when; that is a push notification, which needs a development build, an EAS project, credentials, push tokens and a server
C) Yes, if the app was opened that morning
D) No: local notifications cannot carry text
Why: A local reminder is the tide table on the dashboard: written ahead, from what the phone knew. News that only a server knows, at the moment it happens, is the harbor radio: push. Lesson 6.4's table lists what it would take; shoreline-api has none of it, and the course does not build it.
A is wrong: Cancelling a reminder makes the phone show NOTHING; it cannot announce anything by itself.
C is wrong: Opening the app would quietly cancel the reminder (the sign-up is gone); still no message unless the screen shows one.
D is wrong: Local notifications carry a title, a body and data, as the lesson's code shows.

Q5
A tap on a reminder reaches the app in two ways. Name both, say when each applies, and say what the app does with the notification's data before it opens anything.
App running (foreground or background): addNotificationResponseReceivedListener hears the tap. 6.5 · Haptics, Sharing and Files: self-check

Q7
Where does the sign-up's buzz go?
A) In onPress, before signUp.mutate(...), so it feels instant
B) In a useEffect that watches the button's pressed state
C) In the callbacks of this mutate call: onSuccess: () => feel('success'), onError: () => feel('error')
D) In the queue's sender, when the sign-up reaches the server
Why: Buzz for outcomes, not presses: the button's pressed look answers the press. Offline, the sign-up waits (Lesson 5.2); a buzz on the press would say "done" before anything is done, and lie if the API refuses. Callbacks passed to mutate run only while the panel is on screen, which is what a buzz needs.
A is wrong: The lesson's last Common Mistake: no tool catches it; it is a design error.
B is wrong: Still the press, not the result.
D is wrong: Sign-ups are not queued (Lesson 5.5), and a background send never buzzes: the volunteer may be driving.

// columns, cell and logbookCsv from src/storage/logbookExport.ts, run in Node with three logbook rows
type LogbookEntry = {
  eventTitle: string;
  eventDate: string;
  pieces: number;
  bags: number;
  weightKg: number;
  note: string;
};

const columns = ['Cleanup', 'Date', 'Pieces', 'Bags', 'Weight (kg)', 'Note'];

// One cell. Numbers as they are; text in quotes with every quote doubled, so a comma, a quote or a
// line break in a note stays inside its cell. Text that starts like a formula (= + - @) gets a '
// in front: a spreadsheet would otherwise run it as one.
function cell(value: string | number): string {
  if (typeof value === 'number') {
    return String(value);
  }
  const text = /^[=+\-@\t\r]/.test(value) ? `'${value}` : value;
  return `"${text.replaceAll('"', '""')}"`;
}

/** The logbook as CSV text: a row of column names, then one row per log */
export function logbookCsv(entries: LogbookEntry[]): string {
  const rows = entries.map((entry) => [
    entry.eventTitle,
    entry.eventDate,
    entry.pieces,
    entry.bags,
    entry.weightKg,
    entry.note,
  ]);
  const lines = [columns, ...rows].map((row) => row.map(cell).join(','));
  // A byte order mark (\uFEFF) first tells spreadsheet apps the text is UTF-8: without it,
  // "Café" may open as "CafÃ©"
  return `\uFEFF${lines.join('\r\n')}\r\n`;
}
