Lesson

2.3

Images, Icons, Fonts and Safe Areas

By the end you can
  • Show local and remote pictures with expo-image, give a picture from a server a size with aspectRatio, choose a contentFit, and describe it for screen readers
  • Use expo-symbols for icons that are SF Symbols on an iPhone and Material Symbols on Android and the web, with type-checked names
  • Load a custom font with useFonts while the splash screen waits, and pick font weights by family name
  • Explain safe areas and insets, and keep content clear of the status bar, the notch and the home indicator with react-native-safe-area-context
  • Replace the template's app icon, adaptive icon layers, splash screen and favicon, and say which ones you can see in Expo Go and which only in a build
Key ideas
  • expo-image (source, style, contentFit = object-fit, transition, accessibilityLabel = alt, disk cache by default) replaces React Native's Image. Every picture needs a size: a width and height, or the parent's width plus an aspectRatio; without one it is invisible, with no error. Local files are require()d with a plain string path.
  • Describe pictures with accessibilityLabel (and accessible): in the web preview, alt alone gave no alt. Shoreline Crew's site pictures come from the API with their alt text, width and height.
  • expo-symbols: SF Symbols on iOS, Material Symbols on Android and the web. Give all three names ({ ios, android, web }): a plain SF name type-checks and draws nothing on Android and the web. Both name sets are type-checked (a typo is TS2820 with Did you mean). Icons are named by job in one table; decorative icons are hidden from screen readers.
  • Fonts: the system font for body text; Outfit for headings, loaded with useFonts (per-weight imports) while the splash screen waits (preventAutoHideAsync / hideAsync); carry on with the system font if loading fails. One family per weight: never fontWeight with a custom font. Typed family names make a typo loud.
  • Safe areas: the status bar, the camera cutout, rounded corners and the home indicator cover the edges; the insets say by how much. useSafeAreaInsets() (or the library's SafeAreaView edges, never React Native's); a screen adds only the edges nothing else covers; scrolling: top on the frame, bottom inside the content; a pinned bar pads itself. The web preview's insets are 0.
  • App icon, adaptive icon, splash screen, favicon live in app.json and assets/images/; name is what the phone shows, slug the project's id. Expo Go shows its own icon: yours comes with your own build (Module 9). npx expo-doctor checks app.json.

Glossary

TermMeaning
expo-imageExpo's picture component: source, a size, contentFit, transition, a disk cache
aspectRatioWidth divided by height: with a width from the parent it gives a height before the picture arrives
contentFitHow a picture fills its box: 'cover' (default), 'contain', 'fill', 'none', 'scale-down' (CSS object-fit)
accessibilityLabelWhat a screen reader says; the web preview's alt
SF Symbols / Material SymbolsApple's and Google's icon sets; expo-symbols draws the right one per platform
useFontsexpo-font's hook: registers font files, returns [loaded, error]
splash screenThe picture shown while an app starts; kept up with preventAutoHideAsync() until the fonts are ready
safe areaThe part of the screen nothing covers
insetThe distance from an edge of the screen to the safe area (useSafeAreaInsets())
status bar / home indicatorThe clock and battery at the top / the gesture bar at the bottom, drawn on top of the app
adaptive iconAndroid's two-layer icon, cut into the phone's own shape
npx expo-doctorChecks the project's configuration (app.json, versions)
