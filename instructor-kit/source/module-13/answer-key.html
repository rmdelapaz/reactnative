5.3 · Storing Data on the Device: self-check

Q1
Shoreline Crew wants to remember that a volunteer has already seen the "Before you go" briefing, so it is not shown again. Where should that live?
A) SecureStore: everything on the phone should be encrypted
B) AsyncStorage: a small flag, not secret, one key
C) SQLite: a table with one row
D) Only the query cache
Why: A small, non-secret setting is AsyncStorage's job (Lesson 5.3's table and Exercise 1 (b)). SecureStore is for secrets and warns about size; SQLite is for many records you search, sort or total; the query cache is gone after a force-quit.
A is wrong: SecureStore is for tokens and keys; a "seen it" flag is not secret.
C is wrong: A database for one flag is the sticky note in a ledger: it works, it is the wrong tool.
D is wrong: Memory does not survive a force-quit, so the briefing would come back every launch.
Q2
The logbook's own INSERT OR REPLACE runs twice with Theo's one sent log ("Bring in my sent logs" pressed twice). The kit then ran the totals query. What does it print?
INSERT OR REPLACE INTO sent_logs (...) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)   -- the same log, twice
SELECT COUNT(*) AS logs, ... FROM sent_logs WHERE volunteer_id = ?
A) { logs: 2, pieces: 84, bags: 2, weightKg: 5 }
B) An error: the row already exists
C) { logs: 1, pieces: 42, bags: 1, weightKg: 2.5 }
D) { logs: 0, pieces: 0, bags: 0, weightKg: 0 }
Why: The primary key is (volunteer_id, client_id), the same pair shoreline-api uses to recognize a log it already has, so the second insert REPLACES the row instead of adding one. The kit ran the stage's SQL on SQLite (built into Node 24) with Theo's real log from the API: the numbers are the lesson's "1 log in all: 42 pieces, 1 bag, 2.5 kg."
A is wrong: That is what a table without a primary key (or a JSON array) would give.
B is wrong: A plain INSERT would fail on the key; OR REPLACE is there so it does not.
D is wrong: Replacing keeps the row: nothing is deleted.
Q3
A note is put straight into the SQL text. What does SQLite answer?
db.exec(`INSERT INTO sent_logs (note) VALUES ('Theo's bag split by the stairs')`);
A) Error: near "s": syntax error
B) It saves the note without the apostrophe
C) It saves the note as written
D) SQLITE_CONSTRAINT: NOT NULL
Why: The apostrophe in Theo's ends the SQL string early, and SQLite cannot read the rest. The kit ran it on SQLite in Node; the lesson measured the same near "s": syntax error inside expo-sqlite's own wording in the web preview. The fix is a ? placeholder: runAsync('... VALUES (?)', note). The unfriendly version of the same mistake is SQL injection.
B is wrong: SQLite never edits your text: it either reads it as SQL or fails.
C is wrong: Only a ? value is stored as written.
D is wrong: SQLite never gets that far: the statement does not parse.
Q4
A query reads only the phone's database. Offline, its screen says "Opening your logbook…" until the connection returns. What fixes it?
A) retry: false
B) staleTime: 0
C) A useEffect instead of useQuery
D) networkMode: 'always' on that query
Why: Since Lesson 5.2 the cache knows when the phone is offline, and the default network mode pauses any query that would fetch. A queryFn that reads only the phone never needs the network. Checkpoint 2's Task 3b is this mistake on new code; the lesson measured the stuck screen.
A is wrong: Nothing failed: the query never ran.
B is wrong: That makes it refetch more often, still paused offline.
C is wrong: It would work, but throws away the cache's loading, error and invalidation for nothing.
Q5
Version 2 of an app adds a column to its table by changing CREATE TABLE IF NOT EXISTS. What happens on a phone that already has version 1's database?
A) The table is rebuilt with the new column
B) The table exists, so the statement is skipped, and the first query that names the new column fails
C) SQLite adds the column by itself
D) The app deletes the old file and starts over
Why: IF NOT EXISTS answers "is there a table?", not "which version is it?". Lab 5.3 Task 3 shows the failure on a real version 1 file. A version number (PRAGMA user_version) and one step per version, in a transaction, bring old files up to date; never delete a user's data and never edit a shipped step.
A is wrong: Nothing rebuilds a table that exists.
C is wrong: SQLite only does what the SQL says.
D is wrong: Deleting a user's database is the thing the expo-sqlite documentation says never to do.
Q6
Why is the signed-in part of the Logbook screen its own component, MyLogbook, instead of more code at the top of the screen?
A mutation's result lives as long as the component that called useMutation, and a tab screen never unmounts; signing out unmounts MyLogbook, so the next person on the phone starts fresh
Why: Lesson 5.3 measured the draft: Theo brought in his logs, signed out, Amara signed in, and her empty logbook still said "Done: the server has 1 log of yours…". The query key's viewer keeps the DATA apart; only unmounting resets the mutation's state.

// Task 3: the volunteer's favorite beaches, kept on the phone with AsyncStorage (one key, a JSON list)
import AsyncStorage from '@react-native-async-storage/async-storage';

import type { SiteSummary } from './api';

export type Favorite = Pick<SiteSummary, 'id' | 'name'>;

export const favoritesKey = 'crew-favorites';

function isFavorite(value: unknown): value is Favorite {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'string' &&
    'name' in value &&
    typeof value.name === 'string'
  );
}

/** The saved favorites, checked: anything this version cannot read means no favorites. It never rejects. */
export async function readFavorites(): Promise<Favorite[]> {
  try {
    const saved = await AsyncStorage.getItem(favoritesKey);
    const value: unknown = saved === null ? [] : JSON.parse(saved);
    return Array.isArray(value) ? value.filter(isFavorite) : [];
  } catch (error) {
    console.warn('Could not read the saved favorites', error);
    return [];
  }
}
labs/module-13/checkpoint-2/solution/src/queries.ts
import { queryOptions } from '@tanstack/react-query';

import { getSite, getSites } from './api';
import { readFavorites } from './favorites';

/** Every site, for the list (given) */
export function sitesQuery() {
  return queryOptions({
    queryKey: ['sites'],
    queryFn: ({ signal }) => getSites(signal),
  });
}

/** One site: its own key, so each site is cached on its own (given) */
export function siteQuery(id: string) {
  return queryOptions({
    queryKey: ['site', id],
    queryFn: ({ signal }) => getSite(id, signal),
  });
}

/** The favorites saved on this phone: read from storage, not the network */
export function favoritesQuery() {
  return queryOptions({
    queryKey: ['favorites'],
    queryFn: readFavorites,
    // The answer is on the phone: no reason to wait for a connection ('online' would pause it)
    networkMode: 'always',
    // Only this app changes it (and would invalidate it): never stale by itself
    staleTime: Infinity,
  });
}

// Task 1: the crew leader's preferences, kept on the phone with AsyncStorage: one key, one small JSON object.
import AsyncStorage from '@react-native-async-storage/async-storage';

export type WeightUnit = 'kg' | 'lb';

export type Prefs = {
  unit: WeightUnit;
  tipsSeen: boolean;
};

export const prefsKey = 'crew-lab-prefs';
export const defaultPrefs: Prefs = { unit: 'kg', tipsSeen: false };

const units: WeightUnit[] = ['kg', 'lb'];

// What was saved is checked like API data: anything this version does not know becomes the default
function fromSaved(saved: string | null): Prefs {
  const value: unknown = saved === null ? null : JSON.parse(saved);
  if (typeof value !== 'object' || value === null) {
    return defaultPrefs;
  }
  const unit = 'unit' in value ? units.find((known) => known === value.unit) : undefined;
  const tipsSeen = 'tipsSeen' in value && typeof value.tipsSeen === 'boolean' ? value.tipsSeen : undefined;
  return { unit: unit ?? defaultPrefs.unit, tipsSeen: tipsSeen ?? defaultPrefs.tipsSeen };
}

/** The saved preferences, checked. It never rejects: a broken save gives the defaults and a warning. */
export async function loadPrefs(): Promise<Prefs> {
  try {
    return fromSaved(await AsyncStorage.getItem(prefsKey));
  } catch (error) {
    console.warn('Could not read the saved preferences', error);
    return defaultPrefs;
  }
}

/** Change some preferences: merged with what is saved, saved again, and returned */
export async function changePrefs(changes: Partial<Prefs>): Promise<Prefs> {
  const next = { ...(await loadPrefs()), ...changes };
  await AsyncStorage.setItem(prefsKey, JSON.stringify(next));
  return next;
}

// Tasks 2 and 3: the crew leader's notes about each beach, in a SQLite database on the phone. SQLite, not
// AsyncStorage: many records with the same fields, read one site at a time, newest first.
import * as SQLite from 'expo-sqlite';

export type Tide = 'low' | 'high' | 'unknown';

export type SiteNote = {
  siteId: string;
  text: string;
  tide: Tide;
  writtenAt: number; // milliseconds, as Date.now() gives them
};

// The version of the tables below. Version 2 added the tide column.
const schemaVersion = 2;

let opening: Promise<SQLite.SQLiteDatabase> | null = null;

// One connection for the whole app, opened and brought up to date the first time it is needed
function database(): Promise<SQLite.SQLiteDatabase> {
  opening ??= openNotes().catch((error: unknown) => {
    opening = null; // try again next time instead of keeping the failure
    throw error;
  });
  return opening;
}

async function openNotes() {
  const db = await SQLite.openDatabaseAsync('notes.db');
  await migrate(db);
  return db;
}

/** Close the connection; the next call opens the file again (the tests use it: a new phone for every test) */
export async function closeNotes(): Promise<void> {
  const db = await opening;
  opening = null;
  await db?.closeAsync();
}

// SQLite keeps a number in every database file, user_version (0 in a new one). Each step brings an older file
// one version further; all of them and the new number succeed or fail together.
async function migrate(db: SQLite.SQLiteDatabase) {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  const version = row?.user_version ?? 0;
  if (version >= schemaVersion) {
    return;
  }
  await db.withTransactionAsync(async () => {
    if (version < 1) {
      await db.execAsync(`
        CREATE TABLE site_notes (
          site_id TEXT NOT NULL,
          text TEXT NOT NULL,
          written_at INTEGER NOT NULL
        );
      `);
    }
    if (version < 2) {
      // The tide when the note was written. Notes from version 1 get 'unknown' (NOT NULL needs a default).
      await db.execAsync("ALTER TABLE site_notes ADD COLUMN tide TEXT NOT NULL DEFAULT 'unknown'");
    }
    // A PRAGMA takes no ? values; schemaVersion is our own number, never user input
    await db.execAsync(`PRAGMA user_version = ${schemaVersion}`);
  });
}

/** Save one note. Every ? is filled in by SQLite with the value in the same place: never build SQL from data. */
export async function addNote(note: SiteNote): Promise<void> {
  const db = await database();
  await db.runAsync(
    'INSERT INTO site_notes (site_id, text, tide, written_at) VALUES (?, ?, ?, ?)',
    note.siteId,
    note.text,
    note.tide,
    note.writtenAt,
  );
}

/** One site's notes, the newest first */
export async function notesFor(siteId: string): Promise<SiteNote[]> {
  const db = await database();
  return db.getAllAsync<SiteNote>(
    `SELECT site_id AS siteId, text, tide, written_at AS writtenAt
       FROM site_notes
      WHERE site_id = ?
      ORDER BY written_at DESC`,
    siteId,
  );
}

import type { ComponentProps } from 'react';
import { type Control, type FieldPath, type FieldValues, useController } from 'react-hook-form';
import { StyleSheet, Text, TextInput, View } from 'react-native';

// TextInput's props, minus the ones React Hook Form provides. T is what the fields hold; Out is what the form
// gives back after the schema's checks (numbers instead of text).
type ControlledInputProps<T extends FieldValues, Out> = Omit<
  ComponentProps<typeof TextInput>,
  'value' | 'onChangeText' | 'onBlur' | 'ref'
> & {
  control: Control<T, unknown, Out>;
  name: FieldPath<T>;
  label: string;
};

// A labeled text field that belongs to a React Hook Form form. A phone has no HTML input for register() to
// find, so useController hands over the value, the change and blur handlers, the field's message and a ref:
// with it, setFocus('volunteers') and "focus the first field with a problem" work.
export function ControlledInput<T extends FieldValues, Out = T>({
  control,
  name,
  label,
  ...input
}: ControlledInputProps<T, Out>) {
  // Taken apart at once: the lint rules treat an object with a ref inside as a ref
  const {
    field: { ref, value, onChange, onBlur },
    fieldState: { error },
  } = useController({ control, name });
  return (
    <View style={styles.field}>
      <Text style={styles.label}>{label}</Text>
      <TextInput
        {...input}
        ref={ref}
        accessibilityLabel={label}
        value={value}
        onChangeText={onChange}
        onBlur={onBlur}
        style={styles.input}
      />
      {error?.message !== undefined && <Text style={styles.error}>{error.message}</Text>}
    </View>
  );
}

const styles = StyleSheet.create({
  field: { gap: 4 },
  label: { fontWeight: '600', color: '#2a1257' },
  input: { minHeight: 48, paddingHorizontal: 12, borderWidth: 1, borderRadius: 8, borderColor: '#6b5a8e', fontSize: 16 },
  error: { color: '#b3261e' },
});

// The shift report a crew leader sends at the end of a cleanup: the form's type AND its checks (Zod 4)
import { z } from 'zod';

// A count typed into a box: digits only, so an empty box is a message, not a silent 0 (the HQ's wholeNumber)
function wholeNumber(min: number, max: number, message: string) {
  return z
    .string()
    .trim()
    .regex(/^\d+$/, message)
    .transform(Number)
    .refine((count) => count >= min && count <= max, message);
}

const hoursRule = 'Hours must be a number from 0 to 12.';

export const shiftReportSchema = z.object({
  leader: z.string().trim().min(1, "Enter the crew leader's name."),
  volunteers: wholeNumber(1, 200, 'Volunteers must be a whole number from 1 to 200.'),
  hours: z
    .string()
    .trim()
    // Many phones set to other languages offer a comma as the decimal key: 2,5 means 2.5
    .transform((typed) => typed.replace(',', '.'))
    .pipe(z.string().regex(/^\d+(\.\d+)?$/, hoursRule))
    .transform(Number)
    .refine((hours) => hours <= 12, hoursRule),
});

/** What the fields hold: text, as typed */
export type ShiftReportValues = z.input<typeof shiftReportSchema>;

/** What a successful check gives back: numbers, ready to send */
export type ShiftReport = z.output<typeof shiftReportSchema>;

The Lesson Pages' Own Quick Quizzes

Lesson 5.3 · Storing Data on the Device
  1. C SecureStore: Tokens are secrets. SecureStore keeps them in the iOS Keychain or encrypted with the Android Keystore; AsyncStorage and SQLite files are not encrypted.
  2. A So the first screen is drawn in the chosen theme, with no light flash: Reading AsyncStorage is async. If the app drew first, a volunteer who chose Dark would see a light screen until the setting arrived. Waiting behind the splash screen means the first screen is already in the right colors.
  3. D His logs and totals, read from the database on the phone: The logbook query reads SQLite on the phone with networkMode always, so TanStack Query does not pause it offline. The rows saved earlier are there; only bringing in new logs waits for a connection.
  4. B See user_version 1 and run only the step that adds the column, then set version 2: PRAGMA user_version says the file is at version 1, so migrate runs only the new step, an ALTER TABLE that adds the column, and sets version 2 in the same transaction. The rows stay.
  5. C db.runAsync('INSERT INTO notes (note) VALUES (?)', note): The question mark is a placeholder: SQLite receives the note as a value, never as SQL, so apostrophes and anything else in it are stored as written.
Lesson 5.4 · Mobile Forms
  1. B It type-checks, but the form never gets what the volunteer types: register is built around HTML inputs: it reads the value from the change event's target and the element itself. A TextInput reports its text differently, so the form never gets it. useController or Controller hands the field value, onChange, onBlur and a ref instead.
  2. D The iOS decimal pad has no return key at all: According to React Native's documentation, the iOS decimal pad and number pad have no return key, so there is nothing to press. Volunteers tap the next field or drag the form to close the keyboard, which is one reason the counts use steppers.
  3. A Pass the header's height as keyboardVerticalOffset: KeyboardAvoidingView measures the keyboard from the top of the window, but the screen starts under the header. keyboardVerticalOffset with the header height (useHeaderHeight) makes the padding come out right.
  4. C Answers 200 with the log it already has, because the clientId is the same: The form made the clientId once, so both requests carry the same one. shoreline-api finds the log it already saved for that volunteer and clientId and answers 200 with it: a resend, never a duplicate.
  5. B "Sign in to log what you collected", with a Sign in button; after signing in she stays on the log screen: log/[id] is not guarded: it has a guest face. Amara signs in on top of it; the sign-in closes and the screen underneath now knows who she is (and, since she has no spot at that cleanup, it says so in the API's words).

Exit Ticket

  1. Three places: the theme choice in AsyncStorage (small, not secret, read once at startup), the session token in SecureStore (a secret: the Keychain or the Android Keystore), the logbook in SQLite (many records the screen sorts and totals; a copy of what the server has).
  2. networkMode 'always': the logbook's queryFn reads only the phone. With the default mode, TanStack Query pauses it offline ("Opening your logbook…" for ever, measured in the lesson); the logbook must open with no signal.
  3. const send: handleSubmit(fn) returns a function typed for a web form event; React Native's press and return-key events are other types, so tsc rejects passing it straight in (TS2322). Made once and called with no arguments, it type-checks and both the button and the Go key use it.

Common Wrong Answers and What They Reveal

  • Q1 A. "Everything on the phone should be encrypted": SecureStore is for secrets and is small. Back to the van: clipboard, lockbox, ledger.
  • Q2 A. Pictures the logbook as a list that only grows: the primary key is the API's own idempotency. Show P1's run.
  • Q4 A or B. Thinks the query failed. It never ran: paused. Show the lesson's networkMode card.
  • Q5 A. Believes IF NOT EXISTS rebuilds tables. Lab 5.3 Task 3's failing test shows the old file.
  • Q7 A or B. Trusts the checkers with behavior: register is the session's quietest mistake.
  • Q11 A. Has not met idempotency: one clientId, one log, however often it is sent.
