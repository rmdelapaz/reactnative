5.3

Storing Data on the Device

By the end you can
  • Choose between AsyncStorage, SecureStore and SQLite for a piece of data, and say what survives a restart, an update and an uninstall
  • Save a small setting with AsyncStorage, check it when you read it back, and apply it before the first screen appears
  • Create a SQLite table, write rows with ? values, and ask questions across them (newest first, totals)
  • Give a database a version number and a migration, so a later version of the app can change its tables safely
  • Read data from the phone through the TanStack Query cache, without waiting for a network it does not need
  • Set up the web preview for SQLite and know where it differs from a phone
Key ideas
  • Three places: AsyncStorage (text under a key, not protected: settings, flags), SecureStore (short secrets: tokens), SQLite (tables of rows you search, sort, total). All three are asynchronous.
  • The phone keeps copies, the server keeps the truth. Storage survives a force-quit and an update; uninstalls and new phones are another story (the platforms' documentation).
  • Read saved data like API data: keep only values this version knows, fall back to defaults, never reject. Load what the first frame needs behind the splash screen. Never a token or a password in AsyncStorage.
  • Four statements: CREATE TABLE (with a PRIMARY KEY), INSERT OR REPLACE, SELECT … WHERE … ORDER BY, COUNT/SUM/COALESCE. Every value goes in a ?; only your own fixed text goes in the SQL.
  • Migrations from day one: PRAGMA user_version, one step per version, in a transaction; never delete a user's database, never edit a shipped step.
  • Phone data in the cache: networkMode: 'always' (never paused offline), staleTime: Infinity + invalidate after every write. The web preview needs wasm in Metro's asset types and one tab at a time.

The logbook's own SQL (src/storage/logbook.ts) on SQLite, with that log inserted twice; then the totals and the entries:

{ logs: 1, pieces: 42, bags: 1, weightKg: 2.5 }
[ 'Sunset Stairs Cleanup: Lots of wrappers by the stairs.' ]

One row: the primary key (volunteer_id, client_id) is the API's own way to recognize a log. And the same run with a note built into the SQL text instead of a ? value:

Error: near "s": syntax error

The table is made by a migration with a version number, so a later version of the app can change it on every phone:

shoreline-crew/src/storage/logbook.ts
async function migrate(db: SQLite.SQLiteDatabase) {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  const version = row?.user_version ?? 0;
  if (version >= schemaVersion) {
    return;
  }
  // All or nothing: if a step fails, the file keeps its old tables and its old number
  await db.withTransactionAsync(async () => {
    if (version < 1) {
      await db.execAsync(`
        CREATE TABLE sent_logs (
          volunteer_id TEXT NOT NULL,
          client_id TEXT NOT NULL,
          event_id TEXT NOT NULL,
          event_title TEXT NOT NULL,
          event_date TEXT NOT NULL,
          pieces INTEGER NOT NULL,
          bags INTEGER NOT NULL,
          weight_kg REAL NOT NULL,
          note TEXT NOT NULL,
          recorded_at TEXT NOT NULL,
          PRIMARY KEY (volunteer_id, client_id)
        );
      `);
    }
    // A PRAGMA takes no ? values; schemaVersion is our own number, never user input
    await db.execAsync(`PRAGMA user_version = ${schemaVersion}`);
  });
}

5.4

Mobile Forms

By the end you can
  • Connect React Hook Form to React Native text fields with useController and Controller, and explain why register is a web tool
  • Pick the keyboard for each field (inputMode, autoComplete, secureTextEntry) and know which keys a phone's number pads leave out
  • Build a return-key focus chain with enterKeyHint, submitBehavior, onSubmitEditing and setFocus
  • Keep every field visible above the keyboard with KeyboardAvoidingView, and say what differs on Android and iOS
  • Replace a keyboard with a stepper where a thumb does better, accessibly
  • Validate a debris log with Zod on the phone and send it to the API with a device clientId, in a shape Lesson 5.5 can queue
Key ideas
  • useController, never register: the form hands each field its value, onChange (→ onChangeText), onBlur, ref (focus) and error. Lesson 5.4's ControlledField wraps it; take field apart where you get it (the linter's react-hooks/refs).
  • const send = handleSubmit(submit) and () => send() for the button and the last field: handleSubmit's function wants a web event (TS2322 otherwise).
  • A keyboard per field: inputMode email / numeric / decimal, autoComplete, autoCapitalize="none", secureTextEntry, multiline + maxLength. Decimal keys may type a comma; the iPhone's number pads have no return key (the documentation).
  • Next, Next, Go: enterKeyHint, submitBehavior="submit", onSubmitEditing={() => setFocus('next')}; the last field submits; the ref also focuses the first problem.
  • Out of the keyboard's way: FormScreen = KeyboardAvoidingView (behavior="padding" on both, the header's height as keyboardVerticalOffset) around a ScrollView. A stepper beats a keyboard for small counts.
  • One id per log, made on the phone: expo-crypto's randomUUID() once when the form opens; a resend answers 200 with the saved log, never a duplicate. The schema uses the API's messages.
Worked example: the debris log's schema, and a form for one thumb

The stage's debrisLogSchema, run with Node: a log with lots in Glass and no weight, then a good one with the weight typed 2,5:

node demo/run.mts
counts.glass: Count must be a whole number from 0 to 100000.
weightKg: Weight must be a number of kilograms from 0 to 5000.
{"bags":1,"weightKg":2.5,"note":"By the stairs","items":[{"category":"plastic-bottles","count":12},{"category":"bottle-caps","count":4}]}

The messages are the API's own; the comma became a decimal point; only the kinds that were found became items. On the screen, every field connects through useController, and the return key walks the form:

shoreline-crew/src/app/sign-in.tsx
      <ControlledField
        control={control}
        name="email"
        label="Email"
        inputMode="email" // the keyboard with @ and .
        autoComplete="email"
        autoCapitalize="none"
        autoCorrect={false}
        enterKeyHint="next" // the return key says Next...
        submitBehavior="submit" // ...keeps the keyboard up...
        onSubmitEditing={() => setFocus('password')} // ...and moves to the password
      />

The submit function is made once and called with no event, by the button and by the last field's Go key:

shoreline-crew/src/app/sign-in.tsx
  // Check, then submit. Called with no arguments: React Hook Form's handleSubmit expects a web
  // form event, and a phone's press and return key send different events
  const send = handleSubmit(submit);

Glossary

TermMeaning
AsyncStorageKey-value text storage on the phone (the browser's localStorage in the web preview); asynchronous, not encrypted
SQLite / expo-sqliteA complete SQL database in one file on the phone; expo-sqlite is the JavaScript way in
table, row, columnA table holds rows that all have the same columns
primary keyWhat makes a row unique: (volunteer_id, client_id) in the logbook
? placeholderA value SQLite fills in separately: never read as SQL (prevents SQL injection)
migration / PRAGMA user_versionA numbered step that brings an older database file up to date
transactionSeveral statements that succeed or fail together
networkMode: 'always'A query or mutation that never waits for the network (for data on the phone)
WebAssembly (wasm)How the web preview runs SQLite in the browser; Metro must be told to bundle .wasm
useController / ControllerReact Hook Form's way to connect a field that is not an HTML input
enterKeyHint / submitBehaviorThe return key's label, and what the keyboard does when it is pressed
KeyboardAvoidingViewA View that adds room for the keyboard (behavior="padding", keyboardVerticalOffset)
stepper−, the number, +: a thumb control for small counts, with a box for big ones
clientIdAn id the phone makes once per log, so the API recognizes a resend
