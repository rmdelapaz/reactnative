# Instructor notes: Fix-It Tables (Alder Row Repair Café)

Keep this file and `solution/` until every hand-in is scored. Scoring guidance by row, the model's outputs and the
scoring sheet are in the kit's `final-assessment.html` (Part 1 section).

- **Sizing.** The kickoff (50 minutes in Session 8) gets everyone through setup and TODO A, and most into TODO B. The rest is three to four hours at home before the Session 9 check-in, plus polish before the hand-in a week later. TODO D is Lesson 3.1's Cleanups screen with other names: learners who finished that lesson project have every pattern they need.
- **Why local data.** Part 1 ends before the app talks to a server over a phone's network (Module 5). Everything runs from `src/data/tickets.ts`: no API, no network, no account. Learners who know `fetch` already may not add it: the rubric scores what Part 1 teaches.
- **Where it lives.** In the learner's course folder, at `shoreline/labs/projects/part1-alder-row-repair-cafe/`: they work in `starter/` (or in a copy of it called `mine/` next to it: any folder three levels under `labs/` finds the labs' one shared install, so there is nothing to install). Never inside `shoreline-crew`. `npm run web` in it while Shoreline Crew's Metro runs: Expo offers the next port (answer yes).
- **No phone needed.** The tests (Jest with React Native's renderer), the type check, the linter and the web preview (`npm run web`, w) cover every row. A learner with Expo Go can scan the code and see it on a phone; the rubric's "strong" for row 5 asks for a look on a phone only if they have one.
- **The type tests (TODO A).** While `Category` or `TicketStatus` is still `string`, tsc reports `TS2578 Unused '@ts-expect-error' directive` in `src/types.check.ts`, and the data file reports the fields `Ticket` does not have yet (`number`, `fixer`). Explain it once in the kickoff: the type tests pass only when the types are exact, and nobody edits `types.check.ts`.
- **Most common problems, and the nudge.** `fixer` not optional (tsc on `tickets.ts`: "Property 'fixer' is missing"); the shown list or the count in `useState` (ask: can you work it out from the search and the switch?); the header as `() => (...)` (D2 fails: the field keeps only the first letter); `numColumns` without `key={columns}` (nothing fails at 390 wide; widen the web preview); `markFixed` editing the ticket in place (`ticket.status = 'fixed'`: React does not re-render, D4 fails); a grouped heading without a background (the cards show through it when it is pinned).
- **Scoring.** Run the four commands yourself on the hand-in (`npm test`, `npm run typecheck`, `npm run lint`, `npx expo export --platform web --output-dir dist`). Then a two-minute pass in the web preview at 390 and at 1024 wide, in light and dark mode (the browser's device toolbar and its rendering panel), with the search, both switches and one Mark fixed. Score each row from the evidence; write one sentence per row that is not "strong".
- **Pairs.** Allowed if both can explain every line in the demo; score each learner's row 6 separately.
- **Resubmission.** A row at 0 gets a written next step and one resubmission within two weeks. The Part 1 result is recorded when both the project and the assessment are met.
