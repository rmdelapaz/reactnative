8.3 · Mental model

The radio call, heard by the test

  • A screen reader's radio call: label, role, state
  • 'switch', { name: 'Group by date' }: "I heard a switch called Group by date"
  • toBeChecked(): "and it said on"
  • A garbled call (no role, no name) = a test that cannot find it either
WHY Listen to the radio, not the wiring: no testID, no style values.
8.3 · From the web course

Testing Library → RNTL 14

  • render(...) returns at once
  • user.click(), {Tab}
  • toBeInTheDocument()
  • Hidden elements found
  • A DOM to query
  • await render(...)
  • user.press(), type(), clear()
  • toBeOnTheScreen(): built in
  • Hidden elements skipped
  • View, Text, RCTSwitch
WHY Every render, rerender, renderHook, fireEvent and act gets an await.
8.3 · Demo, part 1

SwitchRow: a tap anywhere flips it once

shoreline-crew/src/components/SwitchRow.test.tsx
it('flips exactly once for a tap on the switch or on the words', async () => {
  const onChange = jest.fn();
  const user = userEvent.setup();
  await render(<GroupByDate onChange={onChange} />);
  const toggle = screen.getByRole('switch', { name: 'Group by date' });

  await user.press(toggle); // a finger on the switch itself
  expect(onChange.mock.calls).toEqual([[true]]);
  expect(toggle).toBeChecked();

  await user.press(screen.getByText('Group by date', { includeHiddenElements: true }));
  expect(onChange.mock.calls).toEqual([[true], [false]]);
  expect(toggle).not.toBeChecked();
WHY The words are hidden, so pressing them says so: includeHiddenElements.
