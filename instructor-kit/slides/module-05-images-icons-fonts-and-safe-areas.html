2.3 · The size rule

A picture from a server needs a size

  • expo-image never sizes itself from the file
  • From the API, no size: 358 wide, 0 tall
  • A require()d file, no size: 0 by 0
  • Card width + aspectRatio: 1200 / 675: 358 by 201
WATCH No error, no warning: check the size before the URL.

2.3 · The project's code

typography.ts

shoreline-crew/src/theme/typography.ts
export const fontFiles = { Outfit_600SemiBold, Outfit_700Bold };

// Headings use Outfit; everything else stays in the phone's own font.
// A custom font has one family per weight: the weight is in the name, not in fontWeight.
export const fonts = {
  title: 'Outfit_700Bold',
  heading: 'Outfit_600SemiBold',
} as const satisfies Record<string, keyof typeof fontFiles>;
RULE One family per weight: the weight is in the name, never in fontWeight.

2.3 · Mental model

The tide line

  • The safe area is the dry sand
  • The tarp (your background) may reach the wet sand
  • Clipboards and bags (your content) stay above the line
  • useSafeAreaInsets(): the tide chart, per phone, per rotation
WATCH The web preview has no notch: every inset is 0.
2.3 · The project's code

Screen: who covers which edge

shoreline-crew/src/components/Screen.tsx
  const insets = useSafeAreaInsets();
  // How much of each edge the phone covers (0 where it covers nothing, or the edge is left out)
  const clear = (edge: Edge) => (edges.includes(edge) ? insets[edge] : 0);

  // The frame stays out from under the status bar and the notch (and the sides in landscape)...
  const frame = { paddingTop: clear('top'), paddingRight: clear('right'), paddingLeft: clear('left') };
  // ...and the content ends above the home indicator, so the last card can scroll clear of it
  const end = { paddingBottom: spacing.md + clear('bottom') };
RULE Top on the frame; bottom inside the scrolling content.
