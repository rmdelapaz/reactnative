2.1 · View, Text and StyleSheet · Two building blocks

A box and a text

  • View: size, background, border, padding, layout
  • android.view.View / UIView
  • Cannot show text
  • Text: font, size, color, weight, line height
  • The platform's own text view
  • The only component that shows text
WHY <h1> to <h3> = Text with accessibilityRole="header"
2.1 · View, Text and StyleSheet · HTML on a phone

Where your HTML goes

  • div, article, section, header → View
  • p, span, strong, time → Text (a Text in a Text inline)
  • img → Image (2.3) · button, input → Pressable, TextInput (2.4)
  • page scrolling → ScrollView, then lists (Module 3)
WATCH The web preview forgives a raw string in a View. A phone does not.
2.1 · View, Text and StyleSheet · Styles are objects

CSS, the React Native way

  • font-size: 16px → fontSize: 16 (camelCase, a number)
  • 50% → '50%' · line-height: 1.5 → lineHeight: 24
  • border: 1px solid … → borderWidth + borderColor
  • padding: 8px 16px → paddingVertical / paddingHorizontal
  • className, var(--x) → style={styles.x}, a constant
RULE Colors: the same strings. The one thing that really carries over.
2.1 · View, Text and StyleSheet · Units

Density-independent pixels

  • One phone packs 2 pixels where another packs 3
  • fontSize: 16 = 32 pixels on 2x, 48 on 3x
  • Android says dp, iOS says points
  • What px already meant in a phone browser
WHY Your sense of 16 = body text, 32 = big heading carries over.

2.1 · View, Text and StyleSheet · Mental model

Tide pools, not a creek

  • CSS: pour color at the top, everything downstream gets wet
  • React Native: each Text holds only the water you pour in
  • A View is a rock: water poured on it runs off
  • A pool inside a pool shares its water: Text in Text
WHY Same style everywhere? Give every pool the same bucket: AppText.

2.1 · View, Text and StyleSheet · AppText

Three layers: base, variant, the screen

shoreline-crew/src/components/AppText.tsx
export function AppText({ variant = 'body', style, ...rest }: AppTextProps) {
  // Later styles win: the base, then the variant, then whatever the screen passes in
  return <Text style={[styles.base, styles[variant], style]} {...rest} />;
}
AppText title on the banner: {"color":"#ffffff","fontSize":32,"lineHeight":40,"fontWeight":"bold"}
WHY The screen's style is last, so it wins (white over the base's Ink).

2.1 · View, Text and StyleSheet · Text on phones

Fonts, weights, line heights, text size

  • No fontFamily: San Francisco (iPhone), Roboto (Android)
  • fontWeight: the closest weight a font has is used
  • lineHeight about 1.5 × fontSize: 16 / 24
  • Larger text in settings: text grows (allowFontScaling)
  • Never a fixed height on a box with text
