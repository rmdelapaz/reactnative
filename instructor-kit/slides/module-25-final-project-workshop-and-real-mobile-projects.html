10.2 · Platform trade-offs

A ladder, not one decision

  1. Expo Go: instant, only the SDK's modules
  2. Development build: your names, ids, any native package
  3. CNG: native folders generated from app.config.ts (Shoreline Crew)
  4. Committed native folders: hand-edited, merged on every upgrade
WHY Your own native code: the Expo Modules API, in a development build.
10.2 · Teams

Release trains

  • Cut-off: a release branch from main; only fixes go on it
  • Testers: an internal preview build, both platforms
  • Store build and review, with time for a rejection
  • Gradual rollout; watch the crash reports
  • Between trains: JavaScript-only fixes as updates
RULE Native changes always wait for the next train.
