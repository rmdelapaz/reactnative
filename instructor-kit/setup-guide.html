React Native & Expo: Build and Ship a Mobile App · Before You Begin

Set Up Your Toolchain for the Course

About an hour to do before the first session: install Node.js and VS Code, make your course folder, start the course's small Shoreline Crew API on your own computer, create the Shoreline Crew app with create-expo-app, put Expo Go on your phone (or plan on the web preview), install the course's labs once, and run a short check that tells you (and your instructor) whether your laptop is ready. These are the same steps as Lesson 1.2 on the course site (rays-reactnative.netlify.app, lesson "Your Toolchain"), which shows each one with pictures. Session 1 then spends its time on React Native instead of installers. Joining for Part 2 or Part 3 only? Do Steps 1, 2 and 5, then see Joining Part 2 or Part 3 near the end.

⏱ about 1 hour Windows · Mac · Linux Free software only A phone helps; none required Nothing paid, ever
Please do this at home, not in class

Each install is quick on its own, but twenty laptops downloading Node.js, VS Code, a new Expo project (about 560 packages) and the labs' shared install (about 1.1 GB) at once over venue Wi-Fi can fill most of a session. If a step fails, do the others and bring the exact error message (a screenshot is fine) to Session 1: it opens with the environment check, and Lesson 1.2's time in the room is an install clinic.

What You Need

  • A laptop and its charger: Windows 10 or 11, a recent macOS, or a 64-bit Linux, with several gigabytes of free disk space (the app and the labs each install their packages into a node_modules folder). You need permission to install software. Chromebooks, tablets and locked work laptops cannot run the course comfortably: talk to your instructor first.
  • Node.js, the current long-term-support (LTS) version, 24 or newer, with npm (Step 1). The course was checked on Node 24.22.2; the course's API needs at least 22.18.
  • VS Code (free) with the Expo Tools extension, and Git (recommended) (Step 2).
  • A web browser with developer tools: a current Chrome or Edge. The web preview of your app runs in it, and the lessons use its device toolbar to show it at phone size.
  • A phone, if you have one: an iPhone or an Android phone with the free Expo Go app, on the same Wi-Fi as your laptop (Step 5). No phone? The web preview in your browser is a valid way through every session and every lab.
  • The course's labs/ folder, which your instructor sends with this guide. Its file labs/module-01/l1_0-orientation/check_environment.mjs is the environment check in Step 7.
  • A learning journal: a file or a notebook. Every lesson ends with a journal prompt.
  • Later, not now: a free GitHub account (Session 24 and your final project) and, only if you want cloud builds, a free Expo account (Sessions 23 and 24). No store account and no paid developer account, ever. See Accounts below.

Am I Ready for This Course?

This course is for people who know React and TypeScript and are new to mobile: it follows the React + TypeScript course (rays-typescript.netlify.app) and reuses its API and its shared code. It does not reteach React or TypeScript; it shows what changes on a phone. No Swift, Kotlin, Mac or mobile experience is needed. You are ready if you can:

  • ☐ Write a React function component with props, useState and an event handler, in TypeScript
  • ☐ Use filter and map on an array of objects, and copy an object with one change ({ ...cleanup, status: 'completed' })
  • ☐ Say why spotsLeft ?? 'unknown' and spotsLeft || 'unknown' differ when the value is 0
  • ☐ Narrow a union type ('scheduled' | 'completed' | 'canceled') with an if or a switch
  • ☐ Have met TanStack Query, Zustand, React Hook Form with Zod, and a test runner (Vitest or Jest), even briefly
  • ☐ Open a terminal, move between folders with cd, and run a command someone gives you

Two or more unchecked? Come anyway and tell your instructor. Session 1 includes a short, ungraded diagnostic on these same skills (filter and map, copying with one change, ??, narrowing, state, the terminal), so your instructor knows where to help, and a practice file for anything you miss. The React + TypeScript course's lessons are the refresher.

Set Up in 7 Steps

1

Install Node.js (the current LTS, 24 or newer)

~10 min

Node.js runs the Expo CLI, Metro (Expo's bundler) and the course's API on your computer; npm and npx come with it. Not on the phone: there your app runs in React Native's own JavaScript engine (Lesson 1.1). If you finished the React + TypeScript course, Node is probably already there: check it.

  • Windows / macOS: on nodejs.org, download the LTS installer (.msi for Windows, .pkg for macOS) and run it, keeping the defaults (they add Node and npm to your PATH).
  • Linux (or if you already use one): a version manager such as nvm or fnm, then install the LTS (nvm install --lts). Your distribution's own Node is often too old.

Then open a new terminal (Windows: PowerShell or Command Prompt; macOS: Terminal) and run:

node --version
npm --version
v24.22.2
11.19.1

Your numbers may be higher. The first number after the v should be 24 or higher. Older versions do not work: the course's API runs its TypeScript files directly, which needs Node 22.18 or newer, and an older Node stops with ERR_UNKNOWN_FILE_EXTENSION. If you have an older Node, install the current LTS over it.

2

VS Code, Expo Tools and Git

~10 min
  1. Download VS Code from code.visualstudio.com and install it with the defaults. Windows and Linux installers add the code command to your terminal; on a Mac, open the Command Palette (⌘ Cmd+Shift+P) and run Shell Command: Install 'code' command in PATH.
  2. The project you create in Step 4 recommends Expo's own extension, Expo Tools (identifier expo.vscode-expo-tools): accept when VS Code offers it, or search for it in the Extensions view (Ctrl+Shift+X, Mac ⌘ Cmd+Shift+X). The ESLint extension (by Microsoft) is a good second: it shows the linter's findings as you type. Check the publisher before you click Install: copycat extensions exist.
  3. Git (recommended now, needed in Session 24): git --version answers if you have it; otherwise install it from git-scm.com. create-expo-app starts a repository and makes the first commit for you.

Things you will use all course: File › Open Folder… (open a folder, not a file), the built-in terminal (View › Terminal; the + button adds a second one), the Problems panel and the Command Palette (Ctrl+Shift+P; ⌘ Cmd on a Mac).

3

Your course folder and the Shoreline Crew API

~10 min

Every lesson builds Shoreline Crew, the volunteers' phone app of a fictional beach-cleanup group. Its data comes from a small API the course gives you, the same one the React + TypeScript course's web app used: no install, no accounts, it runs on your own computer.

  1. Did the React + TypeScript course? You already have a shoreline folder with shoreline-api and shoreline-hq in it: use it, the API is the same. Skip to step 5.
  2. Otherwise create a folder called shoreline where you keep your code, such as Documents, but not in a folder synced by OneDrive, iCloud or Dropbox (npm writes thousands of small files and syncing makes it crawl).
  3. Download shoreline-api.zip from the course site (Lesson 1.2, or rays-reactnative.netlify.app/downloads/shoreline-api.zip), or take the copy your instructor gives you, and unzip it into shoreline (Windows: right-click › Extract All…; macOS: double-click; Linux: unzip shoreline-api.zip).
  4. Check: shoreline/shoreline-api/server.ts must exist. Some unzip tools add a folder level (shoreline-api/shoreline-api/): move the inner folder up one level.
  5. In VS Code, File › Open Folder… (Mac: File › Open…), open shoreline, then open the terminal (View › Terminal) and start the API:
cd shoreline-api
node server.ts
Shoreline Crew API running at http://localhost:4000/api
  sample sign-in: maya.okafor@example.com (organizer) or theo.nakamura@example.com (volunteer), password shoreline-demo
Press Ctrl+C to stop.

There is no npm install: the API has no dependencies. This terminal now belongs to the server; leave it running. Open http://localhost:4000/api/events?when=upcoming&perPage=2 in your computer's browser: JSON with two upcoming cleanups. The API keeps its data in memory, so a restart brings the sample data back fresh.

4

Create Shoreline Crew with create-expo-app

~15 min

Open a second terminal (the + button in the terminal panel). It starts in shoreline; if its prompt says shoreline-api, type cd .. first. Then:

npx create-expo-app@latest shoreline-crew

If npx asks to install create-expo-app, answer y. It downloads Expo's default template (SDK 58) and installs about 560 packages (a minute or less on a good connection). The end of its output (your counts and timings may differ):

Creating shoreline-crew using the default@sdk-58 template.
…
✅ Your project is ready!
  • It may also report a few "moderate severity vulnerabilities" and suggest npm audit fix --force: do not run it: "force" means it may install versions that break the SDK's tested set, and the reports are mostly about development tools (Lesson 1.2's Common Mistakes).
  • Open the project: cd shoreline-crew, then code .; accept the recommended extension (Expo Tools).
  • Leave the template as it is. Resetting it (npm run reset-project) and writing the first screen are Lesson 1.2's Step 6, done together in Session 1.

Curious? You may look now: in shoreline-crew, npx expo start, then press w (the web preview at http://localhost:8081) or scan the QR code with Expo Go (Step 5). Stop it with Ctrl+C before Step 7. Getting it onto a phone is Session 1's work, so do not worry if the phone does not connect yet.

~5 min

With the API still running in its terminal (and npx expo start stopped, if you started it), go to the other terminal, make sure it is in shoreline and run:

When the Phone Cannot Reach Your Computer

Expo Go loads your app over Wi-Fi from your computer, so the network matters more than in a web course. This is tested in Session 1 (Lesson 1.2, Step 4); Lesson 5.1 (Session 12) returns to it when the phone talks to the API. Work through this list in order; most problems are one of the first three:

  1. Same network? Check the Wi-Fi name on both. A phone on mobile data cannot reach your laptop. Guest, school, hotel and many office networks block devices from talking to each other; home networks usually do not.
  2. The address under the QR code (exp://192.168…) should look like your computer's address on that network.
  3. Firewall: the first time Node.js opens a port, Windows and macOS may ask whether to allow it. Allow it on private networks.
  4. iPhone: Settings › Privacy & Security › Local Network: Expo Go must be switched on.
  5. Still stuck? A hotspot from the phone, or npx expo start --tunnel (slower; it offers to install a helper the first time), or the web preview, which is a valid way to finish every lesson.
Windows with WSL 2: the phone cannot see inside WSL

WSL normally lives behind its own private address, often 172.x.x.x: Expo prints it under the QR code and your phone cannot reach it. Three fixes: run the course's Node commands in Windows itself (PowerShell; every npx command in the course works there unchanged); or turn on WSL's mirrored networking (Windows 11: networkingMode=mirrored under [wsl2] in %UserProfile%\.wslconfig, then wsl --shutdown) and allow ports 8081 and 4000 through the Windows firewall; or use the web preview, which works from WSL.

Frequently Asked

Do I need a phone?

No, but it helps. Every session, lab, checkpoint and part project works in the web preview. Your final project shows its device features on a real phone (yours or a borrowed one); an app without device features can be shown in the web preview (Lesson 10.1's rubric).

Do I need a Mac to make an iPhone app?

No. Expo Go runs your app on an iPhone from any computer. The iOS Simulator and local iOS builds need a Mac; on Windows and Linux, EAS builds iPhone apps in the cloud (Module 9, optional).

Do I have to pay for anything?

No. Node.js, VS Code, Expo Go, every package and the course API are free. GitHub's and Expo's free accounts are enough; no store account and no paid developer account is needed for any step or to pass.

Can I use pnpm, Yarn or Bun instead of npm?

Expo supports them, but the lessons' commands, lockfiles and outputs are npm's, so every command in the lessons and the downloads matches exactly. Please use npm for the course.

Does stopping the API lose my work?

Your code is just files in your course folder and stays. The API's data lives in memory: a restart brings the sample data back fresh, which is a feature when your app has changed it. Start the API before you work, every time.

Is the course data real?

No. Shoreline Crew, its beaches, cleanups, volunteers and email addresses are invented for the course, and so are the clients of the part projects and labs. The sample password shoreline-demo is public on purpose: it only works on the practice API.

What if a step fails and I cannot fix it?

Come anyway, with the output of the environment check. Session 1 opens with the check and has an install clinic, and you can pair with a neighbor until your laptop is ready.

Learners need registry.npmjs.org (npm), nodejs.org, code.visualstudio.com and VS Code's extension marketplace, rays-reactnative.netlify.app (lessons and downloads), snack.expo.dev (Lesson 1.1), the App Store or Google Play (Expo Go), cdn.jsdelivr.net (the web Lottie player, Session 19), github.com (Session 24) and, for learners with an Expo account, expo.dev. Expo Go needs phones and laptops on one network that lets devices talk to each other (ports 8081 for Metro and 4000 for the API); guest and school networks often block it. Corporate proxies that inspect HTTPS often break npm and git push. Keep a phone hotspot as the fallback.
  • ☐ The room: a power socket for every laptop (power strips), a whiteboard, sticky notes (help flags and exit tickets), printed workbooks or a shared PDF.
  • ☐ Install trouble on the day: do not debug one laptop or one phone in front of the room. A NOT READY machine gets a ready partner during Lesson 1.1 (which needs only a browser: Expo Snack) and a slot in the 25-minute install clinic in Lesson 1.2. A phone that cannot connect is not a reason to stop: the web preview is a valid way to finish. Session 1's facilitator guide has the full trap table.
  • ☐ Before Part 2 and Part 3: send the Joining Part 2 or Part 3 section with Session 9's (or 17's) close, and a week ahead to newcomers. Before Session 23, mention the optional free Expo account; before Session 24, ask learners to install Git and create a free GitHub account. Say it every time: no store account and no paid developer account, ever.
