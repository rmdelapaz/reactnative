📖 Glossary

The React Native, Expo and mobile words you meet in this course, in plain language, each linked to the lesson that teaches it.

🧭 How to Use This Glossary

Every word below is used in the course and explained the way the lessons use it: Expo SDK 58, React Native 0.88, Expo Router, TanStack Query 5, Reanimated 4, Jest with jest-expo and EAS. Jump to a letter, or press Ctrl+F (⌘ Cmd+F on a Mac) to search the page. Each entry ends with a link to the lesson that teaches it; a second link means a later lesson goes deeper. Names that start with a symbol (+not-found, (tabs), .web.ts) are filed under their first letter. React and TypeScript words are in the React + TypeScript glossary. For code patterns, see the React Native cheat sheet and the Expo CLI cheat sheet; for the mock back end, the shoreline-api reference; for error messages, Troubleshooting.

10.0.2.2
The Android emulator's built-in name for the computer it runs on. The emulator reaches an API on that computer at http://10.0.2.2:4000. Lesson 5.1.
401 Unauthorized
The HTTP status the API sends when it does not accept the token: wrong, expired, or unknown after the API restarted. Shoreline Crew treats it as "your sign-in has ended" and offers a way back in. Lesson 4.3. Lesson 5.2.

A

Accessibility actions (accessibilityActions)
Named actions a screen reader offers on one element without a visible button (VoiceOver's "Delete" in a mail list), handled with onAccessibilityAction. Lesson 7.2. Lesson 8.1.
Accessibility audit
Going through every screen systematically: automated checks (axe in the web preview), the accessibility tree, then a screen reader and the largest text on a real phone, with a findings table. Lesson 8.1.
Accessibility element
One stop for a screen reader: something it moves to and reads as a whole. accessible on a View makes the view and everything in it one element. Lesson 8.1.
Accessibility hint (accessibilityHint)
An optional sentence that says what will happen if you activate an element. Screen readers say it after a pause, and people can turn hints off, so it must never be needed. Lesson 8.1.
Accessibility Inspector / Accessibility Scanner
Optional platform tools: Xcode's Accessibility Inspector on a Mac and Google's free Accessibility Scanner app on Android. They help, but do not replace using the phone with a screen reader. Lesson 8.1.
Accessibility tree
The tree of elements, names, roles and states that assistive technology sees instead of the pixels. In the web preview, Chrome DevTools shows it. Lesson 8.1.
AccessibilityInfo (reduceMotionChanged)
React Native's API for system accessibility settings: isReduceMotionEnabled() answers now and the reduceMotionChanged event reports every change while the app runs. Lesson 7.3.
accessibilityLabel
The words a screen reader says for a component. Icon-only buttons and pictures need one; a TextInput needs one in place of a <label>. Lesson 2.4. Lesson 8.1.
accessibilityRole
A prop that tells screen readers what a component is: "header" for a heading, "button", "link", "alert" and more. It replaces the meaning HTML elements carry. Lesson 2.1. Lesson 2.4. Lesson 8.1.
accessible (grouping)
The prop that makes a View and its children one element read as one sentence, such as a tally read as "42 pieces". Grouping too much hides the separate buttons inside. Lesson 8.1.
Account deletion requirement
The stores' rule that an app which creates accounts must let people start deleting them from inside the app (and Google Play, from the web too). Lesson 9.4.
Activation (activeOffsetX)
How far the finger must move before a gesture starts. activeOffsetX: [-12, 12] lets a pan start only after 12 points sideways, so a short tap or a scroll is not mistaken for a swipe. Lesson 7.2.
ActivityIndicator
React Native's spinner, drawn by each platform. Shoreline Crew's LoadingView pairs one with words that say what is loading. Lesson 3.1.
Ad hoc provisioning
Apple's way to install a build outside the App Store on registered iPhones only (up to 100 a year), which needs a paid Apple Developer membership. Lesson 9.2.
Adaptive icon
Android's layered icon: a foreground picture on a background that each phone crops to its own shape (circle, squircle). Set in app.json under android.adaptiveIcon. Lesson 2.3.
addressAdvice
Shoreline Crew's function in src/api/address.ts that suggests a fix for an address that got no answer, per platform (for example, "a phone cannot use localhost"). describeError adds it to "Could not reach the server at …". Lesson 5.1.
AGENTS.md
A file from create-expo-app with notes for AI coding assistants about the project's tools and rules. The course keeps it; read it once. Lesson 1.2.
allowFontScaling
A Text prop, true by default, that lets text follow the size the person chose in the phone's settings. Leave it on, and never give a box with text a fixed height. Lesson 2.1. Lesson 8.1.
Anchor (unstable_settings.anchor)
The screen Expo Router puts underneath a screen opened by a link or a guard redirect. Shoreline Crew's root layout sets unstable_settings = { anchor: '(tabs)' }, so a cleanup opened from a link has the tabs and a back button under it. Lesson 4.4. Lesson 6.4.
Android emulator
A virtual Android phone on your computer, from Android Studio. Press a in Metro's terminal to open the app in it; it reaches your computer at the special address 10.0.2.2. Lesson 1.2. Lesson 5.1.
android_ripple
A Pressable prop that draws Android's ripple at the touch. It does nothing on iOS or the web. Lesson 2.4. Lesson 2.5.
Animated component (Animated.View)
A view Reanimated can drive (Animated.View, Animated.Text): it accepts animated styles and layout animation props. Lesson 7.1. Lesson 7.3.
Animated style (useAnimatedStyle)
A style computed from shared values on the UI thread, passed to an Animated.View or Animated.Text. It updates every frame without React drawing anything. Lesson 7.1.
announceForAccessibility
AccessibilityInfo.announceForAccessibility(text) asks the screen reader to say something. announceForAccessibilityWithOptions(text, { queue: true }) waits until VoiceOver has finished speaking (iOS only). Lesson 8.1. Lesson 8.3.
API contract (types.ts)
src/api/types.ts: the types that describe what the shoreline-api sends and accepts. The phone and the HQ agree on it, so it is copied unchanged. Lesson 1.3.
APK / AAB
Android's two build files: an APK is what a phone installs directly (internal builds); an Android App Bundle (.aab) is what Google Play wants, and the store makes each phone's APK from it. Lesson 9.2. Lesson 9.4.
App config
The description of the app around your JavaScript: name, version, icon, splash, scheme, ids and config plugins. Expo Go, prebuild and every build read it. Lesson 9.1.
App icon
The picture under the app's name on the home screen, set in app.json. Expo Go shows its own icon; you only see yours in a build. Lesson 2.3. Lesson 9.1.
App Privacy details
Apple's privacy questions (the "privacy nutrition label" on the store page): what data the app collects, whether it is linked to the user, and whether it is used for tracking. Lesson 9.4.
App Review
The stores' check of every submission against their guidelines. Common rejections: crashes, broken links, missing demo account, unclear permission sentences. Lesson 9.4.
App Store Connect
Apple's website for an app's store record, builds, TestFlight, privacy details and review submissions. Lesson 9.4.
App Transport Security (ATS)
The iPhone rule that apps use https. Expo's iOS project allows local-network addresses (NSAllowsLocalNetworking) and nothing else. Lesson 9.1.
App variant
One of the three apps one project produces: development ("Shoreline Dev", the default), preview ("Shoreline Preview", for testers) and production ("Shoreline Crew", for the stores), each with its own name and id, side by side on one phone. Lesson 9.1. Lesson 9.2.
app.config.ts (dynamic config)
The app config as a TypeScript function, replacing app.json in 9.1. It receives a ConfigContext, returns an ExpoConfig, can read environment variables and is type-checked. Tools can no longer edit it for you ("Cannot automatically write to dynamic config"). Lesson 9.1. Lesson 9.2.
app.json
The app's configuration: name, slug, scheme, icons, splash screen, plugins and experiments such as typed routes. It becomes app.config.ts in Lesson 9.1. Lesson 1.2. Lesson 9.1.
APP_VARIANT
The environment variable that picks the variant when the config is read: set it in the shell (APP_VARIANT=preview npx expo config --type public) or per build profile in eas.json. Lesson 9.1. Lesson 9.2.
Apple Developer Program
Apple's paid yearly membership needed to install builds on iPhones outside Expo Go, use TestFlight and publish. Lesson 9.4. Lesson 9.2.
Approximate and precise location
Both phones let people share only a rough position. Expo's answer says which one the person allowed (ios.accuracy 'full' or 'reduced', Android fine or coarse). Lesson 6.1.
AppState
React Native's report of whether the app is in the foreground ('active') or the background. It is the phone's version of the browser's visibilitychange. Lesson 5.2.
AppText
Shoreline Crew's text component: a Text with the app's font, color and size built in, picked with a typed variant prop (title, heading, body, muted, error). React Native has no inherited font, so one component does that job. Lesson 2.1. Lesson 2.3.
appVersionSource remote / autoIncrement
cli.appVersionSource: "remote" in eas.json lets EAS store the build numbers, and autoIncrement on the production profile raises them for each build. Lesson 9.3. Lesson 9.2.
aria-* props (accessibility state)
React Native's aria-expanded, aria-disabled and similar props tell screen readers a control's state. The course uses them because they work on phones and in the web preview, where accessibilityState is ignored. Lesson 2.4. Lesson 8.1.
aria-hidden
The prop that hides decoration from screen readers on every platform (phones and the web preview), used on icons, the swipe strip and the Lottie check mark. Lesson 7.3. Lesson 8.1.
Ask at the moment (permission timing)
The rule that an app asks for a permission when the person does the thing that needs it, never at start-up. Lesson 6.1 calls it the farm gate rule. Lesson 6.1. Lesson 6.4.
aspectRatio
A style that sets one side of a box from the other: width divided by height. Shoreline Crew's site pictures take the card's width and get their height from aspectRatio. Lesson 2.2. Lesson 2.3.
AsyncStorage (@react-native-async-storage/async-storage)
An unencrypted key-value store in the app's folder: like localStorage, but every call returns a promise (getItem, setItem, removeItem). Shoreline Crew keeps its settings and, from Lesson 5.5, the log queue there. Lesson 5.3. Lesson 5.5.
Automatic mock
What jest.mock('module') without a factory makes: Jest loads the real module to copy its shape and replaces each function with an empty jest.fn(). A module that cannot load in Jest (expo-notifications) needs a factory instead. Lesson 8.2. Lesson 8.4.

Badge (StatusBadge)
Shoreline Crew's small pill label: a View around an AppText, in one of five tones. StatusBadge picks the tone and words for a cleanup's status from a lookup table copied from the HQ. Lesson 2.2.
Before you go
Shoreline Crew's modal route, before-you-go.tsx, with tips for the beach and a Done button. It is opened from the Profile tab. Lesson 4.2.
Blob
The web's type for raw data with a type, such as an image. expo-file-system's File is a Blob, so fetch can send it as a request body. Lesson 6.2.
blockedPermissions
android.blockedPermissions removes a permission a library added. Shoreline Crew's production variant blocks SYSTEM_ALERT_WINDOW, which only development tools use. Lesson 9.4. Lesson 9.1.
Branch (EAS Update)
Where EAS keeps a series of updates; a channel points at a branch (by default the one with its name), so a team can repoint it without a new build. Lesson 9.3.
Breakpoint
A width at which the layout changes. Shoreline Crew shows two columns of cards at 700 wide or more (useColumns). Lesson 2.5.
Build profile
A named kind of build in eas.json, picked with --profile: development (dev client, internal), preview (internal APK with a test API address) and production (store build, autoIncrement). Lesson 9.2.
Build queue
The line a cloud build waits in for a free build server. On the free plan it is low priority and the wait varies; plan for it. Lesson 9.2. Lesson 10.2.
Bundle
The app's JavaScript in one file, written by npx expo export (and by every build). Its size affects startup and download size. Lesson 8.4.
Bundle identifier
The iPhone app id (ios.bundleIdentifier), such as com.example.shorelinecrew. Permanent once a store has seen it, so it must be on a domain you control. Lesson 9.1. Lesson 9.4.
Button (component)
Shoreline Crew's button: a Pressable with a label, a primary or secondary variant, press feedback, the button role and a 48-high minimum. Lesson 2.4. Lesson 4.1.
Byte order mark (BOM)
An invisible character (U+FEFF) at the start of a text file. Spreadsheets read a CSV file with one as UTF-8, so "Café" does not turn into "CafÃ©". Lesson 6.5.

C

Cache and documents directories
The app's two main folders. The system may empty the cache when space runs low; documents stay until the app deletes them. Photos waiting with a log go to documents; the logbook export goes to the cache. Lesson 6.2. Lesson 6.5.
canAskAgain
Part of every Expo permission answer: false means the phone will not show its question again and only the Settings app can change the answer. Lesson 6.1.
Channel (EAS Update)
The name a build listens on for updates, set in its build profile (preview, production). An update published to preview never reaches production phones. Lesson 9.3.
Charter (out of scope)
A one-page agreement on what the app will do, and in writing what it will not ("out of scope"), so the project stays finishable. Lesson 10.1.
Check-in code
The four digits the organizer reads out at the meeting point on the day. Shoreline Crew checks in by this code alone, and the server decides; the location stays an optional extra. Lesson 6.3.
checkInMutation
The mutation that sends a check-in code. Offline it pauses in memory (not queued); retrying is safe because the API's check-in is idempotent. On success the sign-up becomes attended. Lesson 6.3.
CI (continuous integration)
A server that runs the checks on every push. Shoreline Crew's GitHub Actions workflow (.github/workflows/ci.yml) runs npm ci, type generation, tsc, lint and Jest. Lesson 9.3. Lesson 10.2.
cleanupLink and cleanupMessage
Shoreline Crew's helpers in src/utils/links.ts: the link to a cleanup (via Linking.createURL) and the text to share with the link inside it. Lesson 4.4.
Cleartext traffic
Plain http without encryption. Release builds block it by default (Android 9+, iPhone's App Transport Security); Shoreline Crew allows it only in the preview variant with expo-build-properties. Lesson 9.1.
Client brief
A short description of a fictional client's needs (people, must-haves, device features, data) that the final project builds from. The kit has seven, with Copperline Couriers worked as the example. Lesson 10.1.
Client isolation
A Wi-Fi setting on many guest, school, office and hotel networks that keeps every device apart, so a phone and a computer cannot see each other even with the right address. A phone hotspot or a home network gets around it. Lesson 5.1.
clientId
A random id (expo-crypto's randomUUID()) the phone makes once per debris-log form visit and sends with the log. The API recognizes a resend by it and answers 200 with the log it already has, so retries are safe. Lesson 5.4. Lesson 5.5.
Closed test (Google Play)
A test release to chosen testers. Newer personal Google Play accounts must run one with at least 12 testers for 14 days before they can apply for production. Lesson 9.4. Lesson 10.2.
Code coverage
Which lines the tests ran: npm test -- --watchAll=false --coverage prints a table and writes an HTML report. A useful map of untested code, not a score to chase. Lesson 8.2. Lesson 8.3.
Collected (store definition)
Data that leaves the phone and is kept. Data that stays on the phone, like the logbook, is not "collected". Answer from an inventory of the code and every SDK, never from memory. Lesson 9.4.
Color scheme (dark mode)
Whether the phone is in light or dark mode, read with useColorScheme(). The app follows it when app.json's userInterfaceStyle is "automatic". Lesson 2.5.
Committed native folders ("ejecting")
Generating the native projects once and maintaining them by hand. Older articles call leaving Expo's managed setup this way "ejecting". Lesson 10.2.
Compression quality
The picker's quality option (0 to 1). Shoreline Crew uses 0.6, which usually turns a few megabytes into a few hundred kilobytes, small enough for one bar of signal. Lesson 6.2.
Config plugin
Code a package gives Expo to change the native projects when an app is built: purpose strings, backup rules, entitlements. npx expo install often adds one to the plugins list; Expo Go ignores them, your own builds use them. Lesson 4.3. Lesson 6.1.
ConnectionCheck
The Profile section that shows which API address the app uses and a Check the connection button that asks /api/health for an answer right now. Lesson 5.1.
contentContainerStyle
The ScrollView (and list) prop for the strip that scrolls, where padding and gaps go; style styles the outer box that fills the screen. Lesson 2.1. Lesson 2.2.
contentFit
How expo-image fits a picture into its box: 'cover' fills it and crops, 'contain' shows the whole picture with empty bands. It is the phone's object-fit. Lesson 2.3.
Continuous Native Generation (CNG)
Generating android/ and ios/ from app.config.ts and plugins at every build, never editing or committing them. Native changes go through config plugins; upgrades regenerate the folders. Lesson 10.2.
ControlledField
Shoreline Crew's form field: FormField connected to a form by control and name through useController. name is typed from the form's values. Lesson 5.4.
Core components
The components that come with React Native itself, such as View, Text, Image, ScrollView, Pressable and TextInput. They take the place of HTML elements. Lesson 1.1.
CORS (cross-origin resource sharing)
A browser rule: a page may read answers from another origin only if that server allows it. A phone app's fetch has no such rule; the web preview, being a web page, does. Lesson 5.1.
Crash reporting
A service that collects errors from users' phones with the app version and a stack trace (translated by source maps). Shoreline Crew has a seam, reportError with setReporter, ready for one; reports are personal data. Lesson 9.3. Lesson 9.4.
create-expo-app
The command that starts a new Expo project: npx create-expo-app@latest shoreline-crew. It writes the template, installs the packages and makes the first Git commit. Lesson 1.2.
createPermissionHook
A function exported by expo that makes a permission Hook from a get and a request function. Shoreline Crew uses it for notifications, which have no Hook of their own. Lesson 6.1. Lesson 6.4.
createThemedStyles
Shoreline Crew's helper that builds a style sheet from the current theme's colors: call it outside the component and the hook it returns inside, so every color in a style sheet follows dark mode. Lesson 2.5.
Cross-platform
One codebase that produces apps for several platforms: here iOS, Android and, as a preview, the web. Lesson 1.1.
CSS-style transition (Reanimated 4)
Reanimated 4's way to animate a style change with no shared value: put transitionProperty, transitionDuration and transitionTimingFunction in an animated component's style, and React's new value animates in. Lesson 7.1.
CSV (comma-separated values)
A plain-text table: one line per row, commas between fields, quotes around fields that hold commas, quotes or line breaks. Lines end with \r\n, as the standard says. Shoreline Crew's logbook export is a CSV file. Lesson 6.5.
CSV injection (formula injection)
Text in a CSV file that starts like a formula (=, +, -, @) and runs when a spreadsheet opens it. Shoreline Crew puts a ' in front of such notes. Lesson 6.5.

D-U-N-S number
A free company identifier from Dun & Bradstreet that both stores ask organizations for before they can publish as the organization. Lesson 9.4.
Data safety (Google Play)
Google Play's privacy form and store section: what is collected or shared, why, whether it is required and encrypted in transit, and how to ask for deletion. Lesson 9.4.
debrisLogSchema
The Zod schema in src/api/schemas.ts that checks a debris log on the phone: whole-number counts typed as text, a weight that accepts a comma, a note. The server checks the same rules again. Lesson 5.4.
Debugging method

Decision record

Delta sync (updatedSince)

describeError
The helper from the HQ that turns any error into words for a volunteer. The phone's version also knows NetworkError. Lesson 1.3. Lesson 3.1.
Developer menu

Development build
Your own version of the app, with exactly the native modules you chose, that loads your JavaScript from your computer the way Expo Go does. Needed for libraries Expo Go does not include and for store-like testing. Lesson 1.1. Lesson 9.2.
Development vs release build (performance)

dismissTo
An Expo Router navigation that closes screens until it reaches the given route, and replaces only when there is nothing to go back to. The not-found screen uses it so a link never stacks a second copy of the tabs. Lesson 4.4.
DistancePanel (How far is it?)

dotLottie (@lottiefiles/dotlottie-react)

Dynamic route ([id])

Expo's cloud services: EAS Build makes Android and iOS app binaries (no Mac needed for iOS), EAS Update sends JavaScript updates to installed apps, EAS Submit uploads to the stores. Lesson 1.1. Lesson 9.2.

Expo's cloud builds: it uploads your project, waits in a queue, installs, runs prebuild, compiles and signs the app, and gives a link to install it. The free plan is enough for the course; check Expo's pricing page. Lesson 9.2.

The command-line tool for EAS, run in the course as npx eas-cli@latest (build, init, update, submit, env:set). Lesson 9.2. Lesson 9.3.
EAS environment variables

EAS Submit (submit profile)
npx eas-cli@latest submit uploads a finished build to a store, using a submit profile in eas.json (Android track, Apple ascAppId). Lesson 9.4.

eas.json
The file of build and submit profiles at the top of the project. Each Shoreline Crew build profile sets APP_VARIANT; cli.appVersionSource and submit live here too. Lesson 9.2. Lesson 9.4.
Easing
The shape of a timing curve: how an animation speeds up and slows down (Easing.out(Easing.cubic)). An easing-out curve starts fast and settles gently. Lesson 7.1.
Edge to edge

edges (Screen prop)
Which safe-area insets Shoreline Crew's Screen adds: 'top', 'bottom', 'left', 'right'. The rule: leave out every edge a bar already covers. Lesson 2.3. Lesson 4.2.
Embedded update
The JavaScript a build was made with, kept inside it. If a downloaded update fails to start, expo-updates falls back to it. Lesson 9.3.
End-to-end test
A test that drives the real app on a phone, emulator or simulator from outside, the way a person would: taps, typing, waiting, looking. Slow and costly, so kept for the few journeys that matter most. Lesson 8.3.
Entering / exiting animation
Ready-made layout animations for a view that arrives (entering={FadeIn}) or leaves (exiting={FadeOutLeft}). Each can be tuned with .duration(), .easing() and .reduceMotion(). Lesson 7.3.
enterKeyHint
The TextInput prop that labels the return key: 'next', 'go', 'done'… The iPhone's number pads have no return key at all. Lesson 5.4. Lesson 6.3.
Entitlement
A capability Apple must grant an iPhone build, such as push notifications (aps-environment). Shoreline Crew's build has none: local reminders only. Lesson 9.1.
.env.local
The file where you set your own EXPO_PUBLIC_ values, such as the API address. It is copied from .env.example and not committed. Lesson 1.3. Lesson 5.1.
Error boundary
A component shown instead of a screen that threw while drawing. Expo Router uses the ErrorBoundary a layout exports; Shoreline Crew's root layout exports its CrashScreen. Lesson 9.3.
EventCard
Shoreline Crew's card for one cleanup: title, date, meeting point, spots, badges and later the site picture, Show details and Open. It is the phone's version of the HQ's card. Lesson 2.1. Lesson 4.1.
EXIF
Data a camera writes inside a photo: the camera model, the time, and often the exact place it was taken. Shoreline Crew asks the picker for exif: false, because a home address has no place in a debris report. Lesson 6.2.
exp:// link
The form of a link that opens your project in Expo Go during development, with your computer's address and Metro's port in it. It works only for you and your test phones. Lesson 4.4.
Expo
A framework and set of tools for building React Native apps: the project template, the Expo CLI, the Expo SDK, Expo Router, Expo Go and the cloud services called EAS. The React Native team recommends starting new apps with a framework such as Expo. Lesson 1.1.
Expo Atlas
Expo's bundle explorer: export with EXPO_ATLAS=true and open it to see which packages and files take how much of the bundle. Install expo-atlas as a dev dependency first. Lesson 8.4.
Expo CLI
The command-line tool you run as npx expo …: it starts the development server, installs SDK-compatible packages, lints and exports. It lives in the project's node_modules, so there is nothing to install globally. Lesson 1.1. Lesson 1.2.
Expo Go
A free app for iPhone and Android that loads your project from Metro over Wi-Fi when you scan a QR code, with no build step. It contains a fixed set of native modules for one SDK version; for anything else you make a development build. Lesson 1.1. Lesson 1.2.
Expo Modules API
Expo's way to write your own native module in Swift and Kotlin with a TypeScript interface, as a local module inside the project, when no library meets a need. Lesson 10.2.
Expo Router
Expo's navigation library: every file in src/app/ is a screen with its own address, and layout files decide whether screens form a stack, tabs or modals. Lesson 1.1. Lesson 4.1.
Expo SDK
Expo's set of native modules (camera, location, notifications and more) with one consistent API, released together under one number. The course uses SDK 58, and every package is installed in the version that matches it. Lesson 1.1.
Expo Snack
Expo's website for running React Native in a browser tab with nothing installed. Lesson 1.1's first component runs there; it can be a step behind the course's SDK. Lesson 1.1.
expo-build-properties

A navigator with a bar of buttons, one per screen; switching tabs keeps each tab's screen as you left it. Shoreline Crew has four: Cleanups, My cleanups, Logbook and Profile. Lesson 4.2.
Tabs (expo-router/js-tabs)
The JavaScript tab bar Shoreline Crew uses, import { Tabs } from 'expo-router/js-tabs'. Expo Router's older Tabs import is deprecated in SDK 58. Lesson 4.2.
TalkBack
Android's built-in screen reader. Like VoiceOver it moves element by element and reads each one's name, role and state. Lesson 8.1.
Target API level
The Android version an app declares it was built for. Google Play requires a recent one for new apps and updates; a current Expo SDK sets it for you. Lesson 9.4.
Test environment (Jest)
The world a test file runs in. Shoreline Crew's jest.environment.js builds on jest-expo's and keeps Node's real fetch so tests can use MSW. Lesson 8.2.
Test factory
A helper in src/test/factories.ts that builds believable test data (a volunteer, a log) with only the fields a test cares about changed. Lesson 8.2.
TestFlight
Apple's beta testing service: an uploaded build appears there for testers before it is submitted for review. Lesson 9.4.
Text
The only component that can show text. A string directly inside a View is an error on a phone; a Text inside a Text styles part of a line. Lesson 2.1.
TextInput
React Native's text field. It is controlled with value and onChangeText, and its value is always a string, even with a number keyboard. Lesson 2.4. Lesson 5.4.
Theme tokens (color roles)
Colors, spacing and type sizes kept in src/theme/ and named by their job (page, surface, text, primary), not by their color. Screens use only the roles, which is what makes dark mode possible. Lesson 2.1. Lesson 2.5.
Three-point (PERT) estimate
An estimate from optimistic, likely and pessimistic guesses: (optimistic + 4 x likely + pessimistic) / 6. The gap between the extremes shows where the uncertainty is. Lesson 10.2.
Time log
The worksheet's record of estimated and actual hours per milestone, with a column for what surprised you. It is how your estimates improve. Lesson 10.1. Lesson 10.2.
Token (session token)
The string the API hands back after a correct email and password. The app sends it with every request instead of the password, and the API answers 401 when it no longer recognizes it. Lesson 4.3.
Touch target
The area a finger can hit. Make it at least 44 points (Apple) or 48 dp (Google); Shoreline Crew uses 48 with minHeight, never a fixed height. Lesson 2.4.
Tracking (Apple)
Using data to follow a person across other companies' apps or sites, for example for advertising. Shoreline Crew does none, and says so. Lesson 9.4.
Transaction
Several database statements that succeed or fail together (db.withTransactionAsync), so a crash halfway never leaves half a change. Lesson 5.3.
Trim path
The Lottie trick for a line that draws itself: the end of the stroke's trim is animated from 0% to 100% over a few frames. Lesson 7.3.
Tunnel (--tunnel)
npx expo start --tunnel sends Metro's traffic through Expo's tunnel service, for when the phone cannot reach the computer on the same network. It is slower and installs a helper the first time. Lesson 1.2.
TurboModule
A native module (camera, storage, haptics) in the New Architecture, loaded only when the app first uses it. Lesson 1.1.
Typed routes
The app.json experiment that makes npx expo start write types for every route (in .expo/types/), so tsc rejects a link to a route that does not exist. Metro must run to refresh them. Lesson 4.1.

U

UI thread (main thread)
The thread that lays out and draws the native views and reads touches. Reanimated animations and Gesture Handler callbacks run here, so they keep moving even while the JavaScript thread is busy. Lesson 7.1. Lesson 8.4.
Universal links and App Links
https links that open an installed app (universal links on iOS, App Links on Android) and a web page when it is not installed. They need a website you control and your own builds, so the course only describes them. Lesson 4.4.
updateReminders
Shoreline Crew's one function that makes the phone's reminders match the truth (session, setting, permission, sign-ups): schedule what is missing, cancel what is not needed. Idempotent, so it runs at start-up, on foreground and after sign-ups change. Lesson 6.4.
uri-scheme (npx uri-scheme)
A command-line tool that opens a link on an emulator or simulator (npx uri-scheme open "URL" --android or --ios), for testing deep links and notification taps without a message. Lesson 4.4. Lesson 6.4.
useAnimatedReaction
A Reanimated Hook that watches something on the UI thread and runs a worklet when it changes. The tally uses it to hand the visible step back to React. Lesson 7.1. Lesson 7.2.
useAppStateFocus
Shoreline Crew's Hook in the root layout that tells focusManager when AppState changes. Native only: the web preview's browser already does it. Lesson 5.2.
useController and Controller
React Hook Form's way to connect a field that is not an HTML input. React Native's TextInput has no name or web events, so register does not work there. Lesson 5.4.
useFonts
The hook from expo-font (used through @expo-google-fonts/outfit) that loads font files and says when they are ready. Each weight is its own fontFamily, such as 'Outfit_600SemiBold'. Lesson 2.3.
useLargeText (Shoreline Crew)
The app's Hook that is true when fontScale is at least 1.5; then tallies go two per row and detail rows stack. Lesson 8.1. Lesson 8.3.
useOnlineManager
Shoreline Crew's Hook in the root layout that wires NetInfo into onlineManager.setEventListener. Native only: in the web preview the browser's own online events count. Lesson 5.2.
usePermission
Shoreline Crew's Hook (src/hooks/usePermission.ts) that turns any Expo permission Hook into one of five steps: checking, not asked, denied, blocked, granted. It reads the answer again whenever the app comes back to the foreground. Lesson 6.1. Lesson 6.2.
user_version (PRAGMA user_version)
A number SQLite keeps in every database file, 0 in a new one. Shoreline Crew's logbook reads it on open and runs each missing migration step in order. Lesson 5.3.
useRecyclingState
FlashList's hook for row state that resets when the row is reused for another item (useRecyclingState(false, [event.id])), so one card's open details do not appear on another. Lesson 3.2.
useReduceMotion (Shoreline Crew)
The app's Hook in src/state/motion.ts: true when the phone asks for less motion or the in-app "Reduce motion in this app" switch is on. The switch can only add to the phone's setting. Lesson 7.3.
useRefreshOnFocus
Shoreline Crew's Hook that refetches the active, stale queries under one key each time a screen comes back into view, because tabs and stacked screens stay mounted and never start their queries again. Lesson 5.2.
useReminderTaps (isCleanupPath)
Shoreline Crew's Hook that opens the cleanup a reminder names, whether the app was running or closed. isCleanupPath checks the notification's data before trusting it, as outside input. Lesson 6.4.
userEvent (RNTL)
RNTL's realistic interactions: user.press() walks press in, press out and press, respects pointerEvents; user.type() types one letter at a time. Import it from RNTL. Lesson 8.3.
userInterfaceStyle
The app.json setting for which color schemes the app supports: "automatic" (follow the phone), "light" or "dark". Lesson 2.5.
useScreenScroll
The hook Screen exports with the page color, safe-area edges, padding and keyboard props for any scroll view, spread into a list: <FlatList {...screen} … />. Lesson 3.1.
useSendWaitingLogs
Shoreline Crew's Hook in the root layout that starts sendWaitingLogs at sign-in and start-up, when onlineManager says the phone is back online, and when focusManager says the app is back in front. Lesson 5.5. Lesson 6.4.
useSession
Shoreline Crew's Hook for "who is signed in" (null for nobody), built on useSyncExternalStore over the in-memory session in client.ts. Components that use it re-render on every sign-in and sign-out. Lesson 4.3.
useSharedValue
The Reanimated Hook that creates a shared value with a starting value: const count = useSharedValue(0). Lesson 7.1.
useTheme
Shoreline Crew's hook (src/hooks/useTheme.ts) that returns the current color set, light or dark. Expo Router exports a useTheme too; import Shoreline Crew's. Lesson 2.5. Lesson 5.3.
useWindowDimensions
The hook that gives the window's width, height and fontScale in density-independent pixels, and re-renders when they change (rotation, split screen). React Native's answer to media queries. Lesson 2.5.
UTI (Uniform Type Identifier)
Apple's name for a kind of file, such as public.comma-separated-values-text or public.json, passed to shareAsync on iPhone. Lesson 6.5.

V

Velocity (points per second)
How fast the finger was moving when it let go, which a pan gesture reports. SwipeToRemove acts on a long drag (120 points) or a quick flick (800 points per second). Lesson 7.2.
Version drift
Packages slowly moving away from the versions an SDK expects. npx expo install --check finds it and npx expo install --fix repairs it. Lesson 10.2.
Version vs build number
The version (1.0.0) is for people and you choose it by meaning; the build number (Android versionCode, iOS buildNumber) must grow with every store upload. Lesson 9.3.
View
React Native's basic box: it holds other components, has a size, a background, a border and padding, and lays out its children with flexbox. It cannot show text by itself. Lesson 2.1.
Virtualization (windowing)
Drawing only the list rows near the visible part of the screen and throwing away the rest as you scroll, so a long list stays fast and light. Lesson 3.1.
VoiceOver
The iPhone's built-in screen reader (Settings, Accessibility, VoiceOver). Swipe right to move to the next element, double-tap to activate it. Lesson 8.1.

W

Waiting list (waitlisted)
The sign-up status the API gives when a cleanup has no spots left. When someone with a spot cancels, the first person on the waiting list gets it. Lesson 5.2.
Walking skeleton
The thinnest version of the app that works end to end (a route, a screen, data from the API) before any feature is finished, built in Milestone 2. Lesson 10.1.
Watch mode
Jest rerunning the tests every time you save (--watchAll, what npm test does in Shoreline Crew). Keep it in a second terminal while you work. Lesson 8.2.
Web preview
Your app running in a browser through react-native-web (press w in Metro's terminal, or open http://localhost:8081). It shows data and logic quickly but not native code, insets or how the app feels in your hand. Lesson 1.1. Lesson 1.2.
WebAssembly (wasm)
A compact program format browsers run. expo-sqlite's web version is SQLite compiled to WebAssembly, which is why the web preview needs wasm added to Metro's asset extensions. Lesson 5.3.
WithBottomBar
Lesson 2.2's layout pattern for a bar pinned to the bottom of a screen without positioning: the content takes flex: 1 and the bar sits under it. Lesson 2.2. Lesson 2.3.
withSequence
A Reanimated helper that plays animations one after another, such as the tally's small bounce up and back. Lesson 7.1.
withSpring
A Reanimated animation driven by a spring instead of a fixed duration. It suits things that move like objects (a card snapping back) and starts from wherever the value is when interrupted. Lesson 7.1. Lesson 7.2.
withTiming
A Reanimated animation that moves a value to a target over a set duration along an easing curve. Use it for values that must land exactly, such as numbers and bar widths. Lesson 7.1.
Worklet
A small JavaScript function that runs on the UI thread instead of the JavaScript thread. The Babel plugin turns useAnimatedStyle functions and Gesture Handler callbacks into worklets for you; worklets come from react-native-worklets. Lesson 7.1. Lesson 7.2.

Y

Yoga
The flexbox engine, written in C++, that calculates React Native layouts the same way on Android and iOS. The web preview does not use it: the browser lays out the HTML, which is why the two can differ. Lesson 2.2.
