⌨️ Expo CLI Cheat Sheet

Every command the course types, grouped by job: what it does, and the lesson that teaches it.

🧭 How to Use This Page

Run each command in its folder: shoreline-crew for the app, shoreline-api for the API. Expo commands go through npx, which uses the Expo CLI installed in the project, so there is nothing to install globally; EAS commands use npx eas-cli@latest the same way. Stop anything that keeps running with Ctrl+C (on a Mac too). Where a command sets a variable in front of it (APP_VARIANT=preview npx expo …), that form works in macOS, Linux and WSL terminals; the PowerShell form is shown next to it. Each row links to the lesson that teaches it, where you will find the expected output. For the components and patterns, see the React Native cheat sheet; for error messages, Troubleshooting; for words, the Glossary.

🚀 Create and Run

A new project in three commands. Lesson 1.2.

npx create-expo-app@latest shoreline-crew   # the default template: TypeScript, Expo Router
cd shoreline-crew
npm run reset-project                       # answer n: a blank app, no example/ folder
npx expo start                              # Metro, a QR code for Expo Go, the keys below

📦 Installing Packages

Install Expo and React Native packages with npx expo install, not npm install: it picks the version built for your SDK (the one inside Expo Go), and for packages with a config plugin it adds the plugin to the app config. Lesson 1.2, Lesson 4.3.

npx expo install @expo-google-fonts/outfit     # the version that matches the SDK
npx expo install --dev jest-expo jest @types/jest @testing-library/react-native msw
npx expo install --check                       # list packages that do not match the SDK
npx expo install --fix                         # ...and move them to the expected versions
CommandWhat it doesLesson

🌊 The API and Its Address

shoreline-api needs no install. On a phone, localhost is the phone itself: point EXPO_PUBLIC_API_URL in .env.local at an address the device can reach, and restart Metro with --clear. Lesson 5.1.

cd shoreline-api
node server.ts           # http://localhost:4000/api, for the web preview and the iOS Simulator
node server.ts --host    # also reachable from a phone on the same Wi-Fi (Lesson 5.1)

Or set the address for one run (it wins over .env.local). Lesson 5.1.

# macOS, Linux and WSL: the variable in front of the command
EXPO_PUBLIC_API_URL=http://10.0.2.2:4000 npx expo start --clear
# Windows PowerShell: set it first, then start
$env:EXPO_PUBLIC_API_URL = "http://10.0.2.2:4000"
npx expo start --clear
CommandWhat it doesLesson
node server.tsstarts shoreline-api at http://localhost:4000/api1.2
node server.ts --hostlistens on every network of your computer, so a phone on the same Wi-Fi reaches it at your computer's address (such as http://192.168.1.42:4000)5.1
node server.ts --latency=500-3000slows every answer by a random delay in that range (practice loading states)3.1
curl http://192.168.1.42:4000/api/healthchecks from the computer (or open the address in the phone's browser) that the API answers at that address5.1
EXPO_PUBLIC_API_URL=http://10.0.2.2:4000 npx expo start --clearone run with another API address; 10.0.2.2 is the Android emulator's name for your computer (PowerShell: $env:EXPO_PUBLIC_API_URL = "http://10.0.2.2:4000" first)5.1
adb reverse tcp:4000 tcp:4000lets an Android device or emulator connected to your computer reach port 4000 as its own localhost (repeat it after the emulator restarts)5.1

📤 Export, Bundles and Atlas

Export bundles the JavaScript the way a release build or an update does, and Atlas shows what is inside. In PowerShell set $env:EXPO_ATLAS = "true" first and Remove-Item Env:EXPO_ATLAS afterwards. Lesson 8.4.

npx expo install --dev expo-atlas
EXPO_ATLAS=true npx expo export --platform android
npx expo-atlas
CommandWhat it doesLesson
npx expo export --platform weba production web bundle in dist (serve it with npx expo serve)5.3, 9.3
npx expo export --platform androidthe Hermes bundle a release build carries (also --platform ios; add --clear for a clean cache); CI runs it to prove the app bundles for a phone8.4, 9.3
npx expo export --platform android --source-mapsalso writes the source maps that turn a minified stack back into your files and lines8.4
npx expo export --platform android --dump-sourcemap --clearthe export eas update runs, with its source map (set APP_VARIANT and the API address in front)9.3

🏗️ Prebuild

Only in a scratch copy, or with everything committed. Prebuild writes the native projects (android/, ios/) that EAS Build makes for you, and changes the android and ios scripts in package.json. Shoreline Crew never commits those folders: delete them and git restore package.json afterwards. Lesson 6.1, Lesson 9.1.

CommandWhat it doesLesson
npx expo prebuild --no-installgenerates android/ and ios/ from the app config and its plugins; read the manifest and Info.plist to see what a plugin wrote6.1
APP_VARIANT=preview npx expo prebuild --no-installthe native projects of one variant (its ids, its cleartext setting)9.1

🔄 EAS Update and Submit

An update sends new JavaScript to builds on a channel; native changes (a new native package, a permission sentence, the icon, a new SDK) need a new build. --environment loads that EAS environment's variables, since eas update does not read a build profile's env. Lesson 9.3.

npx eas-cli@latest update --channel preview --environment preview --message "Pull to refresh shows the time"
CommandWhat it doesLesson
npx expo-updates runtimeversion:resolve --platform androidprints the runtime version (fingerprint) the current code has; with the variant set (APP_VARIANT=preview …), a different hash than your build means a new build, not an update9.3
npx eas-cli@latest update --channel preview --environment preview --message "…"publishes an update to the builds made with the preview profile; the app runs it at its next start9.3
npx eas-cli@latest update:listthe published updates, with their messages9.3
npx eas-cli@latest update:rollbackrepublishes the update before the bad one, or the embedded code if there was none9.3
npx eas-cli@latest update:republishpublishes an earlier update again, as the newest one9.3

--rollout-percentage 10on update: sends it to some of the phones first9.3

npx eas-cli@latest build:version:getthe build numbers EAS keeps (appVersionSource: "remote")9.3

🔗 Devices and Deep Links

Open a link in the emulator or Simulator to test a deep link. In Expo Go the link is the development server's exp:// address, then /--/ and the path; with a build of your own it is shorelinecrew://cleanups/e08. Lesson 4.4.

npx uri-scheme list
npx uri-scheme open "exp://192.168.1.42:8081/--/cleanups/e08" --android
npx uri-scheme open "exp://127.0.0.1:8081/--/cleanups/e08" --ios
CommandWhat it doesLesson
npx uri-scheme listlists a native project's schemes; in an Expo project it says "Could not find any native URI schemes to list." (the scheme is in the app config)4.4
npx uri-scheme open "exp://192.168.1.42:8081/--/cleanups/e08" --androidopens the link on the Android emulator (--ios: the iOS Simulator, with 127.0.0.1)4.4, 6.4
adb shell am start -a android.intent.action.VIEW -d "exp://192.168.1.42:8081/--/cleanups/e08"the same on Android, without the helper4.4
xcrun simctl openurl booted "exp://127.0.0.1:8081/--/cleanups/e08"the same on the iOS Simulator, without the helper (Mac only: spawn xcrun ENOENT elsewhere)4.4
