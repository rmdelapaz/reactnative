📐 Lesson 2.2: Flexbox the Native Way

You have built page layouts with flexbox for years, so here is the good news: React Native lays out every screen with flexbox too. The catch is that it starts from different defaults, and those defaults explain nearly every "why is this here?" moment you will have on a phone. In this lesson you learn the four defaults that differ, the handful of layouts that phone screens are made of, and the one place where the web preview's layout quietly disagrees with a phone. Then you give Shoreline Crew's cards some real structure: a row of badges, details side by side, and a shared Screen component.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Explain how React Native's flexbox differs from CSS: every View is a flex column, flex is a single number, nothing shrinks by default, and there is no grid
  • Line things up along the main and cross axes with flexDirection, justifyContent, alignItems, alignSelf, flexWrap and gap
  • Size boxes with flex, fixed widths and percentages, and keep text inside a row from running off the screen
  • Build the common phone layouts: a header row, label and value side by side, a wrapping row of badges, a centered message, a bar pinned to the bottom
  • Make a screen fill the phone with flex: 1, and say where the web preview's layout can differ from a phone's
  • ⏱️ Time 140 minutes
  • 📋 Prerequisites Lesson 2.1: View, Text and StyleSheet
  • 🛠️ You will build a Screen component, Badge and StatusBadge, cards with a badge row and label/value rows, and a header row with a count on the Cleanups screen
  • 🧩 Stack Expo SDK 58 (React Native 0.88, React 19.3, Expo Router 58, TypeScript 6.0), the shoreline-api (the versions this lesson was checked with)
  • 📱 Where it runs the web preview on your computer, with shoreline-api in a second terminal; Expo Go on your phone shows the layout without data until Lesson 5.1

👋 Welcome: Same Flexbox, Different Starting Point

At the end of Lesson 2.1, every line of Shoreline Crew's cards sat under the one before it. That was not a choice you made: it is what React Native does when you say nothing about layout. Today you start saying something. A volunteer scanning the list wants to see at a glance that a cleanup is scheduled and happening today, and to find the meeting point without reading a paragraph. That takes rows inside columns, things pushed to an edge, and text that wraps in the right place.

On the web you would reach for display: flex on some elements, CSS Grid on others, and maybe a float you are not proud of. On a phone there is one layout system, flexbox, and it is already switched on for every View. Once you know where its defaults differ from the browser's, your web experience transfers almost completely.

  • Why it matters for your work: layout is the part of a React Native job you touch every day. Teams notice quickly who can look at a design and build it with three flex properties, and who nests five Views and guesses.
  • Why it matters for the volunteers: phones come in many widths, people turn up their text size, and a layout built from fixed pixel positions breaks for some of them. Flexbox layouts bend instead of breaking.

✅ Layout is learned by moving boxes

Nobody learns flexbox from a table of properties. You learn it by changing one property, saving, and watching what moves. This lesson gives you the map; Step 5 of the project asks you to break the layout on purpose, one line at a time. If something lands in a strange place, that is not a failure: it is the layout engine showing you exactly what you asked for, and the fastest way to understand what you meant.

🧭 Every View Is a Flex Column

In a browser, a <div> is a block until you write display: flex. In React Native there is no "block" and no "inline": every View is already a flex container, and the properties you know (justifyContent, alignItems, flexWrap, gap) work on it straight away. The layout is calculated by Yoga, a flexbox engine written in C++ that React Native runs the same way on Android and iOS. The web preview does not use Yoga: react-native-web turns the same styles into the browser's CSS flexbox, which is why it looks almost, but not always exactly, the same (more in Where the Web Preview Disagrees).

Four defaults differ from CSS, and they are worth learning by heart:

PropertyCSS defaultReact Native defaultWhat you notice
flexDirectionrow'column'Children stack from top to bottom unless you say 'row'
flexShrink10Nothing gets smaller to fit: long content can run past the edge
alignContentnormal (stretch)'flex-start'Wrapped lines stay at the start instead of spreading out
flexa shorthand: 1 1 0%one numberflex: 1 means "take a share of the free space"; strings are a type error

The flexShrink default is easy to check for yourself: React Native ships Yoga's source in node_modules/react-native/ReactCommon/yoga, and its style defaults say DefaultFlexShrink = 0.0f, with a separate WebDefaultFlexShrink = 1.0f that React Native does not use. Everything else you know is the same: alignItems defaults to 'stretch', justifyContent to 'flex-start', and gap, rowGap and columnGap work as in CSS.

Here is the first default in action. Three Texts in a View, with no layout styles at all, stack from top to bottom; one line turns them into a row:

import { StyleSheet, Text, View } from 'react-native';

// Three boxes with no layout styles at all: they stack from top to bottom
export function Supplies() {
  return (
    <View style={styles.list}>
      <Text>Gloves</Text>
      <Text>Bags</Text>
      <Text>Water and snacks</Text>
    </View>
  );
}

// The same three, side by side: one line changes the main axis
export function SuppliesInARow() {
  return (
    <View style={[styles.list, styles.row]}>
      <Text>Gloves</Text>
      <Text>Bags</Text>
      <Text>Water and snacks</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  list: { gap: 8 },
  row: { flexDirection: 'row' },
});

Main axis and cross axis

As on the web, every flex container has two directions. The main axis is the direction children are placed in: down the screen for a column, across it for a row. The cross axis is the other one. justifyContent works along the main axis and alignItems across it, so when you switch a container from column to row, the two properties swap the jobs they do on the screen. This is the single most common source of "I set alignItems: 'center' and it centered the wrong way".

💡 Mental model: the crew lining up on the beach

Picture the volunteers gathering at the meeting point. Unless someone gives directions, they line up single file down the beach, away from the water: that is the default column. Say "row" and they stand shoulder to shoulder along the tide line instead. justifyContent is where they stand along the line (bunched at the start, spread out, gathered in the middle). alignItems is how each person stands across it, and the default, 'stretch', has everyone reaching all the way from the dunes to the water. And because nobody likes being squeezed, nobody shrinks to make room unless you ask (flexShrink: 0): if the line is too long for the beach, the last people end up standing in the sea.

No grid, no floats, and positions that stay local

  • display accepts only 'flex' (the default), 'none' (hide it and take no space) and 'contents'. There is no 'block', 'inline' or 'grid': grids are rows of flexible boxes, or lists with columns (Module 3).
  • position defaults to 'relative'. position: 'absolute' places a box relative to its parent, with top, right, bottom and left as numbers, and takes it out of the flex flow. Use it for small overlays (a label on the corner of a picture), not to build screens.
  • There are no floats, no margin: auto centering tricks and no media queries. Lesson 2.5 handles different screen sizes in code.

📏 Sizing: flex, Fixed Sizes and Percentages

A box gets its size in one of three ways, and you will use all three on most screens:

You wantWriteExample in Shoreline Crew
Exactly this bigwidth: 72, height: 8The label column of a card's details
A share of the parentwidth: '50%'Two halves of a row, whatever the phone's width
Whatever space is leftflex: 1A detail's value, next to its label; the whole screen
As big as the contentnothingA badge, a line of text

flex is a number, and it means "take a share of the free space". Inside a row, a box with flex: 1 takes whatever the other boxes leave. Two boxes with flex: 1 and flex: 2 split the free space one to two: in the course's web-preview test, a row 340 units wide (after padding and the gap) gave them 111 and 221. Behind the scenes, Yoga turns a positive flex into flexGrow with a starting size (flexBasis) of 0, and you can still write flexGrow, flexShrink and flexBasis separately when you need to. What you cannot write is the CSS shorthand flex: '1 1 0%': it is a type error (see Common Mistakes).

Ratios are useful for more than columns. This bar shows how full a cleanup is, with no arithmetic at all: the taken spots and the free spots each get a flex equal to their count, and Yoga does the division:

import { StyleSheet, View } from 'react-native';

type SpotsBarProps = { taken: number; capacity: number };

// flex as a share: 7 taken and 5 free out of 12 split the bar 7 to 5
export function SpotsBar({ taken, capacity }: SpotsBarProps) {
  return (
    <View style={styles.track}>
      <View style={[styles.taken, { flex: taken }]} />
      <View style={{ flex: capacity - taken }} />
    </View>
  );
}

const styles = StyleSheet.create({
  track: {
    flexDirection: 'row',
    height: 8,
    borderRadius: 4,
    overflow: 'hidden',
    backgroundColor: '#bfe3df',
  },
  taken: { backgroundColor: '#1f6f8b' },
});

Two more sizing tools you will meet soon: minWidth/maxWidth (and the heights) work as on the web, and aspectRatio sizes one side from the other, which Lesson 2.3 uses for the site pictures.

The rule that bites in rows: nothing shrinks

Because flexShrink defaults to 0, a box in a row keeps the size its content asks for, even when the row is too narrow. For short labels that never matters. For a line of text, such as a meeting point next to its label, it can push the text past the right edge of the card instead of wrapping. The fix is to tell the text it may give way:

  • flex: 1 on the text: "take the space the others leave, and wrap inside it". Use it when the text should fill the rest of the row.
  • flexShrink: 1 on the text: "keep your natural size, but get smaller if you must". Use it when the text should stay as short as it is, with something else beside it (like a heading with a count next to it).

You use both in the project. Learn the reflex: text in a row gets flex: 1 or flexShrink: 1.

🎯 Lining Things Up

The alignment properties are the CSS ones, camelCased, with the values as strings:

PropertyAlongValuesTypical use
justifyContentmain axis'flex-start' (default), 'center', 'flex-end', 'space-between', 'space-around', 'space-evenly'Push a count to the far end of a header row
alignItemscross axis'stretch' (default), 'flex-start', 'center', 'flex-end', 'baseline'Center an icon and a label vertically in a row
alignSelfcross axis, one childthe same, plus 'auto'Stop one child from stretching
flexWrapmain axis'nowrap' (default), 'wrap'Badges or tags that continue on a second line
gap, rowGap, columnGapbetween childrennumbersSpace between cards, lines and badges, never at the edges

Stretch: why a badge becomes a bar

alignItems: 'stretch' is the default, so in a column every child is as wide as the column. That is perfect for cards and banners, and a surprise for anything small. The course measured it in the web preview: a pill-shaped badge with the word "Scheduled", placed directly in a 358-wide card, came out 340 units wide, a long green bar. With alignSelf: 'flex-start' it was 93 units, just wider than its word. Putting small things in a row also stops it, because in a row the stretch goes up and down instead; that is what Shoreline Crew's badge row does.

The HQ's EventCard.module.css had exactly this badge row. Here is how it translates:

The HQ's CSS (.badges)Shoreline Crew (styles.badges)
display: flex;nothing: every View is a flex container
(row is the CSS default)flexDirection: 'row': column is the native default
flex-wrap: wrap;flexWrap: 'wrap'
gap: 0.5rem;gap: spacing.sm (8)

In the project, the Cleanups screen's header row uses the other two properties you will write most: justifyContent: 'space-between' pushes the count to the right edge, and alignItems: 'center' lines the heading and the count up through their middles:

shoreline-crew/src/app/index.tsx
sectionHeader: {
  flexDirection: 'row',
  justifyContent: 'space-between',
  alignItems: 'center',
  gap: spacing.sm,

📱 Filling the Screen

On the web, a page is as tall as its content and the browser scrolls the window. On a phone, the navigator gives each screen a fixed box, the screen's height, and it is your job to fill it. A View with no size is only as tall as its content, so a screen whose outermost View has no flex: 1 has two problems the course measured in the web preview at 390 by 844:

  • The background stops where the content stops. A screen View with a Sand background and only the line "Loading cleanups…" was 48 units tall, with the rest of the screen blank. With flex: 1 it filled all 780 units below the header.
  • A ScrollView inside it cannot scroll. A ScrollView needs a fixed height to scroll within. Inside a View without flex: 1, it grew to the full height of its sixty rows (1,464 units), so there was nothing to scroll: setting its scroll position left it at 0 and the last row stayed far below the bottom of the screen. With flex: 1 on the outer View, the same ScrollView was 780 tall and scrolled to the last row.

The rule: the outermost View of a screen gets flex: 1, and so does every View between it and anything that should fill the space (a list, a map). A ScrollView already grows by default (its base style in React Native has flexGrow: 1 and flexShrink: 1), so you can put one straight at the top of a screen, as Lesson 2.1 did; it is a plain View wrapped around it that breaks things.

Rather than remember that rule on every screen, Shoreline Crew gets a Screen component today: the page color from edge to edge, the standard padding and gaps, and flex: 1, with an optional scroll prop for screens that are longer than the phone. Lesson 2.3 adds the safe areas around the notch and the home indicator to it, so every screen gets them at once.

🧩 Common Phone Layouts

Most phone screens are built from a few patterns. Learn to see them in the apps you use, and a new design turns into a short list of rows and columns:

PatternRecipeWhere you see it
Header rowrow, justifyContent: 'space-between', alignItems: 'center'; the title gets flexShrink: 1"Upcoming cleanups ... 8 cleanups"
Label and valuerow; the label a fixed width, the value flex: 1A card's "When" and "Meet at"
Wrapping chipsrow, flexWrap: 'wrap', gapBadges, skills, supplies
Centered messageflex: 1, justifyContent and alignItems both 'center'Empty states, errors, loading
Bottom barcolumn: content flex: 1, then the barA "Sign up" button under a detail screen
Equal columnsrow, each child flex: 1Two stats side by side
Corner overlayparent normal, child position: 'absolute' with top/rightA label on a picture

Four of them as components, so you can see how little code each takes (these are examples, not files in the project):

import type { ReactNode } from 'react';
import { StyleSheet, Text, View } from 'react-native';

// 1. Centered in the whole screen: an empty or error state
export function CenteredMessage({ message }: { message: string }) {
  return (
    <View style={styles.centered}>
      <Text>{message}</Text>
    </View>
  );
}

// 2. Content that fills the screen, with a bar pinned to the bottom
export function WithBottomBar({ children, bar }: { children: ReactNode; bar: ReactNode }) {
  return (
    <View style={styles.fill}>
      <View style={styles.fill}>{children}</View>
      <View style={styles.bar}>{bar}</View>
    </View>
  );
}

// 3. Two equal columns
export function TwoColumns({ left, right }: { left: ReactNode; right: ReactNode }) {
  return (
    <View style={styles.columns}>
      <View style={styles.fill}>{left}</View>
      <View style={styles.fill}>{right}</View>
    </View>
  );
}

// 4. A small label on top of a corner of something else
export function WithCornerLabel({ children, label }: { children: ReactNode; label: string }) {
  return (
    <View>
      {children}
      <Text style={styles.corner}>{label}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  fill: { flex: 1 },
  centered: { flex: 1, justifyContent: 'center', alignItems: 'center', padding: 24 },
  bar: { padding: 16, borderTopWidth: 1, borderColor: '#e4dccb' },
  columns: { flexDirection: 'row', gap: 16 },
  corner: { position: 'absolute', top: 8, right: 8 },
});
  • CenteredMessage needs flex: 1 first: centering inside a box that is only as tall as its content centers nothing.
  • WithBottomBar pins the bar without any positioning: the content takes all the free space, so the bar ends up at the bottom. On a real screen, the bar also has to stay clear of the home indicator; that is Lesson 2.3.
  • TwoColumns gives both sides flex: 1, so they are equal whatever is in them, and text inside wraps in its own column.
  • WithCornerLabel is the one place position: 'absolute' belongs: the label sits on top of the corner of whatever is the parent's first child.

🔍 Where the Web Preview Disagrees

Lesson 2.1 showed that the web preview forgives a stray string a phone rejects. Layout has one forgiving spot too, and it is the "nothing shrinks" rule. react-native-web gives every View React Native's defaults, including flexShrink: 0, but it renders a Text as an element that keeps the browser's default of flex-shrink: 1. The course measured both in the web preview, in a 358-wide row with a 72-wide label and a long meeting point:

The long value is…Web preview (measured)A phone (Yoga, flexShrink: 0)
a Text with no flexShrinks and wraps; to make room, the browser also squeezed the 72-wide label to about 35Should keep its natural width and run past the card's edge
a Text inside a View with no flexRuns off: one line 645 units wide, far past the 390-wide screenShould run off as well
a Text with flex: 1Wraps inside the space next to the label; the label keeps its 72Should wrap the same way

So the web preview can look right in exactly the case where a phone does not. The habit that protects you is the one from Sizing: give text in a row flex: 1 or flexShrink: 1 whether or not the preview seems to need it, and look at row layouts on a phone.

⚠️ Common Mistakes

⚠️ Writing flex the CSS way

flex: '1 1 0%' or flex: '1' is caught. With it in Screen.tsx, TypeScript says:

Expected output (shortened)

src/components/Screen.tsx:28:5 - error TS2322: Type 'string' is not assignable to type 'number'.

28     flex: '1 1 0%', // fill the space the navigator gives the screen, not just the content's height
       ~~~~

  node_modules/react-native/types_generated/Libraries/StyleSheet/StyleSheetTypes.d.ts:514:3
    514   flex?: number | undefined;
          ~~~~
...

Found 1 error in src/components/Screen.tsx:28

Write a number: flex: 1. If you really need different grow, shrink and basis values, write flexGrow, flexShrink and flexBasis as three properties.

⚠️ Reaching for CSS Grid

display: 'grid' is caught too, and the message lists what is allowed:

Expected output (shortened)

src/components/EventCard.tsx:76:5 - error TS2322: Type '"grid"' is not assignable to type '"none" | "flex" | "contents" | undefined'.

76     display: 'grid',
       ~~~~~~~

  node_modules/react-native/types_generated/Libraries/StyleSheet/StyleSheetTypes.d.ts:68:3
    68   display?: "none" | "flex" | "contents" | undefined;
         ~~~~~~~
...

Found 1 error in src/components/EventCard.tsx:76

Build grids from rows of flex: 1 boxes, or a list with columns (Module 3).

⚠️ Text in a row without flex: 1 or flexShrink: 1

No type error, and the web preview may look fine (see why). On a phone, long text keeps its width and can run past the edge of its card. Every Text that shares a row with something else gets flex: 1 (fill the rest) or flexShrink: 1 (shrink if needed).

⚠️ A screen without flex: 1

The page color stops under the last line, a centered message sits at the top, a ScrollView inside a plain View will not scroll. Nothing is printed anywhere. Use the Screen component, or give the outermost View flex: 1.

⚠️ A small thing stretched into a bar

A badge, a button or a picture placed directly in a column becomes as wide as the column (alignItems: 'stretch'). Put it in a row, or give it alignSelf: 'flex-start'.

⚠️ Swapped axes after switching to a row

You turned a column into a row and now justifyContent: 'center' centers sideways instead of up and down. Nothing is broken: the axes swapped. justifyContent follows the arrow of flexDirection; alignItems goes across it.

⚠️ A fixed height on a row with text

height: 40 on a row of text looks tidy until someone uses a larger text size: the text grows and the row does not, so the text is cut off or overlaps the next row. Let rows take their height from their content and use padding and minHeight for breathing room.

Step 2: Badge and StatusBadge (15 min)

Step 5: Break it on purpose (15 min)

Make one change at a time, save, look at the web preview, and undo it. Each one shows a default doing its job:

  1. In EventCard's badges style, delete flexDirection: 'row', and flexWrap: 'wrap',. The badges become full-width bars, one under the other: the column's stretch. (The course measured the "Scheduled" badge at 324 units wide, the card's full inner width, instead of 102.)
  2. Put them back, then delete only flexDirection: 'row',. The badges stack but stay narrow. That is the alignContent: 'flex-start' default from the table at the top: with wrapping on, each line is only as wide as its widest badge. Put it back.
  3. In detailLabel, delete width: 72,. Each label is now as wide as its own word, so "When" values start further left than "Meet at" values (the course measured 87 and 102). The fixed width is what makes the values line up. Put it back.
  4. In the screen's sectionHeader, delete justifyContent: 'space-between',. The count moves next to the heading, 8 units away (the gap). Put it back.
  5. In detailValue, delete flex: 1,. In the web preview, almost nothing changes (the course measured the "When" label giving up 5 of its 72 units). This is the case from Where the Web Preview Disagrees: on a phone, a long value could now run past the card's edge. Put it back, and remember that "looks the same in the preview" is not proof for rows of text.

❓ Common Questions at This Stage

Is there really no CSS Grid?

Not in React Native's styles: display accepts 'flex', 'none' and 'contents'. Phone screens rarely need a two-dimensional grid. Rows of flex: 1 boxes cover forms and stats, flexWrap covers tags, and lists with several columns (a photo gallery, for example) come from the list components in Module 3.

What is Yoga, and do I ever touch it?

Yoga is the layout engine React Native uses on Android and iOS: it takes your style objects, works out every box's position and size, and hands the result to the native views. You never call it directly; your styles are its input. Because Android and iOS use the same engine, a layout comes out the same on both; differences come from fonts and from the web preview, which uses the browser's flexbox instead.

When should I use position: 'absolute'?

For things that sit on top of other things: a label on a picture, a small count on an icon, a floating button. It is measured from the parent, takes no space in the row or column, and does not move when the content around it grows, which is exactly why it is a poor tool for laying out a whole screen.

Percentages or flex?

Both size things relative to the parent. flex shares the free space after fixed-size siblings, which is usually what you want ("the rest of the row"). A percentage is a fixed fraction of the parent's size, whatever the siblings need. For layouts that change with the screen's width (two columns on a tablet), Lesson 2.5 reads the window size in code.

Why is the header bar white when the screen is Sand?

The header bar ("index") belongs to the Stack navigator, not to your screen, and keeps React Navigation's default look until later lessons style it (Lesson 4.1 gives screens their titles). Your Screen fills the box the navigator gives it, which starts under the header.

📝 Lesson Summary

🎓 Key Takeaways

  • Every View is a flex container, laid out by Yoga on Android and iOS; there is no block, inline or grid
  • Four defaults differ from CSS: flexDirection: 'column', flexShrink: 0, alignContent: 'flex-start', and flex as a single number
  • justifyContent works along the main axis, alignItems across it; switching to a row swaps what they do on the screen, and children stretch across by default
  • Sizes: a number for exact, a percentage string for a share of the parent, flex: 1 for "the rest", nothing for "as big as the content"
  • Text in a row gets flex: 1 or flexShrink: 1, even when the web preview looks fine without it
  • The outermost View of a screen gets flex: 1; Shoreline Crew's Screen component does it for every screen
  • Phone screens are built from a few patterns: header row, label and value, wrapping chips, centered message, bottom bar, equal columns, corner overlay
