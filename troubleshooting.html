✅ Before You Dig In

  • Is shoreline-api running? For a phone, it must be started with node server.ts --host. Open http://192.168.1.42:4000/api/health (with your address) in the phone's browser: if the phone shows the little JSON, the network path works and anything left is in the app.
  • Did you change .env.local or the app config? Stop Metro with Ctrl+C and run npx expo start --clear.
  • Did you read Metro's terminal? Navigation and sign-in mistakes often show up only there, as a yellow WARN or a red ERROR, not in tsc.
  • Did you type-check and lint? Metro runs your code without checking its types. Run npx tsc --noEmit and npx expo lint, and read the first error first.
  • Did you try it on a phone? The web preview is a translation into HTML: it cannot show the native look, the camera, notifications, gestures or the UI thread.

📶 Expo Go cannot connect to the computer

You see: Expo Go spins after you scan the QR code, then gives up; or the phone's browser test of /api/health spins, then fails.

Cause: the phone cannot reach your computer. The phone and the computer must be on the same Wi-Fi, and that network must let devices talk to each other (guest, school, hotel and many office networks do not). On a phone, localhost is the phone itself, so typing http://localhost:8081 into its browser shows nothing; the QR code carries your computer's network address.

Fix: check, in this order:

  • Firewall: the first time Node.js opens a port, Windows and macOS may ask whether to allow it. Allow it on private networks.
  • iPhone: Settings > Privacy & Security > Local Network: Expo Go must be switched on.
  • Wi-Fi: a phone hotspot is a quick way to test whether your Wi-Fi is the problem.
  • WSL: if the address under the QR code starts with 172., see Windows with WSL.
  • Still stuck: use the web preview for now, or npx expo start --tunnel, which sends Metro's traffic through Expo's tunnel service (slower; it offers to install a helper package the first time).

Learn it: Lesson 1.2: Three Ways to Run Your App · Lesson 5.1: Windows, WSL, Firewalls and Fussy Wi-Fi.

🪟 Windows with WSL: the phone cannot reach Metro or the API

You see: the line under the QR code reads › Metro: exp://172.…:8081, the API's on your network line shows a 172. address too, and the phone connects to neither.

Cause: WSL 2's default networking (NAT) gives Linux its own private address, often starting 172., that only Windows can reach. wslinfo --networking-mode tells you which mode you have.

Fix: choose one of three ways out before Lesson 5.1:

  • Run Node in Windows instead: install Node for Windows and run the API and Metro from PowerShell in a Windows folder (every npx command in the course works there unchanged). Simplest.
  • Turn on mirrored networking (Windows 11, version 22H2 or newer): add networkingMode=mirrored under [wsl2] in %UserProfile%\.wslconfig, run wsl --shutdown in PowerShell and open WSL again. Allow ports 8081 (Metro) and 4000 (the API) through the Windows firewall; Microsoft also describes a separate Hyper-V firewall for WSL in mirrored mode.
  • Use the Android emulator on Windows, which reaches your computer at 10.0.2.2 whatever WSL does. (The web preview also works from WSL, because your Windows browser can reach localhost.)

The same applies to a development build that cannot find Metro.

Learn it: Lesson 5.1: Windows, WSL, Firewalls and Fussy Wi-Fi · Lesson 1.2: Three Ways to Run Your App · Lesson 9.2: Common Mistakes.

🧩 Expo Go says the project is incompatible

You see: Expo Go refuses to open the project and says it is incompatible with this version of Expo Go.

Cause: Expo Go supports one Expo SDK at a time, and the version in the stores supports the newest one, SDK 58 for this course. An older Expo Go, or an older project, does not match.

Fix: update Expo Go from the store first. For an older project, upgrade it one SDK at a time instead of saving the upgrade "for when we have time", or use a development build, which is built for your project's SDK.

Learn it: Lesson 1.2: Three Ways to Run Your App · Lesson 10.2: Common Mistakes.

🆕 tsc reports errors in a brand-new project (TS2307, TS2882)

You see: error TS2307: Cannot find module './animated-icon.module.css' or its corresponding type declarations. and error TS2882: Cannot find module or type declarations for side-effect import of '@/global.css'., ending with Found 3 errors in 3 files.

Cause: the type declarations Expo generates (expo-env.d.ts and the typed routes in .expo/types) are written the first time you run npx expo start, and they are not committed to Git. The course's downloads do not include them either.

Fix: nothing is wrong with your code. Run npx expo start once (stop it with Ctrl+C), then npx tsc --noEmit again. If tsc ever complains about missing modules or types in a downloaded project, start it once first. (On a fresh checkout in CI, see Typed route errors.)

📂 Type or lint errors in an example/ folder after reset-project

You see: tsc and ESLint report errors in files you never wrote, all inside example/, about @/ imports that point nowhere.

Cause: you answered y to the reset-project question, so the template's old screens moved to example/ inside your project, where they are still checked.

Fix: delete the example folder once you have looked at it. The course answers n. The reset script also deletes itself, so npm run reset-project works only once.

📦 "The following packages should be updated for best compatibility"

You see: The following packages should be updated for best compatibility with the installed expo version: followed by a package and its expected version, and in CI Found outdated dependencies.

Cause: a native package was installed with npm install (or at @latest) at a version outside the set the SDK tested.

Fix: repair drift with npx expo install --fix, and install Expo and React Native packages with npx expo install from now on. Related traps:

  • npm audit fix --force: do not run it. "Force" may install versions that break the SDK's tested set, and many reports are about development tools that never ship in the app. Read npm audit and update the right package deliberately.
  • TypeScript 7: "upgrading" makes npx expo lint crash with Oops! Something went wrong! :( and TypeError: Cannot read properties of undefined (reading 'Intrinsic'). Put it back with npx expo install --dev typescript (without --dev, Expo adds a second typescript entry under dependencies).
  • expo-doctor's Found duplicates for expo-server: two copies of one native module; an overrides entry in package.json tells npm which version a dependency's dependency gets.

🔐 The app ignores a change to .env.local

You see: you fixed the address in .env.local, reloaded, and the app still uses the old one (Profile's Connection section shows the address the running bundle was built with). Or the app says "Something unexpected went wrong" although the variable is set.

Cause: EXPO_PUBLIC_ values are copied into the bundle when Metro builds it. And Metro only replaces the full expression process.env.EXPO_PUBLIC_API_URL: with const { EXPO_PUBLIC_API_URL: url } = process.env; the address is simply not in the bundle, and behind the screen's message is the error EXPO_PUBLIC_API_URL is not set.

Fix: stop Metro (Ctrl+C) and run npx expo start --clear. Its first lines say whether it found the file: env: load .env.local and env: export EXPO_PUBLIC_API_URL. Check the name (.env.local, with a leading dot, in the shoreline-crew folder, not in src/), and write the variable out in full every time you read it. The same restart applies to APP_VARIANT and the app config.

Learn it: Lesson 1.3: Common Mistakes · Lesson 5.1: Common Mistakes · Lesson 9.1: Common Mistakes.

🧭 "Unable to resolve module …"

  • Error: Unable to resolve module ./wa-sqlite/wa-sqlite.wasm from …/node_modules/expo-sqlite/web/worker.ts: None of these files exist (the web preview or npx expo export --platform web, after installing expo-sqlite): "None of these files exist" is misleading; Metro does not know what to do with a .wasm file. Add wasm to Metro's asset types in metro.config.js, then npx expo start --clear.
  • Error: Unable to resolve module @lottiefiles/dotlottie-react from …/lottie-react-native/lib/module/LottieView/index.web.js: lottie-react-native's web file needs the dotLottie player. Read the import stack from the bottom up, then npx expo install @lottiefiles/dotlottie-react.
  • After removing a package: tsc says error TS2307: Cannot find module '@expo/ui/jetpack-compose' or its corresponding type declarations. and Metro fails the same way when it bundles. Something still imports it. Before removing a package, search your src folder for its name and run npm ls with its name.

🖥️ The web preview crashes on a phone-only package

  • Metro error: (0 , r(...).codegenNativeComponent) is not a function: react-native-maps was loaded where the web preview can see it. codegenNativeComponent exists in React Native, not in react-native-web, and Expo Router's web build loads every route, so the whole web build stops. Give the component a .web.tsx twin that never imports the package (SiteMap.web.tsx).
  • expo-file-system is not supported on web then Metro error: this.validatePath is not a function (a blank Logbook tab): a File, Directory or Paths.cache at the top of a module runs the moment the module is imported. Read the call stack from the bottom, and create files and folders inside the functions that use them.

🎨 TS2322 "Type 'string' is not assignable to type 'number'" in a style (and other style errors)

  • error TS2322: Type 'string' is not assignable to type 'number'. for fontSize: '16px' or flex: '1 1 0%': styles take plain numbers. Write fontSize: 16, flex: 1 (or flexGrow, flexShrink, flexBasis). padding: '16px' is not caught, so drop units everywhere.
  • Type '"grid"' is not assignable to type '"none" | "flex" | "contents" | undefined'.: no CSS Grid. Build grids from rows of flex: 1 boxes, or a list with columns.
  • A very long TS2345 ending in 'border' does not exist in type: no CSS shorthands. Write borderWidth, borderColor and, if needed, borderStyle. Skip to the code frame for the line and the property.
  • Property 'className' does not exist on type …: use style={styles.card}.
  • error TS2551: Property 'tagLine' does not exist on type …. Did you mean 'tagline'?: a typo in a style name. The phone would not complain at all; the text would silently lose its look.
  • error TS2820: Type '"calender_today"' is not assignable to type …. Did you mean '"calendar_today"'? (an icon) or Type '"Outfit_700bold"' …. Did you mean '"Outfit_700Bold"'? (a font family): read the end of the first line.

Learn it: Lesson 2.1: Common Mistakes · Lesson 2.2: Common Mistakes · Lesson 1.2: Common Mistakes · Lesson 2.3: Common Mistakes.

👆 A button does nothing, or tsc rejects an event handler

  • A button does nothing and there is no error: look for onClick. React Native 0.88's types accept it on any view, but taps go to onPress.
  • error TS18048: 'event.target' is possibly 'undefined'. and Property 'value' does not exist on type 'number | ReactNativeElement'.: the web habit onChange={(event) => onChangeText(event.target.value)}. Use onChangeText, which gives you the string.
  • Types of parameters 'value' and 'event' are incompatible on a Switch: its onChange gets an event. Use onValueChange.
  • Property 'label' does not exist on type 'IntrinsicAttributes & Omit<ButtonProps, "ref"> …TouchableNativeFeedback…': the editor imported React Native's own Button (which wants a title). Import from @/components/Button.
  • People miss a small icon button, or the first tap only closes the keyboard: give controls 48 of height or hitSlop (the web preview ignores hitSlop), and give scroll views keyboardShouldPersistTaps="handled".

Learn it: Lesson 2.4: Common Mistakes · Lesson 2.4: Pressable.

🌗 "Property 'trackOff' does not exist on type '{ primary … }'" or "useTheme cannot be called at the top level"

  • error TS2339: Property 'trackOff' does not exist on type '{ primary: ____ColorValue_Internal; background: …; card: …; text: …; border: …; notification: … }'.: the editor auto-imported Expo Router's useTheme, which returns the navigator's six colors. Import useTheme from @/hooks/useTheme.
  • React Hook "useTheme" cannot be called at the top level. (react-hooks/rules-of-hooks in npx expo lint): Hooks work only inside components and other Hooks. Use createThemedStyles outside the component and call the Hook it returns inside.

📡 "Could not reach the server at …"

You see: the app's own advice, which names the address that failed and what to try on this kind of device, for example Could not reach the server at http://localhost:4000. On Android, localhost is the device itself. Put your computer's network address in .env.local (10.0.2.2 on the emulator). or Could not reach the server at http://192.168.1.42:4000. Check that shoreline-api is running (with --host for this address), then try again.

Cause: one link of the chain is broken. On a phone, localhost means the phone itself; without --host, the API listens on localhost only (curl from the computer to the network address says Connection refused); or Metro still has the old address.

Fix: press Check the connection on Profile first. Then:

  • Start the API with node server.ts --host (it prints your computer's address on your network).
  • Set EXPO_PUBLIC_API_URL in .env.local per device: http://192.168.1.42:4000 (your address) for Expo Go on a phone, http://10.0.2.2:4000 on the Android emulator, http://localhost:4000 for the iOS Simulator and the web preview.
  • Restart with npx expo start --clear.
  • Open /api/health in the phone's browser: if that fails too, no change to the app can help (Expo Go cannot connect, WSL).
  • Only photo uploads fail while everything else works? Suspect the body (Photo uploads). Only a preview build on Android? See The build has no API address.

🔤 "leave out the /api at the end" or "start it with http://"

You see: EXPO_PUBLIC_API_URL is "…/api": leave out the /api at the end (the app adds it). or EXPO_PUBLIC_API_URL is "localhost:4000": start it with http://, as in http://192.168.1.42:4000. (Before the client checked addresses, the same mistake showed "Nothing was found at this address. Check the link.")

Cause: the API prints on your network: http://192.168.1.42:4000/api, and copying the whole line is natural, but the app adds /api itself.

Fix: write the address with http://, without /api and with no space around the =: EXPO_PUBLIC_API_URL=http://192.168.1.42:4000. Restart with npx expo start --clear.

🌐 "has been blocked by CORS policy" when the web preview is opened on the phone

You see: in the browser's console, Access to fetch at 'http://192.168.1.42:4000/api/events?…' from origin 'http://192.168.1.42:8081' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource., and on screen "Could not reach the server".

Cause: you opened the web preview from another device's browser. The API allows only localhost origins; it answered, and the browser refused to hand the answer to the page. Native apps send no origin, so CORS does not apply in Expo Go.

Fix: use Expo Go on the phone, and the web preview in the computer's own browser.

🔑 "Your sign-in has ended. Sign in again."

You see: Profile or My cleanups says Your sign-in has ended. Sign in again., and sign-ups or logs you made earlier are gone.

Cause: shoreline-api keeps everything in memory, sessions included, and starts from its sample data each time it starts (or after POST /api/_reset). On a 401, the app forgets the session too. That is on purpose. If a guest who never signed in sees it, the screen refetched a disabled query: refetch through the client with type: 'active' (Another person's data).

Fix: sign in again (password shoreline-demo). In the web preview, a reload also signs you out, because the session lives in memory only there.

Learn it: Lesson 4.3: When the API Forgets You · Lesson 5.2: One Place for an Ended Sign-In.

🎨 A style does nothing (or only the web preview looks right)

  • Text does not change color or size: a color, fontSize or fontWeight on a View passes the type check and does nothing. There is no cascade: text inherits from Text only. Move it to the Text (or an AppText variant).
  • Lines overlap or vanish: lineHeight: 1.5 means 1.5 units. Multiply yourself: font size 16, line height 24.
  • The web preview is fine, the phone shows the red error screen: a string left directly inside a View. Keep every word inside a Text or an AppText.
  • The custom font looks wrong on a phone: fontWeight: 'bold' on a custom family is faked by the browser only. Pick the weight by family name (Outfit_700Bold). A misspelled family silently falls back to the system font, which is why typography.ts types the names.

Learn it: Lesson 2.1: Common Mistakes · Lesson 2.1: No Cascade · Lesson 2.3: Common Mistakes.

📐 Text runs off the edge, a ScrollView will not scroll, a badge becomes a bar

You see: no message anywhere, and the web preview may look fine.

  • Long text runs past the edge of its card: a Text that shares a row needs flex: 1 (fill the rest) or flexShrink: 1.
  • The page color stops under the last line, a centered message sits at the top, a ScrollView will not scroll: the screen has no flex: 1. Use the Screen component.
  • A badge or button is as wide as the column: alignItems: 'stretch'. Put it in a row, or give it alignSelf: 'flex-start'.
  • justifyContent: 'center' centers sideways: the axes swapped with flexDirection: 'row'.
  • Text is cut off at a larger text size: a fixed height on a row (or a fixed width on a label). Use padding and minHeight.

Learn it: Lesson 2.2: Common Mistakes · Lesson 2.2: Where the Web Preview Disagrees.

🖼️ A picture or an icon is missing

  • A picture is missing, with no error and no warning: an expo-image without a width and height (or a width from its parent plus an aspectRatio) is 0 tall. Check its size before its URL; then the address (pictures come from the API, Could not reach the server).
  • An icon shows on an iPhone but not on Android or in the web preview: a plain SF Symbol name (date: 'calendar') type-checks. Give all three names (ios, android, web).

📱 Content under the status bar, or an empty band under a header

  • A warning: SafeAreaView has been deprecated and will be removed in a future release. Please use 'react-native-safe-area-context' instead.: an old tutorial imported it from react-native (which never handled Android). Import it from react-native-safe-area-context, or use the hook.
  • An empty band about the height of the status bar under a header: the screen adds the top inset again. Under a header use edges={['bottom', 'left', 'right']}.
  • An empty strip at the end of every list above the tab bar: the bottom inset twice. Above a tab bar, leave out 'bottom'.

The web preview has no insets, so check these on a phone.

🌙 A screen stays light in dark mode, or ignores the window size

  • The phone switches to dark mode; this screen stays Sand: a color baked into StyleSheet.create when the file loaded. Every color in a style sheet comes through createThemedStyles, every color handed to a prop from useTheme(). Search src/ for lightColors and brand.: outside src/theme/ there should be no hits.
  • Columns do not change when the window widens or the phone turns: Dimensions.get('window') at the top of a file reads the width once. Inside components, use useWindowDimensions.
  • React error #418 ("text content does not match") in the web preview's console: the window size shown in a screen's very first render, which the server drew first. Phones do not have it.
  • A tablet layout that misses Android tablets: choose layouts by width, not by Platform.isPad.

📋 FlatList stops the screen or warns

  • Changing numColumns on the fly is not supported. Change the key prop on FlatList when changing the number of columns to force a fresh render of the component. (a blank page when the window widens): give the list key={columns}.
  • columnWrapperStyle not supported for single column lists: pass it only when there are columns: columnWrapperStyle={grid ? styles.row : undefined}.
  • Type '(card: Card) => number' is not assignable to type '(item: Card, index: number) => string'.: keys are strings, and must be unique. Use an id: String(item.id) if it is a number.
  • VirtualizedLists should never be nested inside plain ScrollViews with the same orientation because it can break windowing and other functionality: a list inside <Screen scroll>. Make the list the screen's scroll view; everything else goes in its header or footer.
  • The keyboard closes after every letter in a search field above the list: ListHeaderComponent={() => (…)} makes a new component on every render. Build the header as an element (const header = (…)) and pass that.

♻️ Another row shows my row's state

You see: no warning anywhere. You open one card's details (or swipe one row) and scroll: a card a few screens down, which nobody touched, shows its details open (or "Item 95: remove it?").

Cause: FlashList recycles rows: the same component is handed a different item, and useState inside it travels along.

Fix: use FlashList's useRecyclingState(initial, deps) with the item's id, or keep the state in the parent screen, keyed by id, and pass it down. Never put a key on the row inside renderItem: it defeats recycling (the key belongs in keyExtractor).

Learn it: Lesson 3.2: Common Mistakes · Lesson 3.2: Recycling · Lesson 7.2: Common Mistakes.

🔁 The list keeps asking for the same page

You see: after page 2 fails, the list asks for it again and again (three times in a hundredth of a second, or hundreds of requests in a few seconds).

Cause: onEndReached={loadNextPage} calls the loader directly. Each failure changes the footer, which changes the list's height, so the list checks the end again and asks again.

Fix: ask only when nothing is loading and the last attempt did not fail; after a failure, the footer's Try again button is the only way to ask (with TanStack Query, check hasNextPage, isFetching and isFetchNextPageError).

Learn it: Lesson 3.2: Common Mistakes · Lesson 3.2: Page by Page.

⚡ FlashList: "Property 'columnWrapperStyle' does not exist", estimatedItemSize, a yellow warning

  • Property 'columnWrapperStyle' does not exist on type 'IntrinsicAttributes & FlashListProps<…> …': a FlatList-only prop. The first line of the error is long (it lists every prop); read the second. Put spacing in the cells.
  • estimatedItemSize from an online answer: that is FlashList version 1. Version 2 (installed by npx expo install for SDK 58) has no size estimates.
  • Padding in the list's style type-checks but is not supported: put it on a View around the list.
  • A yellow warning in the web preview's console starting Animated: `useNativeDriver` is not supported because the native animated module is missing: it comes from the pinned heading in the web preview; harmless.

📑 WARN [Layout children]: "No route named … exists in nested children" or "Too many screens defined"

You see: in Metro's terminal, WARN [Layout children]: No route named "my-cleanup" exists in nested children: [ 'index', 'logbook', 'my-cleanups', 'profile' ], and a tab is missing; or WARN [Layout children]: Too many screens defined. Route "cleanups/[id]" is extraneous.

Cause: a layout names a screen the folder does not have: a typo, or a file that moved. tsc says nothing, because screen names are plain strings.

Fix: the name in a Stack.Screen or Tabs.Screen must be the file's name without .tsx; the warning lists the names that exist. "Too many screens" also appears until you create a file the layout already names.

📡 An update never arrives

  • The build was made before expo-updates was installed: it has nothing that can ask. Make a new build first.
  • Published and listed on expo.dev, received by nobody: the runtime version does not match any build (often: the EAS environment has no APP_VARIANT, so the fingerprint is the development one). Compare the runtime version EAS CLI prints with your build page.
  • A native change (a permission sentence, an icon, a native package): it is compiled into the build and needs a new one. Check with npx expo-updates runtimeversion:resolve --platform android.
  • Just published: the app checks at start and runs the new code at the next start. Close it completely and open it, then once more.

Learn it: Lesson 9.3: Common Mistakes · Lesson 9.3: Runtime Versions.

🏪 Stores and the final project: "Missing Compliance", failing profile tests, an embedded repository

  • An App Store build waits as "Missing Compliance": every build answers the export compliance (encryption) question. Answer it once in app.config.ts with ios.config.usesNonExemptEncryption.
  • The profile tests fail with Expected: "com.example.shorelinecrew.dev" after you change the app ids: the tests doing their job. Update the expected ids in app.config.test.ts, and change ids once, before the first upload.
  • Git warns about an "embedded repository": a project copied inside the shoreline folder, which is itself a repository. Keep the final project in its own folder next to it.
  • The mock API refuses every valid request with "Invalid input: expected string, received null": it checks request bodies with the form's schema, which turns an empty note into null. Keep two schemas: one for the form, one for what the API accepts.
